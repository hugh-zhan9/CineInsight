# 片库组合筛选、排序与自动黑边发现

状态：需求及下列补充已确认；用户随后调用$exec授权实施，实际实现/验收以执行计划为准。
来源：2026-11-11 当前会话，用户调用 `$spec`。

## 原始请求与补充裁定

> 片库管理 的搜索支持 目录 + 文件名 组合筛选
> 增加一个自动识别需要裁切黑边的任务，识别出来之后加入到视频工作台，不自动裁切
> 裁切导出之后直接替换原文件
> 片库管理的列表增加排序模式的选择-文件名称、文件大小

用户补充确认：

- “开启后后台检查整个片库，并持续检查新增或变更的视频”。
- “仅整片裁剪替换原文件，选定时间段仍另存”。
- “必须保持原完整文件名及扩展名，按原容器编码”。
- 用户要求其他容器及部分外接盘兼容方案在本轮明确，不留作笼统缺口。

设计阶段交付设计文档；用户随后通过$exec授权实现和验证，未授权提交、安装或部署。旧编辑合同的另存原则仅在上述整片裁剪范围内被新需求取代。

## 验收与场景

<a id="AC-01"></a>
- **AC-01**：目录条件与文件名条件可以同时输入，按交集筛选，任一条件可单独使用；保留已有筛选能力。
<a id="AC-02"></a>
- **AC-02**：片库列表提供文件名称、文件大小排序，分页延续所选顺序。
<a id="AC-03"></a>
- **AC-03**：开启后后台检查已有全库、新增及变更的视频；需要裁剪的结果进入视频工作台，保持人工编辑和显式导出，不自动编码或替换文件。
<a id="AC-04"></a>
- **AC-04**：整片裁剪导出成功后直接替换原文件；只导出选定时间段仍另存。

<a id="TC-01"></a>
- **TC-01 → AC-01**：目录含“电影”、文件名含“预告”时只返回同时满足的文件；另有仅目录匹配、仅文件名匹配的反例；验证空条件、空结果、中文、空格及 `%_\` 字面量。
<a id="TC-02"></a>
- **TC-02 → AC-02**：同名不同目录、同大小、多页、空库及单文件下，排序和计数一致；改变排序回到第一页；旧排序仍可使用。
<a id="TC-03"></a>
- **TC-03 → AC-03**：开启后发现存量黑边视频，新增/修改后检查；无黑边、未识别、检测失败不冒充候选；重复调度和重启不重复创建项目；关闭后不再检查。
<a id="TC-04"></a>
- **TC-04 → AC-03**：自动生成项目后等待用户操作；用户改框不被后台覆盖，来源变化后旧建议不能直接导出；取消或单文件失败不损坏已完成结果。
<a id="TC-05"></a>
- **TC-05 → AC-04**：整片裁剪成功后原路径可播放裁剪成品，原文件名/扩展名/容器保持，原记录的用户资料保留，无额外片库记录；选定区间导出成新文件，原片不变。
<a id="TC-06"></a>
- **TC-06 → AC-04**：编码失败、空间不足、只读目录、来源被修改及发布中断时，不把半成品当原片；恢复明确区分文件替换与数据库提交状态。

技术细化（匹配方式、排序方向、任务去重与替换恢复）见设计；实现授权来自后续$exec；不将代理新增猜测记为用户裁定。
