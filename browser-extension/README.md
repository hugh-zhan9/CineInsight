# CineInsight 媒体抓取（Chrome / Edge 扩展）

嗅探网页上正在播的流式媒体（HLS `.m3u8`、TS 分片、直链视频），列出可选码率，下载到本地；
桌面端 CineInsight 在跑时还可以一键推过去，由它用 ffmpeg 下载并直接入库。

只支持 Chrome / Edge（Manifest V3，Chrome 116+）。Firefox 与 Safari 不在支持范围内。

## 安装

没有构建步骤，源码就是可加载的扩展：

1. 打开 `chrome://extensions/`（Edge 是 `edge://extensions/`）；
2. 打开右上角的「开发者模式」；
3. 点「加载已解压的扩展程序」，选中本目录（`browser-extension/`）。

图标是脚本生成的，改了想重新生成就跑 `python3 icons/make-icons.py`。

## 用法

1. 打开视频页面，**把视频播起来**——不少站点要点了播放才会去取播放列表；
2. 点扩展图标。角标上的数字就是这个标签页抓到的条数；
3. HLS 条目点「查看码率并下载」，展开后选一档；直链条目直接点「下载」；
4. 进度在「下载管理」页看（弹窗一失焦就关，长任务的进度不能只放在弹窗里）。

每条命中还能复制原始链接、复制等价的 ffmpeg 命令（含请求头），交给外部工具下载。

## 能下什么，不能下什么

| 情况 | 内置下载器 | 说明 |
| --- | --- | --- |
| 明文 HLS | ✅ | 分片并发取，按序落盘 |
| AES-128 加密的 HLS | ✅ | WebCrypto 解密，密钥自动取 |
| fMP4 分片（`EXT-X-MAP`） | ✅ | 输出 `.mp4` |
| MPEG-TS 分片 | ✅ | 输出 `.ts`，见下方「为什么不是 mp4」 |
| 直链 mp4/mkv/webm… | ✅ | 支持 Range 时分块并发并可续传 |
| 直播流（没有 `EXT-X-ENDLIST`） | ❌ | 没有终点，内置下载器不接；可复制 ffmpeg 命令自己录 |
| SAMPLE-AES / Widevine / FairPlay | ❌ | 受 DRM 保护，明确报错而不是产出一个打不开的文件 |
| DASH（`.mpd`） | ❌ | 只登记与展示，可复制命令或推给 CineInsight |
| MSE / blob 播放 | ⚠️ | 需要手动开启捕获并从头重播，见下 |

### 为什么 TS 流输出的是 .ts 而不是 .mp4

浏览器里做 TS→MP4 的转封装要自己处理 ADTS 音频、时间戳不连续、纯音轨这些情况，
产出坏文件的概率不低。所以内置下载器只做拼接，不做转封装。想要规范的 mp4：

- 用「复制 ffmpeg 命令」，在终端跑一次 `-c copy`；或者
- 推给 CineInsight，桌面端本来就在用 ffmpeg 做无损转封装。

`.ts` 文件本身绝大多数播放器都能直接播。

### MSE 捕获

页面用 MediaSource 喂数据时，网络层看不到完整的流。这时候可以开启捕获：扩展会挂在
页面把数据交给播放器的那一步上，把内容录下来。两个前提：

- **默认关闭**。捕获要在页面内存里攒下整段媒体（上限 2 GB），这个代价由你决定要不要付；
- **开启后必须从头重新播放**，否则录到的是从中间开始的一段。

导出时由页面自己触发下载——数据本来就在页面里，搬到扩展再存一遍要在两个进程之间
复制几个 GB，得不偿失。

## 推送到 CineInsight

桌面端「设置 → 浏览器插件」里打开桥接、生成令牌、选一个下载目录，然后把令牌填到
扩展选项页。配好之后弹窗里的「发送到 CineInsight」就可用了。

没检测到 / 没填令牌 / 令牌不对是三种不同的提示，按提示排查即可。安全边界见
`../docs/browser-extension.md`。

## 权限说明

| 权限 | 为什么要 |
| --- | --- |
| `webRequest` | 只读监听请求与响应头，用来判断这是不是流式媒体、并留下 Referer 等取流必需的请求头。不阻塞、不改写任何页面请求。 |
| `declarativeNetRequestWithHostAccess` | `fetch()` 不允许设置 Referer / Origin / User-Agent，而很多 CDN 只认这几个头。规则限定在「不属于任何标签页的 xmlhttprequest + 本次任务用到的主机」上，任务结束立刻撤销。说清楚残留的重叠：MV3 没有「只匹配本扩展的请求」这种条件，所以任务进行期间，同一主机上由**页面自己的 service worker** 发出的请求也会被改写这三个头。把窗口压到最小的办法就是规则只在任务运行期间存在。 |
| `storage` / `unlimitedStorage` | 存设置与任务断点；下载中的分片写在 OPFS 里（几个 GB 的片子不能堆在内存里）。 |
| `downloads` | 下完之后交给浏览器的下载器保存到你的下载目录。 |
| `offscreen` | MV3 的 service worker 随时会被回收，长下载必须挂在 offscreen 文档下面。 |
| `tabs` | 取当前标签页的标题与地址，用来给文件命名、把命中按页面归类。 |
| `<all_urls>` | 视频可能在任何站点上。 |

## 隐私

- 除了你显式发起的媒体请求，以及探测本机 `127.0.0.1` 上的 CineInsight，扩展不联网，没有遥测；
- Cookie **只留在内存里**，不写进任何存储，也不出现在命中列表和下载产物里。只有你在选项页
  显式打开「推送时附带 Cookie」，它才会随那一次推送发给本机的桌面端；
- 命中记录随标签页关闭或页面跳转一起清掉。

## 开发

```bash
npm test              # 全部单测（Node 内置 test runner，无依赖）
npm run test:hls      # 只跑播放列表解析
npm run test:download # 只跑解密、断点账本、下载主循环
```

代码分两层：`src/common/`、`src/download/` 是不碰浏览器 API 的纯逻辑，有单测；
`src/background/`、`src/offscreen/`、`src/content/` 是与 chrome API 的接线，靠人工验收。
