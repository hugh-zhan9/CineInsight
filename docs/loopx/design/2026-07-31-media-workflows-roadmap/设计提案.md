# 从媒体管理器走向本地生产工作台

Author(s): Codex / CineInsight
Last updated: 2026-07-31
Status: Accepted

## Abstract / 摘要

本提案把四项能力按独立发布边界接入现有 Wails + Go + Vue 模块化单体：先增加以外置 SRT 为事实源的字幕编辑工作台，再用文件系统事件驱动窄范围片库对账，然后导入本地 NFO 与同目录图片，最后基于已持久化的人工作业结果提供 AI 质量评估。

四项能力不共享一个新的通用任务框架。它们只复用已经稳定的基础边界：视频路径变更锁、扫描与迁移识别、字幕索引、详情事务、托管图片以及 AI 审批状态。这样每个迭代都能独立启停、验证和回滚应用行为，同时数据库只做加法迁移。

## Background / 背景与动机

CineInsight 已经能扫描本地媒体、生成和翻译字幕、维护人物与作品集、运行 AI 标签审批和同源判断，但这些能力仍偏向一次性生成和手工维护：

- 字幕可生成、翻译、检索和跳转，却不能在应用内完成校时、改文、重排和安全保存。
- 片库可在启动或手工操作时同步，却无法及时感知应用外部的新增、改名和删除。
- 详情页支持人工维护人物、标题和作品集，却无法利用常见本地 NFO 与图片资产。
- AI 有审批结果和同源否认，却缺少按模型/版本归因的质量趋势，因而无法用真实反馈判断改动是否有效。

用户确认当前元数据能力严格本地化，不接入在线资料源；字幕保存不保留旧版本或 `.bak`；AI 评估也只读取本地结果，不产生额外模型调用。

## Goals And Non-Goals / 目标与非目标

目标：

- 把同名外置 SRT 的完整编辑、校验、会话撤销重做、选区重译和显式保存整合到一个工作台。
- 在可靠的本地或直连文件系统上监听全部扫描根目录，并把事件转化为合并、稳定后的窄范围对账。
- 导入同名 Kodi/Jellyfin 风格 NFO 和同目录图片，先给出字段差异和实体映射，再按确认结果写入。
- 统计标签批准/拒绝、同源否认和 AI 运行质量，并按时间、标签、置信度、模型和版本筛选。
- 保持四项能力独立发布、独立关闭，并保持现有公开行为兼容。

非目标：

- 在线元数据搜索、远程图片下载或任何元数据外发。
- 对 NFS/SMB/FUSE 等网络或事件不可靠文件系统承诺实时一致性。
- 直接编辑 ASS/SSA/VTT、容器内嵌字幕、字幕样式和特效。
- 波形、声纹自动对齐、自动保存或字幕持久版本历史。
- AI 自动训练、自动修改提示词/阈值或为评估发起新的模型请求。
- 跨设备同步或把桌面单体拆成分布式服务。

## Proposal / 设计方案

### 1. SRT 文件仍是字幕事实源

字幕工作台打开同名外置 `.srt` 时执行严格解析并记录文件内容 SHA-256、大小和纳秒级修改时间。编辑状态只存在于当前前端会话，数据库字幕段仍是派生检索索引。

保存时服务端重新读取源文件并比较指纹；任何外部变化都会拒绝覆盖。合法内容先序列化到同目录临时文件、同步落盘，再经平台适配的原子替换操作覆盖当前 SRT。成功后立即重建字幕索引并返回新指纹。整个过程不创建 `.bak`、不保存历史、也不提供旧内容恢复。

宽松的现有检索解析器继续服务旧字幕查询；编辑入口使用独立严格编解码器，避免把跳过坏块的容错行为带进写入路径。

### 2. 文件事件只负责唤醒窄范围对账

使用 `fsnotify` 作为跨平台事件源。它不递归监听，因此服务在启动和新目录出现时显式注册每个子目录；监听目录而不是单个文件，以兼容编辑器常见的临时文件原子替换行为。已知网络文件系统由平台能力探测标记为不可用，注册失败、资源上限或运行错误均进入可见错误状态。

单个事件永不直接写数据库。一个进程内事件循环将短时间内的变化按扫描根目录和父目录合并，等待目录快照以及相关文件的 `size + mtime` 连续稳定后，再一次性调用 `VideoService` 的受影响路径对账。跨目录改名因此可在同一批次中复用现有迁移识别并保留关系；消失只进入现有失效/软删除语义，绝不永久删除文件或记录。

新安装默认开启实时同步；迁移后的已有安装默认关闭。运行状态只保存在内存，通过 Wails 查询和事件发送给设置页，避免把瞬时错误当成业务数据。

### 3. 本地元数据使用“观察指纹 + 即时差异”

导入器只读取视频同目录下的同名 NFO 和约定图片文件。XML 使用 Go 标准库流式解析，设置文件大小、元素深度、文本长度和候选数量上限，拒绝 DTD/指令；不会解析远程 URL，也不会创建 HTTP 客户端。

数据库只持久化每个视频观察到和已应用的来源清单指纹、状态与错误，不持久化一份容易过期的完整差异。用户打开详情或批量预览时，服务重新解析当前文件，并与当前数据库详情计算字段级 diff。

视频增加简介、海报和背景图字段。图片继续复制到应用托管目录，WebView 只通过受控资源接口读取。人物与作品集先作为映射候选返回：唯一规范化人物可预选，多个人物必须明确选择；作品集复用唯一活跃规范化名称。确认前不创建实体、不写关系，也不自动合并人物。

### 4. AI 质量数据以原业务记录为事实源

标签质量继续以 `ai_tag_candidates` 的最终状态为事实源，仅把 `approved` 和 `rejected` 纳入分母。新增不可变的 AI 运行记录，为新候选提供模型、提示词版本、耗时、请求数和工具次数归因；旧候选的空归因统一归入“历史/未知版本”。

同源关系当前表会随内容变化刷新，不适合作为长期质量样本，因此新增每次实际展示关系的最小评估记录。用户否认时更新该关系当前评估的结果。重复任务在双方内容未变化时不重复创建样本，防止重跑放大统计权重。

质量查询只执行本地 SQL 聚合，不读取字幕/帧/模型 payload，也不调用模型。现有 AI 管理弹窗增加“待审 / 质量”两个页签；质量视图不提供任何会改变审批状态的操作。

### 5. 四个独立发布边界

每个迭代只增加自己的表、列、服务和 UI 入口：

1. 字幕工作台不依赖 watcher、NFO 或 AI 质量。
2. Watcher 只依赖现有扫描/迁移语义。
3. 本地元数据复用 watcher 的“变化后对账”信号，但手工预览和导入不依赖 watcher 开启。
4. AI 质量只依赖新产生的最小归因字段，未归因历史仍可参与总体基线。

功能关闭时停止相应 worker 或隐藏入口，不删除已经持久化的数据。旧版本应用会忽略新表和新列。

## Support Lens Checks / 专项设计检查

| Support lens | Trigger | Design checks applied | Result |
|---|---|---|---|
| architecture-designer | 新文件写入、watcher 状态机、批处理和跨模块数据流 | 事实源、失败域、取消、资源上限、恢复与可观测性 | 文件事件只是提示；SRT/NFO/AI 各自只有一个事实源；后台 worker 均有明确关闭边界 |
| sql-style | 新状态、运行历史、同源质量记录和视频详情列 | 规范化、空值语义、唯一性、索引、事务、迁移重跑 | 只做加法迁移；瞬时 watcher 状态不落库；质量归因不复制敏感 payload |
| go-style | Go 服务、文件系统适配、context 和 goroutine | 小接口、错误包装、所有权、取消、race 验证 | 每个后台服务拥有自己的 goroutine；跨平台原子替换与文件系统能力通过窄接口隔离 |

## Boundary Scenarios / 边界场景

| 场景 | 处理 |
|---|---|
| SRT 打开后被外部修改、替换或删除 | 指纹比较失败，拒绝保存，原文件不被覆盖 |
| SRT 含坏时间、空文本、逆序或重叠 | 工作台显示逐条错误；保存不产生临时可见文件或局部索引 |
| 选区翻译返回条数不一致 | 整次操作失败，编辑缓冲区保持原值 |
| 原子替换在当前平台不可用或失败 | 返回具体错误并删除临时文件，保留原 SRT |
| 事件风暴或同一文件持续写入 | 合并事件；稳定探测有界等待；超时后报告错误并等待新事件或手工扫描 |
| 新建目录后立刻写入文件 | 先注册新目录并把其子树加入当前对账批次，扫描补足注册竞态窗口 |
| 网络盘、断开的卷或 watcher 数量上限 | 根目录显示不可用/错误；应用其余功能和启动/手工扫描继续可用 |
| 跨两个受监控目录改名 | 同一合并批次扫描源与目标父目录，串行复用迁移识别；若事件分批到达，后续批次仍可匹配软删除记录 |
| NFO 超大、XML 非法、含 DTD 或远程图片 URL | 拒绝或忽略并给出每视频错误；无网络访问、无部分实体写入 |
| 同名人物存在多个 | 必须选择具体人物或明确新建，不能按名称猜测或合并 |
| 批量元数据部分失败 | 每视频事务独立；成功项保留，失败项带原因，可重新预览后重跑 |
| AI 历史缺少模型和版本 | 纳入总体已决样本，显示“历史/未知版本”，不猜测归因 |
| 视频软删除 | 历史 AI 结果仍参与聚合，但 UI 不恢复对该视频的业务操作 |
| 功能关闭或应用退出 | 停止接收新后台工作，取消等待，释放 watcher；持久数据保留 |

## Rationale / 理由与取舍

| Alternative | Why Not |
|---|---|
| 把字幕编辑内容先存数据库，再异步导出 SRT | 产生双事实源和冲突恢复问题；用户明确当前 SRT 应被直接修改 |
| 保存前自动保留 20 版或生成 `.bak` | 与用户明确“不保存旧内容”的决定冲突 |
| 复用宽松字幕解析器进行编辑保存 | 宽松解析会跳过坏块，可能把未显示内容静默丢失 |
| 每个文件事件触发全库扫描 | 写入风暴下成本不可控，也扩大迁移锁竞争 |
| 依赖文件事件精确表达最终状态 | 跨平台事件会重复、合并或丢失；最终目录快照才可作为事实 |
| 为网络盘增加轮询伪装成实时监听 | 当前范围明确不保证网络盘实时性，且会增加持续 I/O 和错误认知 |
| 把完整 NFO diff 持久化 | 源文件和数据库都可能继续变化，持久候选容易陈旧且增加清理状态机 |
| 自动按姓名合并人物 | 人物表允许同名，名称不是可靠身份键，误合并难以恢复 |
| 元数据批量导入使用一个全局事务 | 单个坏文件会回滚全部成功项，与可报告、可重跑的批处理要求冲突 |
| 用一个通用 AI 质量事件表复制所有结果 | 会形成与候选/同源关系并行的第二事实源；只补足现有表无法表达的运行和同源评估历史 |
| 质量评估再次调用模型打分 | 增加成本和外发，且不能衡量用户真实批准/拒绝反馈 |
| 为四项能力引入通用 Job/Workflow 框架 | 当前任务生命周期、失败语义和持久化需求不同，抽象不会减少真实复杂度 |

## Compatibility And Rollout / 兼容与发布

- 所有 schema 变化由现有迁移入口加法创建；不删除列、不重解释旧值、不批量改写历史记录。
- 新设置字段数据库默认 `false`，初始化全新设置行时显式写 `true`，从而区分新安装和已有数据库升级。
- 新 Wails DTO 只新增方法或响应字段；现有字幕生成、扫描、详情和 AI 审批方法保持语义。
- 每个功能具备独立开关或独立入口；旧应用版本忽略新表/列时仍可使用原功能。
- 发布顺序遵循字幕工作台、watcher、本地元数据、AI 质量，但设计不要求四项同版上线。
