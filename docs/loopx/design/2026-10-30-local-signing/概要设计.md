# 本机持续签名

## D-SIGN-01 已接受范围
2026-10-30 用户选择为本机创建并持续复用专用代码签名证书，授权新增钥匙串私钥与证书。只用于本机，不是 Developer ID 分发或公证。旧应用 DR 为 cdhash，重编译改变身份；当前打包增加资源后未重新签名，校验失败。

## D-SIGN-02 身份与密钥
一次性显式 setup 命令生成自签代码签名证书，导入用户 login 钥匙串；只授权 /usr/bin/codesign 使用该私钥，不设置任意应用访问、不修改系统钥匙串或信任根。临时目录 0700、私钥 0600，退出删除临时密钥；仓库不保存任何私钥。证书 SHA-1 指纹保存在用户配置目录，之后按指纹选签名，不凭同名任意替换。已有配置不可静默重建；证书缺失/失效则报错。

## D-SIGN-03 打包顺序
现有 build_and_install_app.sh 保持构建、打包、安装顺序；在打包完成后增加最终签名。保留当前 CFBundleIdentifier，不改变已有应用身份名称。先签嵌套 Mach-O 和辅助 app，再签外层 bundle；不使用 --deep 签名。显式 DR 约束 identifier 和证书指纹，不用无证书约束的纯 identifier。完整验证失败阻止安装；--build-only 同样验证。不清 TCC、不增加全盘访问、不修改已有授权。独立 build_apple_ai.sh 仍可产生开发用 ad-hoc 辅助包，最终发布包覆盖为稳定签名。

## 验收
用不同内容的合成 app 验证 DR 相同、交叉满足 DR、篡改失败；真实打包产物执行 codesign --verify --deep --strict。旧身份迁移可能最后请求一次权限，不能通过模拟测试证明系统 UI 此后绝不提示。未授权安装时不替换 /Applications。

来源：[Apple TN2206](https://developer.apple.com/library/archive/technotes/tn2206/_index.html)。

## 独立审阅修订
signing_review 指出超分运行时 manifest.files 保存二进制摘要。签名前必须校验打包副本的既有 files；重签后仅更新实际已签文件的摘要，不更新 models，不触碰源码构建目录。每个辅助 app / Mach-O 分别 strict verify；外层验证不替代组件验证。以上纳入 D-SIGN-03，Important 已在设计中修正。

最终差异审阅修订：签名前拒绝包内全部符号链接及非法 CFBundleExecutable，防止签名或清单写入越界。现有打包布局不依赖 framework 链接；未来需要此布局应另行设计包内解析规则。相关失败用例保证任何 codesign 前拒绝。
