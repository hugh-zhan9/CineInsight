# 用受限证据工具把固定 AI 打标流水线升级为可审计 Agent

Author(s): Codex / CineInsight
Last updated: 2026-07-30
Status: Accepted
Discussion: 当前会话澄清记录
Source requirements: `.loopx/intake/2026-07-30-ai-tagging-agent/requirements.md`

## Abstract / 摘要

我们把现有“固定抽帧后一次性分类”的 AI 打标流程升级为一个有硬预算的证据获取 Agent。外部 OpenAI 兼容多模态 API 每轮只能选择一个动作：结束、请求额外帧、请求本地临时转写或查询同源内容视频。服务端验证动作、执行工具并返回结构化观察；每视频最多 4 次决策，补帧累计上限默认 20 且可配置，临时转写和同源查询各最多一次。正式标签仍只来自闭集候选并经过人工批准。

同源视频不是泛化语义推荐，而是识别同一底层内容的重编码、低清或空间裁剪版本。第一期采用本地多帧感知哈希召回候选，再用当前外部多模态 API 对候选画面做最终确认。确认关系持久化、产生未读提示并允许用户标记“不是同源”；用户否认在双方内容指纹未变化时优先于模型。

## Background / 背景与动机

当前 `AITaggingService.processVideoWithConfig` 固定执行“读取标签库 → 收集字幕和抽帧 → 调用模型 → 保存候选”，模型无法在证据不足时请求补充信息。抽帧数量由时长固定计算；外部请求只输出标签建议；现有字幕服务会写正式 `.srt` 并进入翻译和幻觉确认流程，不适合作为后台 Agent 的隐式工具；现有清理服务的文件大小与采样字节哈希只能发现物理近重复文件，无法覆盖不同清晰度或空间裁剪版本。

用户已确认一期同时支持三类补充证据动作，并固定了以下边界：临时转写不写正式字幕；音频只在本地处理；同源标签只作为证据；同源发现必须可见且可纠错；外部 API 可以接收临时转写文本和候选抽帧但必须在设置页明示。

## Goals And Non-Goals / 目标与非目标

目标：

- 让模型在硬预算内决定是否以及补多少帧。
- 让模型按需调用本地 WhisperX/Qwen 获取非持久化转写。
- 识别内容实际一致的低清、重编码和空间裁剪版本。
- 保持闭集标签、服务端校验、待审候选和人工批准不变。
- 为每轮动作、工具状态、预算消耗和结束原因留下脱敏轨迹。
- 向用户展示同源关系、未读数量和匹配理由，并支持长期否认纠错。

非目标：

- 通用语义相似视频推荐或向量搜索平台。
- 自动写入正式 `.srt`、自动翻译或绕过字幕幻觉确认。
- 自动安装字幕运行时或模型。
- 从同源视频直接复制正式标签。
- 向外部 API 上传原始音频。
- 无轮次或资源上限的通用 Agent。

## Proposal / 设计方案

### 1. 一个动作一轮，服务端拥有最终控制权

Agent 决策协议只允许 `finalize`、`request_more_frames`、`request_transcript`、`find_same_source` 四个动作。模型返回动作、补帧数量和简短理由；服务端按当前预算和工具状态验证。非法、重复或超预算动作不会执行，并作为结构化观察交给下一轮。

每视频最多 4 次决策。临时转写和同源查询各最多一次；补帧可以多次请求，但累计不超过设置项 `ai_tagging_max_extra_frames`。第 4 次必须结束；若模型仍请求工具，服务端强制进入最终闭集标签分析。

Agent 决策请求只携带均匀选出的代表帧和脱敏观察。结束后，正式标签分析继续复用当前所有抽帧分批发送、标签去重和最高置信度合并逻辑，从而避免降低现有长视频覆盖率。

### 2. 补帧数量由模型决定，时间点由确定性算法决定

模型决定请求数量；服务端在尚未采样的 5%–95% 时间范围中优先填充最大时间间隔，保证无重复、覆盖均匀并可测试。默认累计额外帧上限为 20，设置页允许调整。模型请求超过剩余额度时整次请求不执行，而不是静默截断。

### 3. 临时转写复用本地运行时但不复用正式字幕产物流程

`SubtitleService` 新增只返回内存文本的窄接口。它优先使用已就绪 WhisperX，回退到已就绪 Qwen，使用自动语言识别；两者都不可用时返回 `tool_unavailable`，不准备依赖。该接口复用音频提取和转写实现，但不写 `.srt`、不翻译、不缓存全文、不进入强制保留流程。

正式字幕任务和 Agent 临时转写共享一个可取消的转写并发槽，避免同时驱动同一本地运行时。等待并发槽时响应 `context.Context` 取消。

### 4. 同源检测先本地召回，再外部确认

本地召回不要求外部 embedding API：

1. 以时长窗口筛出候选，排除自身、失效和已删除视频，并限制候选规模。
2. 对固定时间锚点抽帧，为完整画面及多个中心/边缘裁剪计算感知哈希。
3. 用跨裁剪最小汉明距离和多时间点一致性得到本地分数，只保留最高分的少量候选。
4. 把当前视频和候选视频的受限 JPEG 联系表发送给当前外部多模态 API。
5. 只有外部结果为 `same_source=true` 且 `confidence=high` 时创建或刷新同源关系。

本地阈值是召回阈值，不是最终产品结论；外部确认负责过滤“仅人物/场景相似但内容不同”的误召回。完全相同的字节采样哈希仍可作为排序加速信号，但不会绕过外部确认。

### 5. 同源关系是可否认的持久数据

关系按排序后的视频 ID 唯一保存，记录双方内容指纹、状态、置信度、匹配理由、检测版本和未读状态。状态为 `detected` 或 `rejected`。用户点击“不是同源”后写为 `rejected`；只要双方内容指纹仍与否认时一致，后续任务不得再次确认。任一内容指纹变化后允许重新比较。

同源视频已有的正式、非自动标签只作为当前 Agent 的辅助观察；最终仍经过当前闭集标签分析和人工审批。

### 6. UI 使用未读徽标和非阻塞审阅

`AITaggingStatusSummary` 增加未读同源数量。首页“AI 标签管理”入口显示徽标；审阅弹窗同时加载待审标签和同源关系，展示双方名称、路径、匹配理由及“不是同源”操作。成功加载的关系用幂等接口标为已读。后台发现不得弹出系统对话框。

| Support lens | Trigger | Design checks applied | Result |

| go-style | Go 接口、context、并发槽、测试 | 小接口、取消、错误分类、race 验证 | 在消费方定义转写/同源工具接口；共享运行时槽支持取消 |

## Boundary Scenarios / 边界场景

| 场景 | 处理 |
|---|---|
| 模型返回未知动作或非法 JSON | 外部模型调用视为失败，视频状态为 `failed`，保留可诊断错误 |
| 模型请求 0、负数或超过剩余补帧预算 | 不执行，写 `invalid_request`/`budget_exceeded` 观察；下一轮继续或强制结束 |
| FFmpeg 缺失或部分补帧失败 | 记录工具失败/部分成功，继续剩余证据，不静默伪装成功 |
| 已有字幕时仍请求临时转写 | 返回 `already_available`，不执行本地 ASR |
| 本地字幕引擎都不可用 | 返回 `tool_unavailable`，不安装依赖，继续流程 |
| 同源候选为空 | 返回成功的空观察，不创建关系 |
| 外部同源确认超时 | 同源工具失败，但主 Agent 可继续；外部最终标签分析失败仍使视频失败 |
| 两个并发任务发现同一视频对 | 排序 ID 唯一键 + upsert 保证只有一条关系 |
| 用户否认与后台确认并发 | 数据库行锁/条件更新使 `rejected` 优先；相同内容指纹下后台不得覆盖 |
| 视频被替换但路径不变 | 内容指纹改变，视觉指纹缓存失效，旧否认不再阻止新比较 |
| 视频软删除 | 新比较排除；已有关系和历史候选保留并显示删除状态 |
| 旧模型响应不包含 Agent 动作 | 兼容解释为 `finalize`，保留原有一次性打标行为 |
| 回滚到旧应用版本 | 新表和设置列被旧代码忽略；旧 AI 打标状态、候选和审批表保持兼容 |

## Rationale / 理由与取舍

| Alternative | Why Not |
|---|---|
| 让模型任意调用工具直到满意 | 无成本上界，难以恢复和测试，也会扩大隐私外发范围 |
| 用现有正式字幕生成接口 | 会写 `.srt`、翻译并引入人工幻觉确认，违反临时证据边界 |
| 全库视频两两交给外部 API 比较 | API 成本随视频数平方增长，且不必要地上传大量候选画面 |
| 第一期开通用视觉 embedding/向量库 | 当前外部配置不保证 embedding，新增模型和索引运维超出同源检测目标 |
| 只使用文件大小与采样字节哈希 | 不能覆盖重编码、低清和空间裁剪版本 |
| 同源后直接复制标签 | 误匹配会自动传播正式数据，破坏现有人工审批语义 |
| 把全部 Agent 上下文和模型理由持久化 | 可能保存临时转写或画面敏感内容；轨迹只保存结构化元数据 |

## Compatibility / 兼容性

方案是加法兼容：新增 GORM 模型、设置列、Wails 方法和 JSON 字段；现有方法签名、候选状态、正式标签关系和人工审批行为不变。旧模型若忽略新增动作字段按 `finalize` 处理。数据库不做历史回填或破坏性更新；旧版本应用可以忽略新增表和列。

## Operational And Security Impact / 运行与安全影响

- 外部发送范围增加到临时转写文本和候选视频抽帧；设置页必须明示，原始音频禁止外发。
- 请求日志不得输出 payload、Data URL 或临时转写全文；保留视频 ID、轮次、动作、数量、耗时、HTTP 状态和错误摘要。
- 文件名、路径、字幕和同源标签都视为不可信证据，系统提示词明确禁止把其中内容当作指令；服务端枚举和预算校验是最终权限边界。
- 后台 Worker 仍串行处理视频；每视频最多 4 次决策、配置上限额外帧、1 次转写和 1 次同源查询。
- 本地召回最多检查 200 个元数据候选，最多向外部确认 5 个视觉候选；这些是代码常量，改变上限必须回到设计评审。

## Implementation And Transition / 实现与过渡

数据结构、纯算法与模型协议应先落地并测试，再接入字幕工具和 Worker 状态机，最后开放 Wails/UI。迁移只通过现有 `AutoMigrate` 与 `ensureAITaggingIndexes` 增量完成。发布后无需回填：视觉指纹按需生成，同源关系从新处理的视频开始累积。

## Open Questions / 待决问题

无。感知哈希阈值需要由自动化夹具验证后可在不改变产品语义的前提下微调；若要改为 embedding 或放宽为通用语义相似，必须重新进入 spec。

## Detailed Design Handoff / 详细设计交接

详细设计现在编写，并将以下约束视为固定：四轮单动作 Agent、补帧默认上限 20 且可配置、本地临时转写、同源本地召回加外部高置信确认、持久可否认关系、未读 UI、脱敏轨迹及现有人工审批不变。
