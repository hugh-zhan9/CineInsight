# 桌面壁纸 · 概要设计

状态：用户已选择「图片设壁纸 + 视频循环播放作动态壁纸」，并要求继续实现。2026-10-09 首版；实现与验证记录见[详细设计](需求设计文档.md)。

来源：本轮用户提出视频、图片可设为桌面壁纸，且「太糊了就没必要了」；随后明确选择动态视频。首版范围采用继续实施前说明的 macOS 14+、长边至少 1920 / 短边至少 720、视频无声循环、应用退出即停止。

## 能力与所有权

<a id="D-WALL-01"></a>
**D-WALL-01 · Behavior / Architecture Contract · 已采用**：图片调用系统桌面图片接口；视频在应用进程内使用 AppKit 桌面层窗口与 AVFoundation 循环播放器。每个当前显示器一层，位于桌面图标下方、不接收输入，动态窗口加入所有 Space。静态图片接口作用于各显示器的当前桌面，不承诺改变其他未激活 Space。视频功能依赖应用持续运行；停止或退出后移除窗口，露出原系统壁纸。不给系统安装后台登录项，不替换 Apple 的屏保资源。

新增壁纸服务只拥有壁纸操作与原生播放器生命周期。现有 `PreviewService` 通过 WebView / 系统播放器预览，无法拥有桌面层窗口，不能复用其播放路径。沿用既有 macOS cgo 接入惯例、App 生命周期、媒体 ID 查询和应用数据目录；原生层管理窗口和播放器，不反向写媒体记录。

新增依赖如下，箭头表示调用方向：

```mermaid
flowchart LR
  UI[媒体详情中的壁纸按钮] --> APP[App 壁纸绑定]
  BAR[全局动态壁纸状态条] --> APP
  APP --> SERVICE[壁纸服务：校验与生命周期]
  SERVICE --> MEDIA[现有媒体记录与本地源文件]
  SERVICE --> NATIVE[macOS 原生适配：桌面图片与视频窗口]
```

<a id="D-WALL-02"></a>
**D-WALL-02 · Behavior Contract · 已采用**：以真实像素尺寸限制素材。首版长边 ≥1920 且短边 ≥720，1920×800 与旋转后的 1080×1920 可用，1280×720、1920×600 不可用。元数据未知时给出补全尺寸提示；应用前重新检查原文件的真实尺寸，不信任过期数据库值。该规则是最低分辨率要求，不声称检测失焦、压缩伪影或保证在 4K/5K 屏幕上原生像素显示。不自动超分。

## 运行与失败

<a id="D-WALL-03"></a>
**D-WALL-03 · Operational Contract · 已采用**：整个应用同一时间只播放一个动态壁纸视频。原生 AVFoundation 判断源文件是否可播，格式不支持明确失败；不隐式生成代理或转码。视频使用原文件，图片按内容摘要保留独立副本，避免移动或删除图库原图立即破坏系统壁纸。副本不自动淘汰，系统可能仍在其他 Space 使用旧副本；不复制整部视频。

输入/原文件检查失败时保留当前壁纸。视频启动后的异步解码失败停止其窗口，并通过全局状态条显示失败；此时露出原系统壁纸。系统休眠、显示器休眠或用户会话失活时暂停，恢复时继续。显示器变化时重新构造当前显示器的窗口。静态图片在多显示器上逐屏设置，失败时尝试恢复已改变的屏幕，恢复失败须明确报告可能部分改变。

| 当前状态 | 事件 | 结果 |
| --- | --- | --- |
| 空闲 / 失败 | 设置合格视频 | 启动中，再由原生播放器报告播放中或失败 |
| 启动中 / 播放中 / 暂停 | 设置另一合格视频 | 替换视频，重新启动；校验拒绝则原状态不变 |
| 启动中 / 播放中 | 系统休眠或会话失活 | 暂停 |
| 暂停 | 系统恢复且会话活跃 | 启动中 / 播放中 |
| 任意动态状态 | 设置图片成功 / 停止 / 应用退出 | 移除动态窗口并释放播放器；停止可重复执行 |
| 活跃动态状态 | 播放器失败 | 移除窗口，报告失败，可重新选择素材 |

壁纸播放不经过播放记账、断点更新或后台作业登记表。全局状态条提供停止入口，独立于原素材详情页。原生窗口、观察者和定时器随停止释放；应用关闭后不留播放器进程。

## 验证边界

自动化覆盖质量边界、缺失/失效文件、重复停止、失败保留旧状态、图片副本、源变更和并发退出，以及界面拒绝/设置/停止。原生编译与完整 Wails 构建验证链接。多屏、Space、桌面图标穿透、无声循环和系统休眠恢复需真实图形会话观察，不能以模拟播放器的测试宣称验收。
