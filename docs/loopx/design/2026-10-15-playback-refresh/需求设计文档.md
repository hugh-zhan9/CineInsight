# 播放续播与首页推荐更新

来源：2026-10-15 用户要求应用内全屏、修复重复起播到旧位置；随后选择“保留自动续播，但接着最新进度”，并要求从首页“今晚看什么”进入播放后用新推荐补位。

## D-01 最新断点

保留自动续播以及字幕命中、书签的指定位置跳转。普通详情页应用内播放每次展开前等待该页已排队的进度保存，再读取最新视频进度；切换到直接播放前暂停应用内播放器、补报当前位置并等待保存成功。失败就地提示，不用旧值启动。异步读取期间关闭、换片或卸载后，旧请求不得重新打开播放器。更新进度仍由既有宿主持久化，播放器只报告进度，IINA 同步仍由既有服务负责，不改变完成判定与跳转会话的前向保护。

## D-02 今晚看什么补位

首页推荐卡和来自“今晚看什么”的首页大图进入详情后，应用内播放器触发开始播放，或直接播放返回启动成功时，替换对应推荐。只打开详情、启动失败、无关视频的播放都不触发替换。

由 `InlineVideoPlayer` / `VideoDetailPage` 报告开始播放，`App` 转发到已挂载的 `HomePage`；推荐状态仍归首页。复用 `SuggestTonightVideos`，沿用首页默认条件，排除当前推荐，取一条放回原槽位，其他卡片顺序与内容不变。重复播放通知只处理一次；并发补位串行执行，旧请求不能覆盖“换一批”的新结果。若大图对应被替换的推荐，大图一并换成新条目；其他大图保持原样。

候选耗尽或请求失败时，沿用现有换批规则保留原卡片并显示提示，可用“换一批”重试。不更改随机计数、不将推荐替换当成一次播放、不新增后端接口或持久化状态。

## 验证

组件测试覆盖最新断点、保存顺序、失败与迟到响应；播放开始通知覆盖内嵌与外部成功/失败。首页测试覆盖单槽替换、不重复、空候选、错误及并发。完成后运行前端全量测试和构建。全屏的原生窗口行为需要桌面真机验证，单元测试不代替该验证。

## D-03 跨详情实例的保存顺序（独立检查修订）

现有详情、片库和实体页各自维护 Promise，关闭详情后新实例看不到旧实例未完成的保存。新增前端 `utils/watchProgress.js` 统一按视频 ID 串行调用既有 `UpdateVideoWatchProgress`，只持有未完成或失败的最后一次请求；成功立即释放。不存另一份观看进度，不改变后端数据合同。宿主仍负责接收播放器报告和更新界面，直接播放入口等待该视频保存完成后再调既有 `PlayVideo`。

失败当次阻止播放并提示；用户再次点击播放时重试该视频最后失败的保存，成功才继续，不能让一个 false 状态永久锁住按钮。请求还在进行中时不自动重试失败，只有后续明确播放操作触发重试。不同视频互不等待。

“今晚看什么”的来源标记只对本次打开有效：返回首页或从其他入口打开视频时清除，不因相同视频 ID 沿用上一次未播放的选择。

验证结果（2026-10-15）：`npm test` 全部通过（187 个组件/工具测试文件，2,986 项测试，另含源码与设计守卫）；`npm run build`、`go test .`、`go vet .` 通过。`scripts/test_viewing_notes_webkit.sh` 在原生 WKWebView 中使用生成的视频通过解码、书签区间暂停、继续播放与重播检查。保存队列的三项手工变异（跳过保存等待、同视频并发写、取消失败重试）均使相应测试失败，变异副本已删除。独立复审无遗留 Critical / Important 问题。全屏系统窗口切换尚未真机实测。
