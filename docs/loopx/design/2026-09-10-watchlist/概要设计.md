# 想看 · 概要设计

版本 v1.1，2026-09-10。需求来源：本次对话，用户要求记录未入库的想看片名，确认手动移除，并给出「想看 / 待下载」命名范围；采用「想看」。v1.0 于实现前记录；v1.1 回写独立代码评审：分页空态问题已修复并复核，详见详细设计 §11.1；未声称用户进行过额外设计评审。

## 1. 背景与范围

一个手工维护的想看片单，只需填写片名。支持添加、搜索、改名和移除。扫描入库不改变片单；不接下载任务，不抓取在线资料。（2026-09-11：「不抓取在线资料」已被取代，见 D-W01 下的说明；**不接下载任务仍然成立**。）

## 2. 总体设计

**D-W01 · Architecture Contract**：沿用桌面 Vue → Wails App → services → 当前 GORM 数据库的依赖方向。新增 WatchlistService 拥有片单 CRUD，watchlist_entries 是唯一持久来源。无后台工作、外部接口或文件操作。

> **2026-09-11：本条末句「无后台工作、外部接口或文件操作」已被取代。**[想看片单在线补全](../2026-09-11-watchlist-online-metadata/设计提案.md) 已接受并实现：片单新增 `kind` 类型维度、后台补全任务 `watchlist_enrich`、四个外部资料源适配器，海报经 `ManagedImageService` 落盘。唯一约束由 title 改为 (title, kind)。本条其余部分（依赖方向、WatchlistService 拥有片单 CRUD、watchlist_entries 是唯一持久来源）仍然成立。

现有 `models.Video` 表示有本地路径的视频，`CollectionVideo` 必须关联视频 ID，因此不能用空路径视频或空作品集代替一条想看记录。复用 `models.AllModels`、数据库迁移/备份、现有分页与 LIKE 转义、顶栏导航和命令面板。代价是一张独立小表和一个桌面页面；删除模块时可单独移除入口与服务，表留存不会影响媒体。

## 3. 分模块方案

页面只在进入时加载。输入片名回车添加，行内改名与手动移除，默认最新添加在前；搜索覆盖全部持久记录，分批加载。移除复用应用内确认框。请求失败保留输入和已有列表，明确显示错误。

App 只转发参数；服务校验字段并执行单条 SQL。片单无媒体外键，视频新增、删除与扫描均不触发片单变化。

## 4. 改动清单

新增一个模型、一个服务、四个 Wails 方法、一个 Vue 页面；修改模型登记表、App 构造、导航和生成绑定，增加回归测试。既有表结构不变。

## 5. 对外影响

应用重启迁移后创建空表，无数据回填；既有数据库备份和双向迁移按原机制覆盖该表。手机端和 Jellyfin 不暴露片单。

## 6. 风险与待确认

用户已确认手动移除，当前无阻塞产品问题。同名影片可能不同版本，允许同名条目并按 ID 操作，用户可在片名中写年份。没有自动匹配准确率承诺。

## 7. 验收要点

持久增改删、空白与长片名校验、搜索特殊字符、稳定分页、入库不自动移除、前端失败保留输入与内容、删除确认、导航、构建和现有回归。字段和验证映射见 [需求设计文档](需求设计文档.md)。
