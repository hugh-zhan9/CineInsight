# 审阅搜索性能基线

2026-10-10，修改审阅搜索实现之前采集。环境：Go 1.27.1，darwin/arm64，临时 SQLite；测试文件与数据库均为合成夹具，不打开用户数据库或媒体。

可重复脚本：`.loopx/workspace/2026-10-10-media-workbench/review-bench.go`。

```sh
go run .loopx/workspace/2026-10-10-media-workbench/review-bench.go
```

每个视频10条 pending/high 候选，候选包含重复的中文理由和简短来源摘要。按旧搜索方式以200条/页加载到末页，序列化与保留全部详情，然后才具备前端全量筛选的输入。包括末尾一次空页调用。只测取数/序列化，不包含 Wails 实际传输、浏览器 JSON 解析、前端过滤与 DOM 渲染。

| 候选数 | 每轮调用 | JSON 总字节 | 3轮耗时（ms） | 3轮累计分配字节 |
|---|---:|---:|---|---|
| 20,000 | 101 | 39,625,421 | 3357 / 3393 / 2617 | 258,007,168 / 246,024,480 / 257,955,544 |
| 100,000 | 501 | 198,248,242 | 43397 / 54220 / 45541 | 1,165,523,072 / 1,151,632,064 / 1,171,495,512 |

JSON 分别约37.8 MiB和189.1 MiB。分配指标来自 `runtime.MemStats.TotalAlloc` 差值，是整轮累计分配，不是峰值或常驻内存。样本数只有3，不能报告 p95。同机期间有其他验证任务，耗时仅为此夹具的基线观测，不是生产 SLA；后续须在同一程序/同样负载下交替比较新旧查询。

确定的改进目标：搜索首屏不再下发全量详情，返回数量不超过请求页大小；完整命中范围仍覆盖未加载的候选。审批预览按标识与版本固定集合，不为展示数量把全部详情送到前端。

尚未取得：PostgreSQL对比、真实 Wails 端到端延迟、主列表/WebKit滚动与布局基线。不能把本记录当作这些项目已验证。

实际 GORM 夹具（SQLite 3.45.1，20,000 条）的计划检查也已完成：

```sh

```

- 旧索引：`SEARCH ... USING INDEX idx_ai_tag_candidates_status_approved (status=?)`，随后 `USE TEMP B-TREE FOR ORDER BY`。
- 临时增加 `(status,id DESC)` 后：`SEARCH ... USING INDEX idx_ai_tag_candidates_status_id (status=? AND id<?)`，不再额外排序。

此检查只改临时数据库的索引；实际模型/迁移变更仍需实施与回归。

收益主要来自不再水合/发送整个候选库。10万条下，常见词首屏由501次取数、约189.1MiB JSON降至1次、约96.9KiB；稀有词和无命中仍检查整个候选范围，CPU和累计分配仍随库规模增长，但查询批次最多256行，只保留命中ID及当前页详情。`TotalAlloc` 仍不是峰值内存，不能据此声称RSS下降到某数值。

SQLite3.45.1的索引检查已进入回归；临时独立 PostgreSQL18 中同一套搜索/游标/索引测试通过（services11.346s），未取得PG同规模性能结果。真实Wails往返、DOM、WebKit滚动与内存仍由下一渲染切片验证。

## 原生WebKit布局基线（P-011前置调查）

以当前生产 VirtualVideoList/VideoListRow 及样式，在本机WKWebView运行20,000条合成视频、每项0/8/16/24标签；不连接Wails/数据库/媒体。临时夹具目录`.loopx/workspace/2026-10-10-media-workbench/webkit-baseline`，原始结果`/tmp/cineinsight-webkit-baseline.log`。NSWindow不获取焦点、alpha为0.01，结果来自实际WebKit布局；不是完整Wails界面的人工作业验收或视觉截图。

启用现有虚拟列表后，初始15个行节点，深处23个；scrollTop=500000、宽1100时顶部可见ID=4374，偏移-62px。宽度改为660后scrollTop仍为500000，但顶部可见ID跳到2316、偏移-747px；恢复1100后回到4374。证实当前宽度变化使用新高度估算重算窗口，没有保住旧可见媒体锚点。UA为`AppleWebKit/605.1.15`。这项基线不证明禁用守卫可以直接移除，修复后还需相同夹具及更多追加/删除/网格场景复验。


## P-011 最终窗口与原生布局验证

2026-10-10，当前实现使用持久逻辑行高度索引，滚动不遍历全部条目；数据追加、splice、标签名称/布局变化才重建。新测量在Vue提交后合并执行，并隔离重建/失活/过期代次。前置原生基线窗口的动画回调会被WebKit挂起，不能据那一轮结果推定真实可见Wails窗口的帧率；后续检查同时核对实测高度与索引，并改为不依赖动画帧触发首轮测量。

可重复运行的原生检查已收入仓库：

```sh
bash scripts/test_virtual_window_webkit.sh
```

脚本在本机编译临时Cocoa/WKWebView测试窗口，使用真实VirtualVideoList、VideoListRow及两个完整审阅面板；Wails接口由合成数据提供，不访问媒体/数据库。窗口不抢焦点，结束即关闭，编译目录自动清理。Vite正常打包、原生检查退出0；故意抛错的fixture返回1、runner缺参返回2、构建缺临时输出参数返回1，不会把未完成或失败算通过。最终原始结构化记录：[webkit-results.json](webkit-results.json)。
