# 多版本聚合

2026-10-10，Ready（主代理按已授权的“设计后开发”收敛，解除P-006阻碍）。对应源AC-07、Q15与TC-16，概要决定见[D-MW-VERSIONS](概要设计.md#D-MW-VERSIONS)。不改变作品集、同源关系、清理、随机计分或任何文件级元数据的既有语义。

## 行为

- 版本组由用户确认建立：片库多选≥2个视频“合并为版本组”，或在版本组面板接受建议。一个视频最多属于一个版本组；作品集和同源关系保持独立，一个视频可同时在作品集里又在版本组里。
- 每个成员有可编辑短标签（如“原版”“高清版”“编辑版”，≤40字符，默认空）和顺序；第1位是主版本。组有可选标题（≤200字符，空时界面显示主版本标题）。
- 已看、观看进度、个人评分、收藏、点赞、标签、人物、字幕、播放计数全部按文件独立保存（Q15）。分组只做汇总展示，任何版本组操作都不写成员的这些字段。
- 播放：卡片默认播放代表版本；展开后每个版本都有播放与预览，调用既有`PlayVideo`/详情抽屉，按所选具体文件校验与计数。
- 删除：删除一个版本只走既有删除流程删除这个文件，其他版本不受影响。软删除的成员保留成员行，不参与展示与汇总；从回收站恢复后自动回到组内。永久删除时成员行随外键级联删除。活跃成员不足2个的组按普通单文件卡片展示；任何版本组写操作会顺带清理成员总数不足2的组。
- 原有单文件视图随时可用：片库工具栏“合并版本”开关（默认开，按本机记住），关闭时与现在完全一致。

## 片库聚合查询

`LibraryFilter`新增`collapse_versions bool`。只有`SearchLibraryVideoPage`（均衡与评分两种排序）和`CountLibraryVideos`读取它；随机播放、今晚看什么、语义搜索、最近播放、继续观看、字幕命中、按筛选批量生成代理等文件级入口一律忽略。保存视图不持久化该字段。

为真时在原有过滤之外再加一个代表成员条件：

```sql
videos.id IN (
  SELECT ranked.id FROM (
    SELECT videos.id,
           ROW_NUMBER() OVER (
             PARTITION BY COALESCE(vm.group_id, 0 - videos.id)
             ORDER BY COALESCE(vm.position, 0), videos.id) AS version_rank
    FROM videos LEFT JOIN video_version_members vm ON vm.video_id = videos.id
    WHERE <与外层相同的applyLibraryFilter条件> AND videos.deleted_at IS NULL
  ) ranked WHERE ranked.version_rank = 1)
```

即每组在**符合当前筛选的成员**中取顺序最靠前的一个作为代表，卡片位置、排序键和游标都沿用代表行，原有排序与游标代码不动。SQLite（≥3.25）与PostgreSQL都支持窗口函数；组内没有成员符合筛选时该组不出现。计数按卡片计。翻页期间组发生变化（加入、移出、代表被删）只影响后续页，前端在组操作成功后按现有原地刷新重取，不保证跨组变更的游标连续。

页结果`LibraryVideoPage`新增`version_groups map[video_id]VersionGroupSummary`（键为本页代表视频ID，只为本页中属于活跃成员≥2的组返回）：

| 字段 | 内容 |
|---|---|
| `group_id`、`title`、`revision` | 组标识与当前版本 |
| `member_count` | 活跃成员数 |
| `watched_count`、`rated_count`、`min_rating`、`max_rating` | 活跃成员汇总；没有评分时为空，不报0 |
| `members[]` | 活跃成员按顺序：`video_id, label, position, display_title, name, resolution, width, height, size, duration, is_watched, watch_position_seconds, personal_rating, is_stale` |

只为本页代表的组做一次批量查询，不逐卡查询。

## 数据与并发

新增三个`AllModels`成员（排在`videos`之后，均无非零gorm default）：

- `video_version_groups`：`id`、`title`、`revision`(int64)、`created_at`、`updated_at`。
- `video_version_members`：`video_id`主键（不自增）→videos ON DELETE CASCADE，即一个视频至多一个组；`group_id`→groups ON DELETE CASCADE；`label`、`position`(>0)、`created_at`。索引`(group_id, position)`。
- `video_version_suggestion_dismissals`：`id`、`video_low_id`、`video_high_id`唯一对、`created_at`。无外键，永久删除后惰性滞留无害。

所有成员变更在一个事务内先`UPDATE video_version_groups SET revision=revision+1, updated_at=? WHERE id=? AND revision=?`，零行返回`version_group_conflict`（调用方重读）；再增删改成员。加入时成员主键冲突（视频已在其他组）返回`version_member_conflict`并列出冲突视频ID。不使用数据库锁。

## 服务与接口

新增`VersionGroupService`（`services/version_group_service.go`）。App接线（`app_versions.go`），全部有前端调用方：

| 方法 | 规则 |
|---|---|
| `CreateVersionGroup(video_ids, title)` | 2–20个去重后的活跃视频，都不在组内；按传入顺序成为1..N |
| `GetVersionGroup(group_id)` | 组与全部活跃成员（同上`members`字段）及软删成员数 |
| `ListVersionGroups(cursor_id, limit)` | 管理面板分页，按id倒序，limit默认50、最大200 |
| `AddVersionMembers(group_id, expected_revision, video_ids)` | 追加到末尾；总数不超过20 |
| `RemoveVersionMember(group_id, expected_revision, video_id)` | 只移出关系，不删文件；剩余<2时解散组 |
| `ReorderVersionMembers(group_id, expected_revision, video_ids)` | 必须正好是当前全部成员的排列（含软删成员按原相对顺序附后）；第1位即主版本 |
| `UpdateVersionGroup(group_id, expected_revision, title, labels map[video_id]string)` | 只改标题与标签 |
| `DissolveVersionGroup(group_id, expected_revision)` | 删除组与成员行，不动视频 |
| `ListVersionGroupSuggestions(limit)` | 见下 |
| `DismissVersionGroupSuggestion(video_ids)` | 记录建议中的全部视频对，之后不再建议 |

建议只来源于既有`video_same_source_relations`中`status=detected`的配对：双方都是活跃、非失效且不在任何组内，时长都已知且较短者≥较长者的90%（排除截取片段），并且配对未被忽略。按并查集连成候选组，每组≤20个，按成员数和最新关系时间排序。建议从不自动建组。

## 界面

- 片库行/卡片：属于组时显示“N 个版本”徽标与汇总（如“已看 1/3 · 评分 7–8.5”）；点击徽标在卡片内展开版本列表，每个版本显示标签、分辨率、大小、时长、已看/进度、评分，带播放、预览、设为主版本、移出组。展开状态并入虚拟列表的`itemVersion`，测量后高度正确。
- 行菜单“管理版本组…”，批量栏“合并为版本组”（选中项已有组时报冲突并给出“加入该组”的选项，仅当冲突项都属于同一组）。
- 管理菜单“版本组”面板：建议（建立/忽略）与已有组（重命名、标签、排序、移出、解散）。
- 视频工作台的高清替换与去片头成品可“与原片建立版本组”，调用`CreateVersionGroup`或`AddVersionMembers`。
