# 今晚看什么

2026-10-10，已实施并验证；对应源AC-05/TC-14与D-MW-DISCOVERY。用户已授权设计后开发。本功能不依赖待答复的日记/书签记录规则，从原P-005中独立为P-012。

## 行为与范围

片库工具栏打开选片弹窗，完整继承当前LibraryFilter（包括关键词、标签、人物、体积、分辨率、评分、智能视图与目录范围）。语义搜索没有可复用的LibraryFilter边界，沿用当前随机入口的处理：入口禁用并解释原因，不能忽略语义条件去全库推荐。

弹窗填写可用分钟数（默认90，0表示不限，最大1440），可选仅未看和仅收藏。仅未看默认开启；当前智能视图为已看时初始关闭，以免默认条件自相矛盾。用户主动选择相互冲突的条件时返回空集，不代替用户改条件。可用时间按整片时长计算，界面写明；不从历史断点推算本次剩余观看时间。

推荐只读取媒体和观看事实；字幕派生索引按下述规则沿用既有同步。没有播放启动、计数递增、推荐历史、模型调用或新持久表。选择预览/播放时复用原片库动作。关闭弹窗不取消或改写原片库筛选。输入变化清除旧候选；失败显示错误，不把旧条件下的候选作为新结果。晚到响应按请求代次丢弃。

## 接口与查询所有权

App新增`SuggestTonightVideos(TonightRequest) -> []TonightSuggestion`，仅转交现有VideoService。Request为`filter: LibraryFilter`、`max_duration_seconds: int64`、`unwatched_only: bool`、`favorites_only: bool`、`limit: int`；时间范围0–86400秒、limit默认6/最大12，越界明确错误，不静默截断。前端固定取6条。

时长是本次决策的预算，故放在TonightRequest，不扩大LibraryFilter或保存视图的数据合同。保存视图的既有条件仍原样带入；随机入口及其计分/排除表不变。

VideoService复用`normalizeLibraryFilter`与`applyLibraryFilter`。查询在维护operation gate内执行，整个DB读取携带context；扫描根和排除规则仍归现有scope函数，必要时只给这些函数增加内部带DB参数的复用入口，不复制范围逻辑。字幕筛选沿用现有节流索引同步，不新增扫描任务或隐式全库回退。

除LibraryFilter条件外始终排除失效记录，且叠加用户勾选的未看/收藏条件。当预算>0时要求`duration > 0 AND duration <= budget`，因此未知时长不冒充符合上限；预算为0时允许未知时长，并明确标识。只取limit条并为它们加载标签，不能先读取全库DTO再筛选。

排序固定为：收藏优先、未看优先、个人评分从高到低（NULL排后），随后最近入库和ID倒序。排序仅影响本次候选，不继承片库随机分数或写回排序偏好。每项返回Video及中文理由数组；理由只引用满足预算、收藏、未看、已存在的个人评分及当前标签/人物条件。未评分不能报0分，不输出推测内容或“你一定喜欢”。弹窗解释上述排序规则。

## 空态、失败与验证

零匹配明确显示“没有符合全部条件的视频，可调整时间或片库筛选”，不放宽范围。没有自动重试、自动外发或替换筛选。绑定入口遵守数据库不可用/维护/待重启合同；错误不记媒体内容或凭证。

验证覆盖：0/单项/超过limit；预算恰好等于时长与多1秒；未知/零时长；已看/收藏与原筛选的交集；不同评分与NULL排序；标签人物、目录/排除范围；查询前后播放计数和事件不变；取消context与维护；SQLite与一次性PG；UI输入变化、晚到响应、错误与空态、打开原视频。生成绑定后运行消费守卫，并独立检查最终新增公开接口及调用方差异。
