# 批量审阅：预览、冻结与执行

2026-10-10。实施依据为原需求 AC-01 / TC-09、用户 Q14；是 [D-MW-PERF](概要设计.md#D-MW-PERF) 的详细合同。用户已授权按需求设计后开发。本合同不改变单项批准、拒绝、正式标签归属或媒体删除语义。

## 所有权与状态

视频与图片候选服务各自拥有一份进程内审批工作流，复用一个私有协调实现。它只保存待确认的候选版本及本进程最近一批结果，数据库中的候选和正式标签关系仍是事实来源；不增加持久表、不新建审批数据库、不自动重试审批。App 只校验媒体种类、维护状态并转发。

预览 `ready → consumed / expired / cancelled`；执行 `running → completed / cancelled / failed`。每种媒体同时最多一个执行任务；运行时拒绝另一个预览或启动。取消在单项之间生效，已经提交的审批保留，未处理部分保持原状。批次中的单项失效或失败不撤销其他成功项；系统取消、数据库不可用或维护中止批次，不循环制造同类失败。未分类的单项数据库错误后至多做一次有5秒期限的只读连接检查，连接不可用则中止；不重试审批写入。

应用关闭会禁止新的预览/启动，取消并等待在途预览构建和执行事务；任务登记与退出提示使用已有 BackgroundTaskRegistry，且须显式扩展 quitBlockingTasks（该函数不会自动枚举全部key），增加视频/图片审阅两个固定 key，任务中心提供进度和取消。数据库恢复/切换先使预览失效、停批次并等待，再换连接；维护失败退出后允许新预览，旧令牌不复用。启动与维护互斥沿用 App 的 restoreMu，仅持锁完成认领，不持锁等待后台执行。应用重启后不自动批准剩余项；已成功项已落库，剩余待审需重新预览确认。

## 两个范围

- `loaded`：调用方在点击时复制已加载且命中当前筛选的候选 ID；组头“本组全部”也用此范围。服务去重、读取当前版本及资格，不信任前端数量。
- `filtered`：使用查询合同的关键词、媒体、标签及置信度，固定 pending、从首游标开始；在服务端遍历完整匹配集合，不接收前端所谓总数，也不把全部详情发回前端。

两者都先返回 `token / matched / eligible / media_count / link_count / excluded / expires_at / scope`。matched 是本次观察到的候选数；eligible 是当前可批准的高/中置信、媒体活跃、匹配标签仍可用的候选数；link_count 按媒体+标签去重。前端显示实际候选数与受影响媒体/关联数，再确认。没有可批准项只显示结果，不发启动请求。

预览查询在读取匹配证据的同一条SELECT中取得候选全部标量字段并计算版本摘要；后续资格加载只有版本仍相同才进入集合，变化者排除，不能用后来版本替换。期限仍为60秒。未采用覆盖整个预览的事务：现有SQLite DSN使用_txlock=immediate，长期预览事务会占用写锁。普通搜索仍只读原有瘦字段，额外版本字段仅在审批预览路径读取。预览每页读取至多200条候选详情，不预载无关内容；只冻结预览时 eligible 的候选 ID 与 SHA-256 版本摘要；excluded 仅计数、不保存为可执行成员，之后恢复媒体或标签资格也不能加入该批。未消费成员容量按 eligible 计，单次匹配硬上限仍按 matched 计。摘要包含候选全部持久标量字段（含目标媒体/标签、名称、置信度、理由、来源摘要、来源 run、状态及精确时间），不含关联模型对象。不能只比较前端格式化到秒的 updated_at。

确认只传已经预览的 token。启动原子消费该令牌；在该批结果仍被保留期间，同一令牌重复启动返回已有批次状态，不重复执行；下一批替换结果之后，Start/Get(旧令牌)统一返回 review_batch_expired，绝不重建或重跑旧批。过期或未知令牌明确失败，禁止重新按筛选取数再批准。执行前在既有单项审批事务内读候选并核对摘要、pending、媒体和标签资格；发生变化明确记为 changed/skipped，不能改批另一标签。context必须在获取连接/Begin之前注入，覆盖整笔事务及维护等待；database.WithOperationContext沿用已有维护操作围栏并在围栏内捕获当前句柄，供事务和候选核对读取复用，不新开读取事务或数据库锁；复用现存事务锁/条件更新，不新增应用控制的数据库锁。批次调用抽出的事务核心，以提交成功的紧凑结果计成功，不调用单项API提交后的DTO水合；详情读取失败不能将已提交审批记作失败。单项API保留其原有详情返回合同。

批准会沿用既有领域规则，让同媒体同标签的重复候选退出待审。新出现的候选不成为本批审批成员，也不会被计为批准成功；同目标重复候选可能因正式标签已建立而被既有规则置为 superseded。预览范围不扩大为其他标签或媒体。

## 容量、期限与结果

每个服务最多保留2份未消费预览，所有未消费成员合计不超过1,000,000条；单次匹配也以1,000,000条为硬上限，超过时整个预览失败并提示缩小筛选，不返回可误认为“全部”的截断集合。一个预览构建期间拒绝并发构建，避免多个请求同时绕过容量限制。读取有60秒context期限；失败不产生令牌。预览构建与执行都在工作流锁下登记准入/取消与在途计数；维护或退出将工作流置为 closed 并递增代次，取消两类在途工作，等待退出。发布预览时必须再次核对 closed、构建代次和context；即使驱动在取消后才返回，旧构建也不得发布令牌。维护失败恢复以空的新工作流代次接纳请求，旧构建/旧令牌不能复活。预览10分钟过期；取消确认主动释放预览，此外每次请求清理过期项。

只保留本进程最近一批执行结果，下一批启动时替换已结束结果。摘要包含 token、状态、总数、已处理、成功、跳过、失败、未处理、开始/结束时间；每项只保留候选 ID、媒体 ID、标签 ID、结果状态与稳定原因码，不持有媒体详情或完整错误文本。结果按执行次序以最多200项分页返回，游标为本批结果序号，绑定必须带 token 防止串批。空 token 只用于读取当前最近批次，不能用于启动。

前端每秒读取可见审阅面板的进度并消费尚未处理的结果页；结果中的ID/目标对只用于定位需要重新核对的已加载项，不直接当作删除指令。通过新增只读 `GetAIReviewCandidates(kind, ids)`（每次最多200个ID）重新读取这些ID当前仍pending的完整审阅DTO；同一面板的结果核对按事件顺序串行，后一轮在前一轮完成后读取并捕获当前对象；只在请求时的页面查询代次和候选对象仍有效时局部替换/移除，不新增其他候选，不覆盖后来重新加载的数据。changed仍pending的项刷新为新版本；后来生成的同目标pending项保留。保留当前搜索及滚动数据；关闭面板停止轮询，后台审批继续。重开读取当前任务，已消费结果按 ID 幂等处理。运行中进度通过已有task-center合并通知机制有节制地刷新（不超过每秒一次）；任务中心读取摘要，不复制全部结果。取消后呈现明确的已处理/未处理数，不能将部分完成显示为全部成功。

## 接口与兼容

新增四个流程Wails入口，以及上述只读候选核对入口：`PreviewAIReviewApproval(kind, request)`、`StartAIReviewApproval(kind, token)`、`GetAIReviewApproval(kind, token, after, limit)`、`CancelAIReviewApproval(kind, token)`；kind 只接受 video/image，SQL 标识符仍由服务内部固定。Cancel 指定预览令牌时释放预览，指定运行令牌时取消该批；空令牌由任务中心用于取消当前运行批次。Get 不自动创建任务。

两侧共享前端批次控件，视频组头调用该控件的 loaded 预览。原仅视频使用的 Wails `ApproveAITagCandidates`、`CountAITagCandidatesByFilter`、`ApproveAITagCandidatesByFilter` 在迁移完所有前端调用后移除生成导出，避免绕过冻结合同；服务层既有方法/测试保留。已检索仓库，当前只有旧审阅组件调用这三项，无手机、Jellyfin、浏览器插件或其他生产消费者。绑定重新生成，全部新增入口必须有真实调用。

## 验证

先建立单项审批、两侧候选、任务登记、任务中心及维护/退出基线。验证预览之后新增候选、改写目标/理由且不更新时间、删除媒体/标签、过期、重启失效、重复确认、并发启动、满容量、空集/一条/重复ID、部分失败、取消与维护中断。SQL双后端验证事务不把版本变化写成成功；恢复后旧令牌不能操作新库；构建中进入维护、旧构建迟到且随后恢复也不能发布令牌；excluded在确认前恢复资格仍不加入；提交后详情读取故障不影响批次成功计数；结果替换后的旧令牌稳定失效。前端验证两个范围的确认数字与请求、取消确认、旧批响应、关闭重开、局部移除与失败提示。精确diff独立审阅，修正实质问题并复验。
