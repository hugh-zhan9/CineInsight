# 应用内预览支持 mov / mkv / avi 等格式 · 需求设计文档

状态：Accepted 并已实施（2026-10-13）。
来源：用户 2026-10-13 裁决「直接播 + 自动代理」：应用内视频预览要能看 mov / mkv / avi / wmv / flv / ts 等格式。

## 裁决与规则

<a id="D-PF01"></a>
**D-PF01 · 直放按实际编码判定，不按扩展名。** 没有有效代理时（「先查代理」顺序不变，见 AI-CONTEXT §2.23），桌面预览按技术快照判定：

| 条件 | 结果 |
|---|---|
| 扩展名 .mp4 / .m4v / .mov，容器确是 ISO-BMFF（快照 `format_name` 含 `mov` 或 `mp4`；老快照无此字段不否决），首个非封面视频流 ∈ {h264, hevc, prores}，首个音频流 ∈ {aac, mp3, alac, ac3, eac3} 或无音频 | `inline`，直接下发源文件，MIME 为 `video/mp4` / `video/x-m4v` / `video/quicktime` |
| .mp4 / .m4v / .mov，快照判出其他编码 | `proxy-preparing` |
| .mp4 / .m4v / .mov，快照缺失或不新鲜 | 用播放代理同一套探测（`MediaProbeService.Refresh` + `loadPlaybackProxySnapshot`）补探一次，上限 5 秒；仍判不出就按扩展名沿用旧行为（mp4 / m4v 内嵌、mov 外部预览） |
| .webm / .ogv / .ogg | 照旧按扩展名内嵌 |
| 其余扩展名（mkv、avi、wmv、flv、ts…） | `proxy-preparing`，不为判定探测 |
| 没有代理服务（未注入） | 按扩展名沿用旧行为 |

判定表是纯函数 `decideDesktopPreview`（`services/preview_direct_play.go`），与 `inlinePreviewMIMEs` 分开：后者仍是手机端与 Jellyfin 的白名单，一个字不改（`TestInlinePreviewMIMEsUnchanged`）。手机端自己的 .mov 规则（D-PC46）也不动。正式播放（`PlayVideo`）照旧打开源文件。

<a id="D-PF02"></a>
**D-PF02 · 其余一律自动代理。** `proxy-preparing` 会话带「使用系统播放器预览」动作与原因说明。共用内嵌播放器（`InlineVideoPlayer.vue`）收到它后调 `RequestPreviewProxy(videoID)` → `PlaybackProxyService.EnqueueAuto`：算用户发起，不过空闲门；策略沿用既有的 remux（h264/hevc × aac/mp3/无音频）否则 VideoToolbox 转码。等待期间播放器框里显示「排队中（第 N 个）」/「生成中」与系统播放器按钮，就绪后沿用既有的代理跟踪重取会话、自动切到内嵌；失败显示既有的失败文案（`PLAYBACK_PROXY_CODE_LABELS`），系统播放器按钮与「生成播放代理」（手动重试）都在。

<a id="D-PF03"></a>
**D-PF03 · 直放解码失败也自动代理。** 直放源在 `<video>` 里报错（既有的「无法内嵌播放此文件」路径）时，播放器同样调 `RequestPreviewProxy`；两个按钮照留。已经在经代理播放时不再生成。

<a id="D-PF04"></a>
**D-PF04 · 自动代理跟着打开的预览走。** 服务里显式区分自动项（`autoVideoID`）：
- 一次最多一项。`EnqueueAuto(B)` 先取消上一项自动代理；同一视频已是自动项时不重复入队；该视频已被手动入口排进去时只跟着它走，不另记一项、也不标成自动项。
- `CancelAuto(videoID)`：排队中就当场摘掉并记 `cancelled`；处理中就只取消这一项的 ctx（每项一个可单独取消的 ctx，整轮照跑、不算整轮取消）。它不是当前自动项时什么都不做。
- 播放器在换片（`videoId` 变化）与卸载（宿主关闭预览、收起播放器、抽屉里导航到别的条目）时调 `CancelPreviewProxy`；等本次入队请求回来再发，避免取消先于入队到达后端。
- 做好的代理照常保留，交给 LRU。手动入口（详情抽屉按钮、行菜单、批量、按筛选）从不被取消；手动入口再点一次自动项，就把它转成手动项。

## 宿主

详情抽屉与整页详情都经共用播放器拿到上述行为。整页详情在播放器框里已显示代理状态时（`showsProxyState`），框下不再重复同一句。待播队列播放器不用预览会话（它有自己的 `/preview/queue/{token}` 与白名单口径），不在本次范围。字幕工作台与版本对比只读会话、不触发自动代理：它们对 `proxy-preparing` 显示原因（版本对比另提示去详情抽屉生成代理）。

## 实施中补的决定（规则未覆盖）

- **入队由播放器发起，而不是 `GetPreviewSession` 本身。** 会话还被字幕工作台、版本对比（一次读两个）与抽屉嵌套条目读取；在读会话时入队会让这些非预览场景排任务，且版本对比的两次读取会互相取消，违背「一次一项、跟着预览走」。
- **这次预览里用户刚删掉代理，不当场重建。** 删除后会话回到 `proxy-preparing`，若照常自动入队，删除按钮在预览中形同虚设。换片或重新打开后照常自动。
- **不插队。** 自动项与手动项同一条 FIFO 队列；批量任务在跑时预览显示「排队中（第 N 个）」。
- **进度只到排位与「生成中」。** 代理服务没有逐项百分比（不解析 ffmpeg 进度），本次不加。
- **失败后重开同一预览会再试一次。** 规则要求不能直放就自动入队，没有「上次失败就不再试」的例外。

## 验证

- Go：判定表逐行（含 mov+h264 直放、mov+mpeg4 → 转码代理、mkv+h264 → remux、avi+xvid → 转码、缺快照补探一次、探测失败按扩展名回退、补探带期限）；自动入队与取消（一次一项、排队中与处理中的取消、手动项不受影响、手动接管、做完保留、整轮中途做完即释放）；手机端白名单不受影响。
- 前端：等代理状态、排位与进度、就绪自动切内嵌（受控与不受控）、失败文案与按钮、解码失败自动代理、换片与关闭取消、手动不取消、删除后不重建；抽屉与整页详情各一条宿主级用例。
- 真机（本机 ffmpeg 9.0.1）：`TestPreviewFormatsEndToEndWithRealFFmpeg` 用 `testsrc` 合成 5 秒 1280×720 样片走完整链路；`TestPreviewProxyCancelStopsRealTranscode` 在真实转码写临时文件时取消，确认无临时文件残留、无失败记录。
