# 析微影策片库 2.0 设计文档

## 二、需求信息

### 2.1 需求背景

- 背景：现有片库具备可靠扫描、检索、字幕、标签、预览和清理能力，但缺少主片库观看闭环与视觉浏览。
- 需求目的：交付观看状态、缩略图、智能视图、筛选随机和统一清理审阅。
- 目标用户/使用方：本地单用户桌面应用使用者。
- 需求链接：当前用户会话批准建议 1、2、3、4、6。
- 关联原始材料：`AI-CONTEXT.md`、同目录 `设计提案.md`。

### 2.2 需求范围

- 本期范围：收藏/已看/进度/最近播放；列表/网格与缩略图；内置和保存视图；筛选内随机；精确重复与同源候选统一审阅。
- 非目标：系统播放器精确进度、语义 embedding、自动删除、标签传播、数据库或框架替换。
- 决策边界：只新增数据和接口；旧调用保持兼容。
- 依赖方：PostgreSQL、GORM、Wails、Vue、FFmpeg、现有 AI 同源关系和回收站。
- 约束条件：本地优先；缩略图失败不得阻塞主列表；清理必须人工确认。
- 触发的辅助 skills：architecture-designer、sql-style、go-style。

接受标准：

- AC-001：用户可在主列表收藏/取消收藏、标记已看/未看，并在内嵌预览后从保存位置继续；字幕命中跳转优先。
- AC-002：用户可切换列表/网格，当前可见视频按需显示缩略图；缓存过期或源文件变化后可重建，失败显示占位。
- AC-003：用户可使用内置智能视图，并创建、应用、删除带名称的保存视图；重启后仍存在。
- AC-004：随机播放只从当前过滤边界和模式中选择，排除失效与近期 ID，无候选时不回退全库。
- AC-005：清理中心同时展示精确重复和已检测同源候选、保留建议和空间信息，删除仍进入现有回收站。
- AC-006：既有列表分页、字幕搜索、播放统计、AI 审批、短视频和删除恢复测试不回归。

### 2.3 可行性分析

- 业务可行性：全部能力建立在现有视频、预览、筛选、同源和删除入口上。
- 技术可行性：GORM AutoMigrate 支持增量列/表，Wails 可新增结构体接口，资源 Handler 可增加缩略图路由。
- 替代方案：详见设计提案；拒绝数据库存图、自动删除和筛选失败后全库回退。
- 关键风险：缩略图生成负载、网格 DOM 规模、进度高频写入、智能视图查询性能。

## 三、概要设计

### 3.1 方案总述

- 设计目标：以最小增量形成“发现—预览—继续—整理—清理”闭环。
- 总体思路：用户状态持久化、派生资产文件缓存、共享过滤器、增量 DTO。
- 核心模块：`VideoService`、`ThumbnailService`、`CleanupService`、Wails App、Vue 主列表/行/预览抽屉。
- 主要难点：保持旧查询和分页兼容、控制进度写入频率、清理同源候选不越过人工确认。
- 技术指标：不制定虚构 SLO；默认列表继续使用现有虚拟化，缩略图失败独立降级。

### 3.2 整体架构设计

- 系统边界：仍为单进程 Wails 桌面应用与本地 PostgreSQL；FFmpeg 只生成派生图片。
- 数据流转：Vue 操作 → Wails App → Go service → PostgreSQL；图片请求 → asset handler → thumbnail cache/FFmpeg。
- 所有权：数据库保存用户意图；缓存目录保存可重建输出；原视频始终是媒体真源。

### 3.3 核心流程设计

| 流程 | 触发条件 | 参与模块 | 主流程 | 异常/补偿 | 输出 |
|---|---|---|---|---|---|
| 观看进度 | 内嵌播放 timeupdate/pause/end | PreviewDrawer/App/VideoService | 节流上报、夹紧、持久化 | 写失败留在当前 UI，不改变播放统计 | 继续观看位置/已看状态 |
| 缩略图 | 浏览器请求图片 | asset handler/ThumbnailService/FFmpeg | 校验缓存、生成临时文件、原子替换 | 返回 404，前端占位 | JPEG |
| 保存视图 | 用户保存当前筛选 | Vue/App/VideoService | 校验名称、持久化、刷新选择器 | 同名拒绝 | 保存视图 |
| 筛选随机 | 点击随机播放 | Vue/App/VideoService | 应用统一过滤、排除近期、按模式加权 | 无候选返回领域失败 | 播放结果与理由 |
| 统一清理 | 启动分析 | CleanupService/AI relation/回收站 | 精确重复分析 + 读取同源关系 | 单条失效跳过 | 人工审阅候选 |

### 3.4 功能模块

| 模块 | 职责 | 关键功能 | 依赖 |
|---|---|---|---|
| Library state | 用户观看意图 | 收藏、已看、进度 | videos |
| Library views | 可复用筛选 | 内置视图、保存视图 | saved_library_views |
| Thumbnail | 视觉资产 | 缓存、失效、生成 | FFmpeg、asset handler |
| Filtered random | 当前范围选择 | 过滤、模式、近期排除 | shared library filter |
| Cleanup review | 空间治理 | 精确重复、同源建议 | cleanup、same-source、trash |

### 3.5 新增/调整功能说明

- 主列表增加智能视图、保存视图、随机模式和布局切换。
- 行卡增加缩略图、收藏、已看和进度信息。
- 预览抽屉增加恢复位置和进度上报。
- 清理弹窗增加同源候选分区与空间信息。

### 3.6 专项设计检查

| 辅助 skill | 触发原因 | 检查内容 | 设计结论 |
|---|---|---|---|
| architecture-designer | 跨资源/数据库/UI | 所有权、失败隔离、回滚 | 派生缓存与用户数据分离 |
| sql-style | Schema 与过滤查询 | 默认值、索引、幂等 | 增量迁移，索引只绑定实际视图 |
| go-style | Go 接口和并发 | 局部风格、锁、错误、测试 | 同视频缩略图串行，编辑文件 gofmt |

## 四、详细设计

### 4.1 观看状态与智能视图详细设计

#### 4.1.1 需求内容

- 入口：视频行、预览抽屉、智能/保存视图工具栏。
- 调用方：主前端。
- 前置条件：视频记录未软删除。
- 输出结果：更新后视频或保存视图记录。

#### 4.1.2 方案设计

- D-001（AC-001，behavior/data contract）：`videos` 增加 `is_favorite`、`is_watched`、`watch_position_seconds`、`watch_progress_updated_at`、`watched_at`；显式未看会清空 `watched_at`，不清空位置。
- D-002（AC-001，behavior contract）：进度只由内嵌播放器上报；结束自动标记已看；字幕命中 seek 优先于恢复位置；外部播放器保持粗粒度 `last_played_at`。
- D-003（AC-003，data/interface contract）：`saved_library_views` 保存名称、搜索模式、关键词、内置视图、标签 JSON 和数值筛选；名称在活跃记录中唯一。
- 状态流转：未看可带进度 → 已看；已看可手动回到未看；收藏独立。
- 幂等：重复设置同一布尔值或相同进度只产生同一终态。
- 异常：非法视频、非有限进度、负进度返回错误；超过时长夹紧。

#### 4.1.3 流程步骤

1. 用户操作或播放器节流事件调用新增 Wails 方法。
2. 服务校验视频和输入并执行窄字段更新。
3. 前端合并返回视频，不全量重载；视图不再匹配时重载当前视图。

#### 4.1.4 边界条件

| 场景 | 处理方式 | 用户感知 | 监控/告警 |
|---|---|---|---|
| 老记录 | 默认 false/0/null | 视为未看且未收藏 | migration error |
| 重复点击 | 幂等更新 | 状态稳定 | 无 |
| 进度写失败 | 保留播放器状态并记录前端错误 | 下次可能从旧位置继续 | 现有日志 |
| 保存视图同名 | 拒绝 | 明确错误 | 现有日志 |

#### 4.1.5 不变行为

| 行为/表面 | 保持不变的原因 | 验证方式 |
|---|---|---|
| 正式播放计数与随机计数 | 独立统计契约 | 既有 playback tests |
| 现有分页排序 | 大库稳定性 | 既有 pagination tests |
| 短视频喜欢/收藏权重 | 不改变推荐语义 | short-feed tests |

### 4.2 缩略图与视觉布局详细设计

#### 4.2.1 需求内容

- 入口：列表/网格可见项图片请求。
- 调用方：WebView asset loader。
- 前置条件：源视频可读且 FFmpeg 可用。
- 输出结果：JPEG 或占位状态。

#### 4.2.2 方案设计

- D-004（AC-002，operations contract）：缓存位于 `~/.video-master/thumbnails/{videoID}.jpg`；缓存修改时间不早于源视频才有效。
- D-005（AC-002，interface contract）：新增 GET/HEAD `/preview/thumbnail/{videoID}`；失败返回 404/5xx，前端使用 CSS 占位，不影响其他接口。
- 同视频生成由进程内锁串行；写入临时文件后重命名；生成时间点取已知时长约 10%，限定在 1–30 秒。

#### 4.2.3 流程步骤

1. Handler 解析 ID 并调用缩略图服务。
2. 服务校验源文件与缓存；必要时运行一次 FFmpeg。
3. Handler 通过 `ServeContent` 返回 JPEG。

#### 4.2.4 边界条件

| 场景 | 处理方式 | 用户感知 | 监控/告警 |
|---|---|---|---|
| FFmpeg 缺失 | 返回不可用 | 占位图 | 日志一次/请求 |
| 源文件变化 | 缓存失效并重建 | 短暂占位 | 生成日志 |
| 并发请求 | 同 ID 串行 | 最终同一图片 | 无 |
| 网格大库 | 按分页已加载项渲染，默认列表仍虚拟化 | 可切回列表 | 无 |

#### 4.2.5 不变行为

| 行为/表面 | 保持不变的原因 | 验证方式 |
|---|---|---|
| 预览媒体 Range/ServeContent | 视频 seek 依赖 | preview tests、subtitle seek test |
| 默认列表虚拟化 | 大库性能 | virtual-list tests |

### 4.3 筛选内随机播放详细设计

#### 4.3.1 需求内容

- 入口：随机模式选择与随机播放按钮。
- 调用方：主前端。
- 前置条件：当前过滤范围至少一个可播放视频。
- 输出结果：播放尝试及人类可读选择理由。

#### 4.3.2 方案设计

- D-006（AC-004，behavior/interface contract）：新增请求式随机接口，过滤关键词、搜索模式、标签、体积、分辨率、智能视图、模式和近期排除 ID；现有无参方法保留。
- 模式：`balanced` 使用既有分数；`unwatched` 限制未看；`favorites` 限制收藏。所有模式排除 `is_stale=true`。
- 无候选返回失败结果，不放宽过滤、不重试全库。

#### 4.3.3 流程步骤

1. 前端组装当前过滤和最近成功随机 ID。
2. 服务复用统一过滤器查询最少选择字段并加权选择。
3. 继续调用既有正式播放分发和统计更新。

#### 4.3.4 边界条件

| 场景 | 处理方式 | 用户感知 | 监控/告警 |
|---|---|---|---|
| 排除后为空 | 领域失败 | 当前视图没有候选 | 无 |
| 近期 ID 过多 | 服务端去重并限制数量 | 无 | 无 |
| 选中文件失效 | 沿用既有 reconcile | 文件级错误 | 现有日志 |

#### 4.3.5 不变行为

| 行为/表面 | 保持不变的原因 | 验证方式 |
|---|---|---|
| balanced 公式 | 既有产品算法 | ALGORITHM tests |
| dispatch 成功后才计数 | 可靠性契约 | playback tests |

### 4.4 统一清理审阅详细设计

#### 4.4.1 需求内容

- 入口：清理候选弹窗。
- 调用方：主前端。
- 前置条件：清理分析完成；同源关系可选存在。
- 输出结果：精确重复、短/低清与同源候选统一展示。

#### 4.4.2 方案设计

- D-007（AC-005，behavior contract）：`CleanupAnalysis` 增量返回同源候选、建议保留 ID、预计可释放字节；同源关系只取 `detected` 且双方活跃。
- D-008（AC-005，safety contract）：任何候选均不预先删除；同源候选默认不勾选，删除继续使用现有回收站；否认复用既有 `RejectSameSourceRelation`。
- 精确重复配对从同源分区去重；保留建议按分辨率、大小、标签数量、ID 稳定排序。

#### 4.4.3 流程步骤

1. 现有清理扫描完成精确重复与质量候选。
2. 查询已检测同源关系并过滤活跃视频、重复配对。
3. 前端分区展示并允许预览、否认、选择删除。

#### 4.4.4 边界条件

| 场景 | 处理方式 | 用户感知 | 监控/告警 |
|---|---|---|---|
| 一方已删除 | 跳过关系 | 不显示失效候选 | 无 |
| 关系已否认 | 查询排除 | 不再次显示 | 无 |
| 删除部分失败 | 沿用批量删除结果 | 显示成功/失败 | 现有日志 |

#### 4.4.5 不变行为

| 行为/表面 | 保持不变的原因 | 验证方式 |
|---|---|---|
| AI 同源检测与否认规则 | 已有指纹安全边界 | ai same-source tests |
| 回收站不覆盖与可恢复语义 | 文件安全边界 | trash tests |

## 五、存储类设计

### 5.1 库表设计

#### 5.1.1 数据库模型图

`videos 1 --- 0..n saved_library_views` 无直接外键；保存视图引用标签 ID JSON，加载时忽略已不存在标签。

#### 5.1.2 表结构

| 表名 | 用途 | 主键 | 关键索引 | 备注 |
|---|---|---|---|---|
| videos | 增加片库状态 | id | favorite/watched/progress/last_played partial indexes | 原表增量 |
| saved_library_views | 用户保存筛选 | id | active name unique | 软删除 |

`videos` 新字段：

| 字段 | 类型 | 必填 | 默认值 | 含义 |
|---|---|---|---|---|
| is_favorite | boolean | 是 | false | 主片库收藏 |
| is_watched | boolean | 是 | false | 显式/播放完成已看 |
| watch_position_seconds | double precision | 是 | 0 | 内嵌播放位置 |
| watch_progress_updated_at | timestamptz | 否 | null | 进度更新时间 |
| watched_at | timestamptz | 否 | null | 最近标记已看时间 |

`saved_library_views` 保存 `name/search_mode/keyword/smart_view/tag_ids_json/min_size/max_size/min_height/max_height` 和时间戳。

### 5.2 数据迁移/初始化

- D-009（AC-006，compatibility contract）：使用现有 AutoMigrate 扩展；新列非空字段有默认值；不回填历史观看状态。
- 重复启动安全；索引使用 `IF NOT EXISTS`。
- 回滚采用前向兼容：旧二进制忽略新列/表；不执行破坏性降级 DDL。

### 5.3 缓存设计

| 场景 | Key | Value | 过期 | 失效/刷新 |
|---|---|---|---|---|
| 缩略图 | video ID 文件名 | JPEG | 无固定 TTL | cache mtime < source mtime 时重建 |

## 八、系统发布

### 8.4 回滚方案

- 应用回滚：旧代码忽略新增列/表。
- 数据回滚：不删除新增数据，等待前向修复。
- 缓存回滚：可删除 `~/.video-master/thumbnails`，下次重建。

## 九、系统监控与维护

### 9.1 监控与告警

沿用应用日志记录迁移错误、缩略图生成错误、观看状态写入错误和清理分析错误；不记录媒体内容。

### 9.2 性能与容量

- 默认列表继续虚拟化；网格只渲染已分页数据。
- 进度前端至少间隔 10 秒上报并在暂停/关闭时补一次。
- 智能视图索引与实际谓词对应；不声称未测量的性能提升。

### 9.3 可靠性与兜底

缩略图是独立降级面；数据库状态写失败不改变原视频；随机无候选失败关闭；清理不自动执行。
