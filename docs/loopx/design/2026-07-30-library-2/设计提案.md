# 用增量片库状态与派生媒体资产完成“片库 2.0”

Author(s): Codex / CineInsight
Last updated: 2026-07-30
Status: Accepted
Discussion: 当前用户会话
Source requirements: 用户批准上一轮建议中的 1、2、3、4、6
Support lenses: architecture-designer, sql-style, go-style

## Abstract / 摘要

本提案在现有 Wails、Go、PostgreSQL、Vue 和 FFmpeg 边界内，增量增加观看状态、收藏、继续观看、视觉缩略图、智能视图、保存筛选、筛选内随机播放，以及同源候选与清理审阅的统一展示。现有分页、正式播放统计、字幕搜索、AI 审批和可恢复删除语义保持不变。

## Background / 背景与动机

当前首页是文本列表，视频只记录播放次数和最后播放时间；精确进度与收藏仅局部存在于短视频 Feed。随机播放忽略首页正在使用的搜索和筛选；清理审阅与 AI 同源审阅也分散在两个入口。项目已有 FFmpeg、预览资源路由、稳定查询、回收站和同源关系数据，具备以较小增量闭合日常使用链路的基础。

## Goals And Non-Goals / 目标与非目标

目标：

- 让主片库支持收藏、已看、未看、继续观看和最近播放。
- 为可见视频按需生成可失效的本地缩略图，并提供列表/网格视图。
- 提供内置智能视图并持久化用户命名的筛选视图。
- 让随机播放继承当前关键词、标签、体积、分辨率和智能视图，并避免本次会话近期重复。
- 在清理中心同时展示精确重复和已确认的同源候选，给出保留建议与空间信息，但不自动删除。

非目标：

- 不接管系统播放器，系统播放器不回传精确观看进度。
- 不建立通用 embedding、语义推荐或新 AI 推理链路。
- 不自动删除重复或同源视频，不传播标签，不改变 AI 否认语义。
- 不替换 PostgreSQL、Wails 或现有游标分页接口。

## Proposal / 设计方案

1. 在 `videos` 上增加收藏、已看、观看位置与观看更新时间。旧记录使用安全默认值；内嵌预览定期保存进度，播放结束自动标记已看，用户可显式切换收藏和已看。
2. 增加保存视图表，保存名称、搜索模式、关键词、智能视图、标签和数值筛选。内置视图不写库；用户视图可创建和删除。
3. 增加统一的 `LibraryFilter` 过滤器，供列表智能视图与随机播放复用。现有查询方法继续保留并委托到默认过滤语义。
4. 缩略图由 `/preview/thumbnail/{videoID}` 按需生成到 `~/.video-master/thumbnails`。缓存早于源文件或生成失败时重新生成；临时文件原子替换，失败返回占位而不影响列表。
5. 随机播放增加请求对象，明确过滤条件、模式与近期排除 ID。现有无参随机方法保持原行为；新入口排除失效视频并返回选择理由。
6. 清理分析读取现有 `detected` 同源关系并排除已归入精确重复组的相同配对，返回建议保留项和预计可释放字节。前端仍调用现有回收站删除链路。

## Boundary Scenarios / 边界场景

- 老数据：收藏/已看为 false，位置为 0，不需要破坏性回填。
- 重复进度上报：同一位置更新是幂等的；负数、NaN 和超过时长的位置被拒绝或夹紧。
- 字幕命中预览：显式字幕跳转优先于继续观看位置。
- 外部预览或正式播放：继续只维护既有播放统计，不伪造精确进度。
- FFmpeg 缺失或源文件失效：显示占位图，不阻塞列表和其他操作。
- 同名保存视图：拒绝并返回明确错误；删除不存在视图返回未找到错误。
- 当前筛选无随机候选：返回领域失败结果，不回退到全库。
- 同源候选：只读取已检测关系；用户在清理中心否认后沿用现有指纹阻断规则。
- 并发缩略图请求：同一视频串行生成，缓存写入使用临时文件和重命名。
- 回滚：删除新增代码后旧行为仍可读取新增列；缩略图目录可安全删除并重建。

## Rationale / 理由与取舍

| Alternative | Why Not |
|---|---|
| 新建独立观看状态聚合表 | 当前是一对一状态，直接字段减少连接和接口复杂度；短视频交互保持独立，避免改变其推荐权重语义 |
| 将缩略图存入 PostgreSQL | 增加数据库体积和备份负担，且缩略图可从源文件重建 |
| 网格模式保持完整 DOM 虚拟化 | 首版复杂度高；默认列表继续虚拟化，网格按已分页数据渲染，不改变默认大库路径 |
| 随机无候选时回退全库 | 会违背用户当前筛选边界 |
| 同源关系自动选择并删除较差版本 | 同源不等于冗余，自动删除风险不可接受 |

## Compatibility / 兼容性

方案纯增量。现有 Wails 方法、JSON 字段、播放计数公式、游标排序、字幕搜索、AI 审批、短视频交互和删除恢复接口不删除、不改名。新增数据库字段均有默认值，新增表不要求数据回填。

## Operational And Security Impact / 运行与安全影响

缩略图会增加本地磁盘占用和 FFmpeg 子进程负载；仅由可见资源请求触发，失败不重试循环。观看状态和保存视图不含新的外发数据。清理仍使用现有人工确认和回收站边界。

## Implementation And Transition / 实现与过渡

先落数据与统一过滤契约，再接观看 UI 和智能视图；缩略图与网格依赖现有资源路由；随机播放复用统一过滤；清理整合只扩展分析 DTO。所有切片完成后统一生成 Wails bindings 并运行完整验证。

无阻塞问题。网格的全量虚拟化、跨设备同步和系统播放器进度接入留待后续独立需求。
