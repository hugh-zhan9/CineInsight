## 真实客户端与文件证据

当前用户实例仅只读查询 `app/version`、`app/webapiVersion` 和 `app/buildInfo`，确认 v5.2.3 / API 2.15.1 / libtorrent 2.0.13.0。没有列举或修改用户任务，也没有写其配置。

原生测试另启独立的 seed/leech profile、随机 loopback WebUI/peer 端口与合成 torrent，关闭 DHT、LSD、PeX、UPnP，不配置 tracker 或 webseed。端口/PID与版本核验通过后才写测试任务；清理只终止本次创建的进程并等待回收，不向未知归属的 WebUI 发 shutdown。

- 元数据能力：原子 `stopped=false + MetadataReceived` 完成后为 `stoppedDL`，影片 payload 为 0，延后观察仍为 0；反例 `stopped=true` 后再 start 会下载 payload，因此生产禁止该组合。生产能力门固定上述 app/API/libtorrent profile，其他版本明确报告未验证。
- 布局能力：合成 v1、纯 v2 与 hybrid 覆盖实际 hash、路径与文件 index；纯 v2 的客户端布局由协调器按已验证规则转换，hybrid 以原始 info 字节计算双 hash，比较 v1 共同 name 根之外的相对路径，输出仍保持完整路径。元数据与布局原生测试记录为 38.660 秒，相关生产路径未在后续改变。
- 最终真实下载链：`TestBTIsolatedSelectiveDownloadToLibrary` 从解析、选择、提交、优先级回读、下载、轮询到真实 `BTImporter/VideoService` 原位入库。所选视频 5088 字节，文件 SHA256 为 `abdcfd14ab53861b0e497c143a8d91068696083e5eec30e1eaa36d31d4e6884a`；三个文件 priority 为 `1/0/0`，未选文件不要求完成；片库只有一条相应 Video，导入前后文件路径、内容 hash 均不变。
- 同一真实链中显式 stop 回读 `stoppedUP`、start 回读 `stalledUP`；停止本地协调服务后外部任务仍 `stalledUP`。自有进程和 profile 的清理断言通过。隔离单轮 10.610 秒，随后主工作区同状态联合回归 41.175 秒通过。

真实链曾暴露 add 后的 `checkingResumeData` 以及 start 成功响应先于状态变化。修复仅在原已发送且成功的命令内有界只读核实，不重发外部写；超时或维护取消仍保留未决历史。测试未放宽为“最终下载成功即可”。

## 复跑命令

从仓库根目录执行，所有本机重验证串行；Go 必须使用用户级受限入口。先准备一次性 PostgreSQL 数据库并通过环境变量注入测试 DSN，勿指向用户片库或打印凭据。

```sh
/Users/zhangyukun/.local/bin/agent-go test ./... -count=1 -timeout 1500s
/Users/zhangyukun/.local/bin/agent-go test ./services ./services/btclient ./services/btmanifest ./database/migrator -run TestBT -count=1 -timeout 1500s
```

第二条在设置 `CINEINSIGHT_TEST_PG_DSN` 后覆盖 PG 腿；未设置时为 SQLite。最终主 PG 聚焦使用的精确筛选为：

```sh
/Users/zhangyukun/.local/bin/agent-go test ./services ./database/migrator -run 'TestBTCredentialScope|TestBTRestore|TestBTTaskSummary|TestBTDuplicate|TestMigrateBTStringFileIdentityRoundTrip|TestBTFile.*Upgrade|TestBTTaskWriteSafetyColumnUpgrade' -count=1 -timeout 1500s
```

该命令需先注入自有一次性 PG 的 `CINEINSIGHT_TEST_PG_DSN`；不能将未设变量的运行标记为 PG 证据。真实 qB 检查是显式 opt-in，会启停测试自有进程，须安装受测 qBittorrent 和 FFmpeg；不要并行启动：

```sh
CINEINSIGHT_BT_QB_PROBE=1 /Users/zhangyukun/.local/bin/agent-go test ./services -run '^TestBTIsolatedQBMetadataCapability$' -count=1 -timeout 240s
CINEINSIGHT_BT_QB_PROBE=1 /Users/zhangyukun/.local/bin/agent-go test ./services -run 'TestBTTask|^TestBTIsolatedSelectiveDownloadToLibrary$' -count=1 -timeout 240s
```

前端从 `frontend/` 执行，先限并发组件测试，再按 `package.json` 中 `test` 脚本的顺序运行其余静态守卫。以下读取现有脚本，避免复制后遗漏新守卫：

```sh
nice -n 10 npm run test:components -- --maxWorkers=1 --no-file-parallelism
node --input-type=module -e 'import fs from "node:fs"; import {execSync} from "node:child_process"; const p=JSON.parse(fs.readFileSync("package.json","utf8")); for(const cmd of p.scripts.test.split(" && ").slice(1)) execSync(cmd,{stdio:"inherit"});'
nice -n 10 npm run build
```
