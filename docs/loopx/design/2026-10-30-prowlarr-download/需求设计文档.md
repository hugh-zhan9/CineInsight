## D-PT-04：连接与凭据（Interface / Security Contract）

连接限定本机 loopback HTTP(S)，默认建议 Prowlarr `http://127.0.0.1:9696`、qBittorrent `http://127.0.0.1:8081`；只读调查已确认后者版本5.2.3、API2.15.1可访问，不能假定别的安装免认证。拒绝userinfo、fragment、任意外部host及DNS解析到非loopback；支持配置Prowlarr URL base。HTTP客户端不继承系统代理，不自动追随跨源重定向。qBittorrent WebUI为单一全局账号，用户名与密码更新属于同实例认证变更，允许在受管理任务存在时经Drain/CAS/Invalidate/Resume恢复连接，不更换任务connection_id；端点或下载根变化才需要实例换代。单连接配置版本单调增加；修改端点后使旧会话、搜索令牌与在途结果失效，有活跃任务时拒绝覆盖连接，先明确处理旧连接任务。 abandoned表示用户已明确停止本应用继续管理，只保留历史/路径保护；该操作仅需本地父连接身份/任务CAS/维护守卫，不依赖旧服务在线、旧凭据可用或enabled=true；它与需要enabled的重新活跃任务准入是不同角色，因此不计入阻止端点或根换代的活跃集合；退休后旧task仍关联旧connection，不解除保护、不发远端写、不以新连接接管，UI仅查看。未决active任务如要退休连接，须先明确放弃管理；提示旧请求仍可能生效且qBittorrent不会被自动停止。abandoned重新确认、cancelled纯草稿重新准备会重新成为活跃任务，必须在同一事务先ClaimBTTaskEpoch并核实父连接仍local/同revision，再CAS任务，防跨进程穿越连接退休。

macOS使用系统Keychain保存Prowlarr API key与qBittorrent密码；数据库仅保存引用、端点、用户名及配置revision。UI回读只有`configured`，空密码表示保持，清除须显式`clear`。Keychain不可用则配置失败，不退回明文。站点Cookie/API key由Prowlarr持有。qBittorrent SID仅会话内存，不落库。设置接线独立于通用UpdateSettings，避免表单覆盖凭据。

凭据与数据库采用版本化引用：每次保存生成新随机secret_ref，在Keychain写不可变凭据bundle后，事务CAS切换DB引用及配置revision；CAS失败清理新项，旧引用仍有效。keep字段从当前引用组合，clear字段从新bundle移除；全部清除先CAS断引用，再删除旧秘密。清理失败只留下不可达孤儿，不能把有效配置回滚到已删除凭据。崩溃后的孤儿清理与配置保存共用串行边界，保护本次已写但尚未CAS挂接的新ref，只删除不被任何配置或当前保存操作引用的本应用命名空间项。实现使用Security.framework，不把密码作为security命令行参数。配置操作串行关闭本地命令准入并等待/取消在途请求，令旧generation失效后换客户端；已发远端命令按不确定状态对账。Configure在尝试Drain之前注册恢复旧配置生命周期的收尾：Drain超时且配置未变也须移除本次配置暂停，避免保存失败把协调器永久关闭。配置暂停与维护暂停独立持有准入条件，任一仍有效或已Stop都不得开放；App Resume只解除维护暂停，不能反向重开仍在秘密保存/DB CAS中的Configure；配置结束移除自己的暂停后按当前全部条件重算准入，不因旧generation而永久关闭，也不能盖过仍有效的维护/停止状态。

跨实例协调补充（实施审阅发现后的技术修订）：Keychain service与OS锁均按“当前物理数据库公开身份”的SHA256 scope隔离。SQLite身份取PRAGMA database_list的规范真实文件路径；PostgreSQL取同一固定句柄的服务器地址/端口、current_database与current_schema，不含数据库密码。无法确定生产身份则拒绝凭据操作；测试注入明确scope。多个进程指向同一库时共享scope与本机文件锁；不同库不枚举或删除彼此的秘密。迁移到不同物理库后的旧ref在新scope不可读，按既定“恢复/切换后重新连接”处理，不搜索其他scope或明文兜底。数据库身份在整个快照→秘密发布→CAS→清理期间必须稳定：短operation lease取得旧句柄/维护代际，Drain在lease外执行，随后重入lease复核代际与句柄，再在该lease内完成发布/事务/清理；Resume在lease外重读。

这是外部Keychain无法参与数据库CAS所需的本机协调，不是数据库应用锁：复用仓库已有O_NOFOLLOW+flock方法，锁文件按scope命名、0600、不得unlink，进程退出自动释放；Save/Load/Cleanup共享锁序。锁忙立即返回可重试的credentials_busy，不固定延时猜测发布完成。GC只枚举当前scope，并在同一锁内查询当前DB引用；配置服务按所持DB句柄取得对应scope的manager，禁止跨切库继续用旧scope manager。多manager发布/清理交错与跨scope互不删除须作为回归。

这是当前本机macOS需求的设计；其他平台可阅读已有任务，但启用新连接须提供对应系统凭据存储实现，不把明文文件当跨平台兜底。数据库备份不含Keychain秘密或原始torrent；恢复后显示需要重新连接。连接instance_id不因改显示名变化，替换服务端不能继承旧任务归属。

Prowlarr响应的downloadUrl仅后端短期保存：只允许已配置同源及已识别的`/{indexerId}/download`或`/api/v1/indexer/{id}/download`路径，indexer匹配搜索结果；拒绝任意前端提交URL。对站点redirect/magnet响应明确分流，密钥不随重定向外发。取种由Prowlarr代理完成；代理若要求跳到外站，提示将该站改为代理取种，不自行携带站点Cookie访问外站。

日志和错误只记任务ID、站点名、操作阶段、结构化原因；不记录完整下载链接、SID、Authorization、原始上游错误体、torrent announce/passkey。后台超时不自动重放写请求。读取超时按网络状态提示，后续正常轮询可重新获取。

## D-PT-05：搜索、预览、选择与提交（Interface / Workflow Contract）

入口在想看片目详情增加“找资源”，并在下载页提供独立搜索；BT下载入口不依赖浏览器桥接开关。2026-10-31 用户要求默认浏览最新内容：首次打开可用的资源面板且没有预填关键词时发起空关键词查询；有预填关键词仍由用户确认搜索。结果不自动下载。前端按请求代际丢弃旧查询。

### 对外依赖的确切用途

| 服务/操作 | 使用方式与判据 |
| --- | --- |
| Prowlarr GET `/api/v1/indexer` | 列出启用的Torrent站点；不把配置响应原样返回UI，不请求账户密码回显 |
| GET `/api/v1/search` | `query/type=search/indexerIds/limit/offset`；按站点请求，最多2个并行，30秒单请求/90秒总期限，未执行完站点标timeout或not_queried；结果最多500条后显示截断 |
| 搜索返回的取种代理URL | 后端GET，30秒/16MiB上限；不调用POST search，因为它会发送给Prowlarr下载器 |
| qBittorrent `app/version`、`app/webapiVersion`、`auth/login` | 验证协议能力及会话；401/403区分认证失败，不删除任务 |
| `torrents/info`、`torrents/files`、`torrents/properties` | 按明确hash对账，读取真实文件index、相对路径、大小、priority、progress及状态 |
| `torrents/add` | 单种子multipart，普通torrent使用`stopped=true`；磁力元数据任务仅在已验证构建上使用`stopped=false + stopCondition=MetadataReceived`原子添加。两者均`autoTMM=false, contentLayout=Original, savepath=<任务子目录>, useDownloadPath=false`，携带专用category与随机任务tag；不传rename，不改变全局偏好 |
| `torrents/filePrio` | 使用返回的文件`index`，先全置0，再将明确选择置1，回读验证全部选择；不能用筛选后的数组序号 |
| `torrents/start`、`stop` | 仅本应用拥有且身份复核成功的hash；响应成功仍回读确认状态 |

qBittorrent 5.2.3源码确认stopped/contentLayout/useDownloadPath参数；旧版兼容不是本次默认承诺。连接测试须拒绝能力不足的版本，不静默使用不同语义的paused/start别名。Prowlarr版本未安装，实施须以目标版本再核验；资料链接在文末。

搜索成功但零结果与请求失败分开。上游SearchController可能吞异常并返回空列表，因此空列表标记`coverage=unknown`，文案“未返回结果”，不能保证站点确实无资源；非空也不承诺穷尽站点全部结果。每站HTTP失败显示独立原因，不丢其他站结果。

### 文件清单准备

搜索结果返回随机result_token（10分钟、最多500个，绑定配置revision）；UI看不到downloadUrl。点击预览生成持久草稿draft_id及revision，重复调用相同有效令牌复用同一草稿。临时torrent存数据目录`bt-previews`（目录0700、文件0600、原子写入、未提交草稿从本次准备UpdatedAt算24小时过期，取消后重新准备刷新该时点而不改原CreatedAt；已提交但结果不确定时保留，提交结果已确定或用户明确放弃后删除），不进入媒体扫描与备份。缓存文件在bt-previews/<公开物理DB scope>/<task UUID>/<digest>.torrent内寻址，内容不可变；DB scope复用D04的BTCredentialScope，只读公开身份、不访问Keychain秘密，不跨scope枚举/清理；不同库复制来的同task UUID也隔离。元数据由magnet变为导出torrent时先落盘新版本，再以任务CAS切换ManifestDigest，成功后才清旧版本。崩溃前后的旧DB指针始终指向完整旧文件，新未挂接文件由有界GC清理；取消/放弃按明确task身份清理，不以任意文件名前缀扩大删除范围。GC不能删除当前任务指向或仍需用于未决原操作的版本。同scope/task的缓存发布、依赖指针CAS、取消/放弃后的清理及GC共用跨实例OS文件锁；复用BTFileCredentialLock的0600/O_NOFOLLOW/nonblocking flock，锁在scope的.locks目录，永不随task缓存删除或unlink。顺序为WithOperationContext固定句柄→用该句柄算scope→TryLock（无SQL事务）→锁内重读revision/stage/current digest→发布/同句柄CAS/清理→解锁→释放lease。忙立即返回可重试状态，不在SQL事务里等待或重试外部写；同task嵌套调用只复用私有context携带的固定db/guard，不再取global句柄，不嵌套不同task锁。GC游标绑定scope，换库即关闭旧游标。该协调保护重新引用与清理窗口，不改变临时缓存非事实源的定位。manifest中默认selected仅是UI建议，启动负载必须有用户Submit写入的非空SelectionDigest；准备磁力清单的重确认不能把默认选择冒充用户已经确认下载。

对`.torrent`使用有界bencode元信息解析，支持v1/v2/hybrid，hash基于原始info字节，校验长度总和溢出、文件数≤10000、路径深度≤64，展开后的全部File.Path总字节≤16MiB（Join分配前检查预算）；拒绝绝对路径、`..`、空组件、NUL、符号链接条目、大小写/Unicode等价路径冲突及超出根的路径。纯v2的name仅为显示文本，真实路径来自file tree，不按文件路径组件校验显示名。协议padding可省略path，此时Path为空且只作不可选占位；真实文件仍必须有安全路径。协议允许仅padding之间同规范路径同长度重复；它们是不可选占位，仍计入解析数量/长度/对齐检查，不参与可选文件路径唯一映射，也不能与真实文件或目录冲突。共享pieces root的Merkle layer在单次解析中只验证一次，每个文件仍单独核对size对应hash数量，避免合法重复内容造成计算放大。保存完整元信息的SHA256，文件选择绑定此版本。解析器保留协议路径；hybrid按v1多文件共同name根之外的相对路径与v2树逐项比较内容名称、顺序、size及piece对齐，单文件不盲目剥根；最终仍输出v1的完整落盘路径，原始info字节和稳定文件ID规则不改写。映射到qBittorrent文件index须按已验证的客户端布局相对路径+size一一核对，不能认为本地解析序号等于客户端index。torrents/files响应采用有限JSON预算：6×16MiB路径转义上界+10000×1KiB每行字段开销+64KiB外壳，仍最多10000行，JSON数组逐项解码并在第10001项与路径累计超预算时立即拒绝，不能先无界分配全部行再检查数量；不能用4MiB响应上限拒绝已允许的正常大清单，也不能改成无界读取。5.2.3隔离试验已证明rootless纯v2多文件会按Original布局加显示名根，故P002负责明确且有目标版本实证的布局变换，P006不把所有v2 name强制解释成路径。用于实际目录的name须先通过安全组件/展开预算校验；不能确认布局、客户端改写或净化后与预期不符则拒绝启动，不能事后任意剥前缀凑匹配。完整隔离试验已覆盖v2单文件、nested单文件、已有共同树根（含重复name目录）及hybrid；实际目标profile为qBittorrent5.2.3/API2.15.1/libtorrent2.0.13.0。

磁力结果先展示“准备文件清单”，经用户点击后才允许建立受控元数据任务：在同一次add传`stopped=false + stopCondition=MetadataReceived`，无影片负载下载，元数据就绪后保持停止，导出元信息并校验后再展示选择。5.2.3对停止中的add忽略停止条件，因此禁止`stopped=true`后另发start获取元数据；该组合已在合成试验中证明会下载完整负载。MetadataReceived触发后条件自动重置为None，没有独立setStopCondition接口，确认选择后的正常启动依赖这一已核实语义，不调用虚构清除接口。该能力须用本机目标版本及实际libtorrent构建信息证明“停止前未下载影片负载”，生产门固定到已验证profile，不能用任意true跳过校验；不满足时该结果报`metadata_preview_unsupported`，不自动改成整包下载。v2/hybrid hash匹配以客户端明确返回的v1/v2身份与本地元信息一致为前提；5.2.3隔离试验已确认纯v2路由hash为完整SHA256前40个十六进制字符，但最终身份仍核对properties中的完整64字符。成功add优先记录added_torrent_ids给出的实际路由hash；超时查询只能用已验证规则，不能只凭截断hash认领。

默认勾选视频和同名字幕，其他文件可选，一键全选含所有正常文件；padding文件不可选。空选择拒绝。勾选后显示文件数、下载字节数和保存位置，明确非视频不会成为影片条目。跨文件piece可能包含少量未选文件字节，承诺的是客户端priority选择，不宣称网络绝无相邻piece字节。

### 提交与取消

提交前检测客户端是否已有同hash：本应用同manifest同selection返回原任务；同hash不同选择报冲突；非本应用任务报`existing_external_torrent`，不得接管、改tag、优先级或路径。检查与add不具备跨客户端原子性，add后必须同时匹配hash、owner_tag、路径、manifest；任一不符都停在conflict，不再设置其优先级、路径、分类或运行状态。注意add本身没有“仅不存在时创建”的原子接口；同hash竞争可能触发qBittorrent自身的元数据补全；公开种子在全局允许时还可能合并tracker/webseed，私有种子不合并。补全原有活跃磁力任务的元数据可能使其继续下载。5.2.3的重复分支在应用新AddTorrentParams前返回，因此不会用本次参数覆盖原保存路径、分类、标签、文件优先级、运行标志或分享限制。这是协议固有限制，事后检查不能撤销，也不能声称零副作用。CineInsight不为消除此限制改全局客户端偏好；确认页说明检测到已有任务时不会接管，竞争命中时会停止后续操作。

先事务写入意图、所选文件和独占保存根保护，再发外部add。每任务保存根是配置下载根下的`CineInsight/<task_uuid>/`，种子内部原始目录/文件名保持不变；用户在确认页可见该位置。保存根原先必须不存在，防止覆盖已有做种文件。根必须被用户已授权扫描目录覆盖且不在黑名单；未覆盖时返回配置错误并由既有目录配置入口处理，不能偷偷添加扫描根。

真实5.2.3全链路实证：普通torrent成功add后的第一次查询可能为`checkingResumeData`，此时归属、路径和完整infohash已经通过，稍后才成为`stoppedDL`。仅在本次原始成功add调用和现有add_sent claim内，允许对该已验证归属的`checkingResumeData`做最多5秒、100ms间隔、可取消的只读确认；每次仍完整核对归属、路径和hash，进入停止状态后继续原有完整清单/priority验证。等待不重发任何add/stop/start，不新增持久阶段或字段。实际链随后验证了同一客户端的start成功响应与运行状态更新也非同步：第一次完整回读仍停止，随后成为stalledDL。对本次确实发出并收到成功响应的start/stop命令，在原sent claim内同样以最多5秒、100ms间隔、可取消的只读回读确认请求的目标状态，每次仍核对归属、路径、完整hash、manifest和已选priority；不重复发送运行命令。命令前已经满足目标且未发写的路径保持原检查；超时uncertain保留pending/unresolved，维护取消保留sent。stop方向与start使用同一请求状态合同，最终隔离合成链已验证显式停止与继续，结果见验证记录。预算耗尽保留pending add与unresolved并转uncertain；维护取消立即退出并保留sent，由原恢复规则冻结；其他运行状态、身份/路径不符及读取错误保持原拒绝规则，不借此加入通用重试或扩大状态兼容。

只有停止状态、文件清单映射一致、所有priority回读一致后才启动。任何失败保持任务与保护记录，不向用户谎报下载已开始；再次操作仅从已核实阶段继续。取消草稿：本地未提交时删除临时元信息；已建立元数据任务只对已核实归属的任务发送删除且`deleteFiles=false`，结果不确定保留记录与目录保护。纯torrent草稿取消后，若attempt_generation=0、QBHash空且unresolved_write=false，用户重新预览相同digest可CAS回draft、回填cache并刷新有效期，保留原ID/root保护；不得把cancelled草稿永久锁死。released正式任务不由Preview或reconcile自动重开。正式下载仅提供停止/继续，不新增“删除数据”操作；qBittorrent中的外部删除在下次对账显示missing。

<a id="D-PT-06"></a>
## D-PT-06：逐文件入库与扫描资格（Data / Security Contract）

新增 `BTPathPolicy` 只读取任务/文件表，不访问网络；作为VideoService注入依赖。普通扫描对尚未成功导入的托管文件一律withheld，由协调器在新鲜完成快照下调用内部逐文件导入入口；已导入文件仅在保存指纹一致时允许既有记录继续对账，变化后撤销资格。配置下载根后先在托管namespace创建固定内容的标识文件（只含schema与初始instance_id创建标识，不含路径列表或秘密；此标识不代表当前connection归属，合法旧marker跨连接退休原样复用，任务准入仍按任务/files/指纹判断）；任务根保护行提交并发布到本进程策略后，才允许发qBittorrent add。首次仅允许在新建或空namespace目录写标识；已存在非空但无合法marker的目录拒绝接管，未知marker不覆盖。标识文件先于任何外部写创建，不能由普通torrent覆盖；扫描器在遍历前识别它，即使恢复的数据库不含连接/任务行，也把该namespace列为未知归属而不是普通目录。数据库读取失败，对受保护根内拒绝新增/刷新；未知范围时扫描整轮失败并禁止缺失对账，不能将查询失败当作“不是BT路径”。

受保护根内所有文件默认不具备入库资格，包括未选择文件、客户端临时文件及校验中内容。入库资格=属于本应用任务+已选择视频+客户端文件progress=1+非checking/moving/error/missing状态+任务归属/选择/保存根未变+规范路径与真实路径都在根内+实际大小匹配。不要求整包100%，更不能要求未选文件完成。完成后可边做种边入库。

保护必须在三层接线：

1. `scanDirectoryCollectContext` 输出文件集合前分类，返回allowed、withheld roots/paths和错误，而不是简单丢弃未完成路径。
2. 全量/窄扫描的既有记录刷新、自动恢复、搬家匹配、缺失软删阶段均排除withheld路径；这些路径表示“暂不核对”，不能变成“不存在”。新增`bt_pending`跳过计数接入Total及前端摘要。
3. `addVideoOrRestorePutBack`、`addScannedVideo`及`relocateVideo`/元数据刷新入口复核策略；BT导入只调用既有单文件入口，保留扫描根/黑名单、用户软删、同路径身份规则。测试必须覆盖直接AddVideo绕过扫描的调用。

单协调worker读取qBittorrent完成快照，事务写入文件资格版本（本轮同步generation，仅用于本轮导入，后台完成快照不向普通扫描发放永久许可）；调用库导入前再stat，导入后核对size/mtime/真实路径和资格版本，变化则不标imported，并使新建记录按既有失效路径隔离。外部qBittorrent/文件管理器不受应用文件锁约束，不能承诺文件永不被外部修改；后续发现校验/移动/选择变化立即撤销资格、停止进一步导入，并提示已有记录需核实。缓存只可用带revision的不可变快照，不能把过期完成状态视作永久通行证。

文件行另存publication_state：空表示复用既有记录且无待发布动作，pending_new/pending_restore表示首次创建/恢复已在同一事务关联video_id但尚未发布，done表示已完成发布调用。新建/恢复事务保持视频IsStale=true；最终路径、文件指纹和远端资格复核及CAS成功后才置为可见。恢复不得触发新视频规则，pending_new不得在重试恢复时降级为pending_restore。重启协调器对imported但仍pending的文件也重放发布；UI只有import_state=imported且视频可见才提供播放，不能只看video_id。复用既有发布记录不再发新视频通知。现有observeLocalMetadata/notifyNewVideo是进程内回调：pending在调用后标done，崩溃窗口允许重复调用，不承诺消费完成或exactly-once；规则消费者用既有账本去重，本地元数据沿用默认填充与来源指纹检查，不扩大为新的消息系统。回调未完成时退出保留pending，正常错误仍沿用现有观察者语义。扫描根和黑名单同时复核词法与真实文件路径；真实路径等价不替代现有词法片库范围授权。

文件导入状态：pending/importing/imported/failed/blocked_user_delete。AddVideo成功后记录video_id；如果导入成功但写结果前崩溃，恢复按规范路径复核既有视频身份，匹配即补关联。导入错误保留阶段和可重试原因，重新入库只处理未完成项。用户只删记录后不得被轮询重新收录。公开Undo/恢复保留既有语义：曾成功导入、旧video_id相同且仍selected/complete、Observed指纹与当前文件吻合的blocked_user_delete项可经显式恢复入口放行；该角色不授给普通扫描/Add，未曾导入且没有历史指纹的pending项仍拒绝。完成后由BT协调域的可取消串行查重worker调用注入的现有DownloadDuplicateChecker，只展示结果，不自动删除或覆盖。逐文件duplicate_result复用现有结果结构与来源video_id/size/mtime指纹，保存在BTFile，不另建任务表；查重失败不改变下载或导入成功。读取时复用现有可见性/指纹过滤，再投影当前片名；过期结果不展示。查重不占用下载命令串行门，维护/退出取消并等待查重后才能切库，恢复从已导入且未查重的文件继续。

词法路径与真实路径各自按最具体的匹配任务根判定，两侧适用资格必须分别通过，不跨坐标比较相对层数，也不依赖查询行顺序；已released的祖先任务不能放行其内后来建立的待完成子任务。released仅解除本任务范围的旧保护，其下新出现或恢复后未知的namespace标记仍隔离（原外层namespace标记不因此使正常released路径一直受阻）。

任务缺失/失去归属/连接不可达时保持保护，不自动释放目录。墓碑行不受下载历史展示分页/清理影响。已导入文件可按稳定指纹保持既有可见性，但不因离线假设新文件已完成。支持人工“解除下载管理”只对无未决外部写历史的允许状态开放，必须重新核实任务已停止或不存在、目录内无未完成/未选残留，展示影响并单独确认；该动作不删除磁盘内容。

关系：连接1:N任务，任务1:N文件；video_id为逻辑引用，硬删库记录不级联删下载事实。未选文件同样保存清单用于保护。`intent_key=connection_id+canonical torrent identity`防重复创建；v1/v2别名必须关联到同一意图，不只按展示标题去重。SQLite和PG用普通唯一约束/条件更新；不依赖NULL唯一性差异或SELECT FOR UPDATE。

任务创建与配置换代采用父连接task_epoch CAS：创建意图事务先以期望epoch、配置revision及slot=local条件递增父连接epoch，再插入任务；任一失败整事务回滚。Configure的更新/退休CAS同时比较旧epoch，因此active计数检查与新任务插入不能穿越换代。此为显式运行期事务辅助方法，迁移/备份恢复不触发，不放入模型BeforeCreate全局hook。单进程drain也关闭意图创建准入，但不能替代该CAS不变量。

所有外部写先CAS持久化执行阶段和pending_action（add/metadata/priority_zero/priority_select/start/stop/cancel_stop/cancel_delete；restore仅表示恢复快照待核实，不是已发HTTP操作），同时置unresolved_write=true，只有CAS胜者可发该次HTTP写。设置优先级不能以selecting作可重复执行状态：selecting→priority_zero_sent→priority_select_ready→priority_select_sent→start_ready→start_sent；stop、元数据取消的stop/delete也分别有ready/sent阶段。每次实际HTTP写前仍重读归属、路径、文件选择及所需停止状态，不能把本地CAS当作qB外部排他锁。

只有发起者以原revision/attempt收到成功响应并完成读回验证，才能推进下一阶段并清pending_action；unresolved_write恢复为本次claim前的旧值，而不是无条件false。*_sent中断/超时/重启后只读对账，不能自动重放或用一次空查询清除未决历史；初始化/Resume的恢复屏障在首条串行业务操作前按持久阶段冻结全部恢复候选，不以created_at与当前墙钟比较判定旧请求，避免时间回拨或未来时间戳漏掉写意图。显式reconfirm_submit按pending_action重发原操作，仍复用同一task/root/tag/hash/selection。后来一次成功不能洗掉更早未能证实终结的请求标记。uncertain/abandoned或unresolved_write=true一律不能release，保护持续保留；已确认的正常操作仍可使用。reconcile只接受uncertain/abandoned/missing/conflict，不得重开released。此限制来自外部API没有取消/栅栏旧请求能力，不承诺通过等待时长证明请求已经终结。

下载进度/纯远端观察不递增用户命令revision，否则持续轮询会使停止动作和风险确认反复过期。BTTask.observation_epoch拥有观察快照的CAS：比较id/command revision/stage/attempt_generation/旧epoch后递增，本轮BTFile.EligibilityRevision取该epoch；首轮取max(当前epoch,已有file eligibility)+1，避免旧列升级为0造成资格ABA。P003仍分别校验task命令revision/attempt和file资格epoch，无需弱化守卫。由观察产生的失败/结构转换同样须匹配原observation_epoch，防旧失败覆盖较新正常观察；用户命令CAS仍不比较观察epoch。只有命令或结构阶段变化才推进revision，相同stage/error不空增；纯观察事件可带相同revision，UI仍重读并按自身请求代际丢弃旧响应。

每次用户命令带expected_revision；事务条件`id/revision/stage/connection_id`匹配后stage前进、revision+1。0行更新时重读：同意图同选择已完成返回原任务，其余`bt_conflict`；不在事务重试中重放网络动作。用户显式reconfirm_submit只允许复用原意图与保存根，不能用“查询为空”冒充先前请求未发生；确认提示会说明可能与迟到原请求重复。客户端同hash去重与相同归属参数限制其结果，外部同hash竞争仍按D-PT-05处理。单worker序列化外部写入，UI只写意图；重复/过期回调携带操作generation不能覆盖新状态。revision永不重置，避免停止→运行→停止的ABA。

| 元数据准备 | 归属明确且取消删除确认 | cancelled；目录仍受保护直至安全解除 |

完成用远端下载状态和逐文件import状态组合投影，不用一个done抹平“已下完但没入库”。重启将瞬态外部命令改为待对账，不能照浏览器下载把外部任务标interrupted。维护先关闭命令准入、取消并等待本地worker、停止导入，qBittorrent继续下载/做种。恢复/迁移完成后先对账再启动watcher或扫描；旧备份缺少任务但存在托管namespace时，namespace默认隔离并显示“未知下载归属”，不得自动扫描放行。

显式数据库恢复不能仅信任恢复出来的旧flag：备份之后可能已发出新请求。P004在App的beforeRestore（真实替换数据库之前）持久写BT恢复围栏标记，复用数据目录内临时文件fsync/原子rename模式，记录目标库公开身份scope且不包含秘密，不进入备份。恢复成功或提交结果不确定时标记留到下一次初始化；初始化在开放BT接口/worker前核对scope，事务把恢复的非released任务设为未决并冻结自动外部写，再删除标记并fsync目录。不能用DatabaseRestoreRequiresRestart(err)==false推断原库未变：pg_restore已调用后即使工具报错、重连成功，提交结果仍可能未知。beforeRestore成功后的失败，只有额外证明未进入破坏性恢复或持久配置选择未改，才可撤该次标记；其余保留围栏。普通服务可沿既有失败恢复恢复，但BT不得经通用Resume重开，须先在固定当前库和task cacheguard内成功消费围栏，或保持BT关闭等待下次初始化。明确未修改原库的恢复失败可清标记并恢复原服务；标记读写/清理失败只关闭BT新命令，不绕过围栏。已提交后进程崩溃也能据标记重做该幂等标记事务；原namespace与未知路径保护持续有效。“只改配置切回旧后端”也可能打开旧快照：复用同一BT围栏，但scope从DatabaseSwitchService已经打开并校验的目标库句柄取得，在发布后端配置前落标记；仅取得目标公开身份，不提前修改目标库，保留“只改配置”合同。由App注入可拒绝的目标准备hook，数据库切换服务不反向依赖BT实现。配置写失败只有确认持久选择未改变才能清标记；结果不确定时保留。正常的全量迁移复制了已Drain的最新任务意图，不额外把全部任务扩散为未决。普通配置更新/正常暂停不将全部任务扩散为未决。 恢复标记处理使非released行revision前进、stage=uncertain、unresolved_write=true，保留非空PendingAction，空值归为restore。用户重确认restore时，若已确认选择且远端完整匹配，可只读恢复管理视图并保留远端运行状态/历史hold；未确认SelectionDigest时只能重新准备文件选择，缓存缺失要求重新搜索，不能从默认勾选启动负载。该额外磁盘标记仅拥有恢复与外部请求的失效边界，数据库仍是任务意图事实源；不引入新的下载状态存储。

迁移在AllModels中按连接→任务→文件顺序；双向迁移夹具每表有数据。备份仅包含上述非秘密记录；临时元信息及Keychain不复制。回滚旧版应用无法识别新保护表，必须先停新BT准入并把整个托管namespace从旧版扫描范围排除，完成风险说明后才回滚。不能仅删除新表或关闭开关让半成品进入旧扫描器。

SQLite 恢复目标身份补充：现有恢复按本次 `database.SQLitePath(dataDir)` 对最终文件做原子替换；若最终文件是符号链接，恢复前物理库身份与替换后身份不同。BT 围栏在破坏性恢复前同时持久化当前实际库 scope 和计划替换后 scope（规范真实父目录加最终文件名，不跟随最终 symlink），共用现有 SQLite scope 编码，不改变备份恢复目标或 Keychain 语义。普通路径同 scope 去重；两份 marker 均持久成功才允许恢复。票据保留每项 nonce/Created，第二项失败也保留首项的归属信息；已知尚未开始恢复时只清本次创建项，既有 marker 不清；恢复已开始或结果不确定时保留各 scope 标记，之后各自按既有消费流程核实。ConfigOnly 只标记已打开目标库的实际 scope，不采用文件替换身份。该补充由真实临时 symlink→replace 的 scope 变化证据触发，保持原恢复兼容行为，已独立定点复核。

## D-PT-09：最新资源、封面与观看区入口（2026-10-31）

来源：当日用户要求默认展示最新数据、补齐缩略图、在片单增加栏位。产品结果已授权；下列为实施设计。

- 空关键词复用 GET search；Prowlarr 返回的本轮资源统一按发布时间倒序，缺失时间排末尾，同时间稳定排序。仍最多两站并发、500条、10分钟令牌，不新增自动轮询、持久资源库或自动下载。
- 片单新增 `resources` 标签，嵌入现有 `BTDownloadsPanel`；首次进入才挂载，切走后保持实例但停止轮询与在途结果更新。保留管理下载页；想看条目的「找资源」改为打开片单资源标签并带关键词与一次性请求token；重复相同片名也重新应用。下载协调及文件选择仍由现有模块拥有，设置、播放事件交由 App。
- `btclient.Release` 读取 `posterUrl`，原地址仅保存在既有搜索令牌缓存。前端只拿 `/preview/bt-poster/<result_token>`，无图时为空。资源图片懒加载，图片缺失或失败显示无封面占位，不阻断搜索或文件选择。
- 资产路由只接收令牌（不接受URL），经 `BTService` 的维护/连接准入与 `BTSearchService` 的代际/过期检查后取图；图片仅在短时准入与取连接快照期间持有命令串行门闩，外站GET在门闩之外、独立的可取消图片读作用域中执行；Drain/Configure/维护取消该作用域，请求完成再次检查作用域和令牌代际。慢封面不得阻塞任务列表及停止/继续。图片请求复用现有资料源HTTP客户端工厂及其代理配置，不使用BT服务的带API Key客户端；不携带站点Cookie、Authorization或Prowlarr凭据，不追随重定向。
- 图源限公网HTTP(S)默认端口，拒绝userinfo、fragment、内网及特殊地址。解析域名后固定到已校验的公网IP（包括通过代理时的CONNECT目标），HTTPS仍按原域名校验证书，阻止DNS重绑定和跨源密钥泄漏。Go标准库的明文HTTP代理无法把路由IP与Host分离，因此配置代理时拒绝HTTP封面（保留无封面占位），不悄悄改成直连；HTTPS经CONNECT固定IP。最多两个图片请求并发，每张20秒、4MiB，只响应JPEG/PNG/WebP，禁止SVG/HTML。不落盘，不改变片库封面或托管图片服务。
- 复用取舍：`ManagedImageService` 和想看海报下载拥有持久实体及落盘生命周期，不适合10分钟搜索快照；只复用HTTP工厂与图片类型判定。图片短期链接继续归BT搜索模块，不增加独立存储或任务。

验证覆盖：空/单条/多站时间排序与截断；空词请求和失效代际；有图/无图/坏图；内网、重定向、超限与超时；前端自动最新、手动关键词、隐藏与迟到请求；片单导航与原四页生命周期。安全相关差异完成后独立审阅。Support lenses：go-style。
