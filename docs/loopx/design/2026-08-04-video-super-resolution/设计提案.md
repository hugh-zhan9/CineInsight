# 视频超分首版采用原生 NCNN sidecar 与确定性 2× 输出

Author(s): CineInsight 工程团队
Last updated: 2026-08-04
Status: Under review
Discussion: 当前会话；用户显式批准是进入 P-013 的唯一审批门槛
Source requirements: `docs/loopx/plans/2026-08-04-feature-expansion.md` P-012；`docs/video-super-resolution-model-selection.md`
Support lenses: architecture-designer, sql-style, go-style

## Abstract / 摘要

首版视频超分固定面向 macOS arm64（Apple M4、32GB 统一内存），使用随应用发布并签名的 `Real-ESRGAN-ncnn-vulkan v0.2.0` 派生 sidecar。真人/普通视频使用 `realesrgan-x4plus`，动漫使用 `realesr-animevideov3`；两个配置都输出 2×，由用户显式选择，不自动判断内容类型。sidecar 通过 NCNN/Vulkan 与内置 MoltenVK 使用 Apple GPU，不安装 Python、不依赖 CUDA、不经 Rosetta、不在运行时下载模型，也不提供 CPU 静默降级。

任务以 PostgreSQL 持久队列串行执行，原视频只读。增强结果固定写到源视频同目录的 `<stem>.enhanced-<general|anime>-2x.mkv`，通过同卷临时目录分块处理并在最终校验后原子发布。成功后结果作为新视频入库，并自动建立已确认的现有同源关系；失败、用户取消或磁盘不足均清理临时产物，不留下输出记录，原视频 SHA-256 必须保持不变。

本文已经关闭所有实现相关选择，但状态仍为 `Under review`。在用户明确批准前，P-013 不得开始。

## Background / 背景与动机

旧文档只得到“优先 Real-ESRGAN”的阶段性结论，仍留下六类实现阻塞：并列的 NCNN 与 PyTorch/MPS 候选、一般内容的实际模型、输出容器与命名、持久任务状态、同源关系语义、失败/取消/磁盘不足的文件终态。直接进入实现会让运行时发布、数据库状态机和用户媒体目录写入在代码阶段被临时决定，违反 P-012 的审批边界。

仓库已有可复用先例：

- `TechnicalBackfillService` 证明了显式触发、单 worker、context 取消、事件加轮询的本地长任务模式。
- `libraryPathMutationMu`、扫描对账与唯一活跃路径索引构成媒体目录发布边界。
- `VideoSameSourceRelation` 已经表达规范化视频对、高置信同源、已确认/已否认以及清理中心消费方式。
- `MediaProbeService` 已经提供参数数组调用 ffprobe、源文件前后指纹和有界错误输出。

上游官方资料也给出可落地基础：Real-ESRGAN NCNN 可执行程序支持 `realesrgan-x4plus`、`realesr-animevideov3`、2/3/4 倍输出和自动 tile；动漫模型官方说明可用于 1×/2×/3×/4×。NCNN 官方构建文档提供 macOS `arm64` 与 MoltenVK/Vulkan 路径。因此首版可以固定在一个无 Python 的本地 sidecar，而不把模型运行时变成用户环境管理问题。

## Goals And Non-Goals / 目标与非目标

目标：

- 在 Apple M4/32GB 上提供完全本地、显式触发、可取消、崩溃后可续跑的 2× 超分。
- 普通真人内容与动漫内容各有一个固定模型配置，用户可预测地选择。
- 绝不覆盖或修改原视频；最终输出、数据库记录和同源关系要么完整出现，要么都不出现。
- 将运行时、模型、输出、任务状态、磁盘策略、取消和清理规则固定为可测试契约。
- 保持现有扫描、软删除、字幕、标签、播放统计和 AI 数据外发边界不变。

非目标：

- Windows、Linux、Intel Mac、Rosetta、CPU fallback、PyTorch/MPS 或云端推理。
- 4×/8×、任意缩放、1080p 以上输入、HDR/10-bit、隔行、可变帧率或多视频流输入。
- 自动判断真人/动漫、自动挑选模型、面部修复、去噪强度或用户自定义模型。
- BasicVSR++、RealBasicVSR、扩散式或其他多帧生成模型。
- 覆盖原文件、原地替换、外置 SRT 复制、标签/收藏/播放进度复制或自动删除原版。
- 把性能耗时承诺为固定倍数；耗时取决于分辨率、帧率、时长和 GPU 状态，UI 只展示实测进度与已用时间。

## Proposal / 设计方案

### 1. 一个原生、离线、可校验的运行时包

发布包包含 `realesrgan-ncnn-vulkan v0.2.0` 源码派生的 `darwin/arm64` sidecar、该版本锁定的 NCNN 子模块、静态或随包签名的 MoltenVK、两个模型的 `.param/.bin` 与许可证。运行时身份固定为 `realesrgan-ncnn-vulkan-v0.2.0-cineinsight1`；清单记录每个可执行文件和模型文件 SHA-256，应用调用前验证清单、架构和 Vulkan GPU 可用性。

固定配置：

| Profile | 模型 | 输出倍率 | NCNN 参数 |
|---|---|---:|---|
| `general` | `realesrgan-x4plus` | 2× | `-s 2 -t 0 -g 0 -j 1:2:2 -f png` |
| `anime` | `realesr-animevideov3` | 2× | `-s 2 -t 0 -g 0 -j 1:2:2 -f png` |

`-t 0` 使用 NCNN 自动 tile，避免把未经实机测量的 256/512 写成产品配置；首版不开放 tile、线程、GPU 或 TTA。profile 必须由用户选择，默认 `general`，应用不根据标签、文件名或画面猜测动漫。

任一清单、签名、架构、模型或 Vulkan 检查失败时，能力状态明确不可用并返回稳定错误码；不下载、不安装、不切换 CPU/Python，也不继续排队。

### 2. 输入闭集与固定输出契约

可接受输入必须同时满足：活跃且非 stale 的本地常规文件、恰好一个主视频流、宽高均大于 0 且不超过 1920×1080、8-bit SDR、逐行、恒定帧率、可由现有 ffmpeg/ffprobe 读取。旋转元数据在抽帧时归一化；最终展示宽高以归一化后尺寸计算。HDR、10-bit、隔行、VFR、多个主视频流或 1080p 以上均在创建任务前拒绝，不做隐式转 SDR、去隔行或降采样。

输出固定为源目录下：

```text
<source-stem>.enhanced-<general|anime>-2x.mkv
```

例如 `movie.mp4` 的普通内容输出为 `movie.enhanced-general-2x.mkv`。目标路径只要已存在文件、目录或活跃/软删除视频占用就拒绝，不覆盖、不递增后缀。视频编码固定为 HEVC Main、`libx265 -preset medium -crf 18 -pix_fmt yuv420p`；MKV 复制源文件全部 audio/subtitle 流、chapters 和安全容器 metadata，忽略 attachment/data 流。输出视频流保持源 CFR、时长和显示比例。外置字幕不复制。

### 3. 有界磁盘的分块流水线

任务在目标目录创建隐藏工作目录 `.cineinsight-enhance-<task-id>/`，因此临时与最终文件位于同一卷。每批固定 120 帧：ffmpeg 抽取无损 PNG，NCNN 生成 2× PNG，ffmpeg 编码视频分段，然后立即删除该批输入/输出帧。所有视频分段和 staging final 使用不在扫描扩展名中的 `.cispart` 后缀，并通过显式 ffmpeg `-f matroska` 读写；隐藏目录本身不作为防扫描保证。已完成分段和清单作为崩溃续跑点；当前未完成批次在恢复时整批删除重做。

创建任务时和每批开始前都检查同卷可用空间。预留下限固定为：

```text
required = max(source_size * 4, 8 GiB)
         + raw_chunk_bytes
         + 1 GiB

raw_chunk_bytes = 120 * (source_width * source_height * 4
                       + output_width * output_height * 4)
```

计算使用防溢出的 64 位整数并向上取整；低于下限即以 `disk_insufficient` 拒绝或失败。这个公式是运行安全下限，不是最终文件体积预测；运行中 `ENOSPC` 仍走同一失败清理路径。

所有外部命令通过参数数组与 context 启动，不经过 shell；取消必须终止整个子进程组。stderr 只保留清洗路径后的末尾 4 KiB，进度事件不包含绝对路径或帧内容。

### 4. PostgreSQL 持久队列是任务事实源

新增 `video_enhancement_tasks`，状态固定为 `queued -> running -> completed`，或从 `queued/running` 进入 `cancel_requested -> cancelled`，或进入 `failed`。`phase` 固定为 `preflight/extract/enhance/encode/publish/verify`。每个源视频同时最多一个活跃任务，队列按 `(created_at,id)` FIFO；全应用只有一个增强 worker。

任务创建记录源视频 ID、profile、倍率和初始 size/mtime；worker 开始 preflight 时确认 size/mtime 未变，再计算并持久化源 SHA-256，避免 Create Wails 调用因大文件全量哈希而长时间阻塞。任务还记录运行时和模型版本、输出 basename、帧总数/已提交帧数、状态/阶段、稳定错误码与有界错误摘要，以及成功后的输出视频 ID 和同源关系 ID。数据库不保存帧、音视频内容、命令 payload 或新增绝对路径副本。

应用启动只恢复之前由用户显式创建且仍为 `queued/running` 的任务，不创建新任务。恢复时重新验证源 SHA-256、目标冲突、运行时/模型版本和分段清单；合法则从最后完整批次继续。应用升级导致原运行时/模型不再可用时，旧任务以 `runtime_unavailable` 失败并清理，用户显式 Retry 才按当前版本从头开始。用户取消与应用退出不同：用户取消最终进入 `cancelled` 并删除全部工作文件；生命周期 shutdown 只停进程，任务保留为可恢复状态。

### 5. 原子发布后一次性入库并建立已确认同源关系

编码完成后先在隐藏目录验证输出：容器可探测、一个主视频流、归一化宽高恰为源的 2×、帧数相同、时长差不超过一帧或 100 ms 中的较大者、audio/subtitle 流数量相同、首/中/尾帧可解码。随后重新计算原视频 SHA-256，必须与任务创建时一致。

最终发布只在短临界区持有 `libraryPathMutationMu` 独占锁：再次确认目标未被占用，将已验证文件同卷原子 rename 到最终名，然后用数据库事务创建 `videos` 记录、技术快照、视觉指纹、已确认同源关系并完成任务。新视频不复制源视频的普通/AI 标签、收藏、已看、播放次数、进度、标题、评分、人物或作品集；自动短视频标签与后续 AI 处理继续走新视频现有入库语义。

同源关系沿用规范化 `(video_a_id,video_b_id)` 唯一对：`status=detected`、`confidence=high`、`reviewed_at=now`、`is_unread=false`、`detection_version=enhancement-v1:<profile>:<model-version>`，双方指纹由现有本地视觉指纹算法生成。它不写 `AISameSourceEvaluation`，因为这是确定性生成溯源，不是 AI 猜测；关系不会进入待审工作台，但会被详情关联与清理中心发现。

若 rename 后数据库事务失败，先把最终文件移回工作目录或删除，再将任务置为 `failed`。若进程恰在 rename 后崩溃，启动对账依据任务、最终 basename、SHA-256 和缺失的 output/relation ID 完成入库；文件不合法则删除。最终不能出现“文件成功但任务永远运行”或“关系存在但输出记录缺失”的静默状态。

### 6. 用户可见行为与接口边界

右键菜单和详情抽屉只增加入口，不改现有布局层级。创建前展示 profile、固定 2×、输出完整预览名、预计空间下限和“原文件不会被修改”。Wails 边界固定提供：能力检查、创建任务、任务列表/状态、取消、失败任务重试；事件 `video-enhancement-state` 与轮询返回同一状态快照。

同一源视频重复创建相同或不同 profile 的活跃任务均返回既有活跃任务，不重复排队。失败/取消任务重试复用同一 task ID，重新执行全部 preflight 并清零进度；`completed` 不可重试。进入 `publish` 后取消不再中断原子提交，调用方收到 `publish_in_progress`，最终以 completed 或 failed 为准。

## Boundary Scenarios / 边界场景

| 场景 | 处理 |
|---|---|
| 非 darwin/arm64、运行时缺失或 Vulkan GPU 不可用 | 能力为不可用，稳定错误码；不排队、不 fallback |
| HDR/10-bit/VFR/隔行/多视频流/大于 1080p | 创建前拒绝并说明首版边界 |
| 输出名已被文件、目录、活跃或软删除记录占用 | 拒绝；不覆盖、不自动改名 |
| 同一视频重复点击或并发调用 | 部分唯一索引与事务返回同一个活跃任务 |
| 运行中源文件 size/mtime 或 SHA-256 变化 | 终止、清理、`source_changed` failed；不发布 |
| 创建时或运行中磁盘不足 | `disk_insufficient`；终止子进程并清理隐藏目录 |
| FFmpeg/NCNN 超时、崩溃或输出帧缺失 | 当前任务 failed；有界错误摘要；不继续拼接坏结果 |
| 用户取消 queued/running | 进入 cancel_requested，杀子进程组，清理后 cancelled |
| 应用正常退出或崩溃 | 不视为用户取消；完整批次保留，下次启动验证后续跑 |
| publish 前取消 | 正常取消；publish 已开始则拒绝中断并完成原子结果 |
| rename 成功后数据库失败/进程崩溃 | 同步补偿或启动对账；不遗留不可追踪最终文件 |
| 原视频软删除、改名或迁移与任务并发 | 处理阶段每批复验；发布在路径独占锁内，变化导致 source_changed |
| 同源关系已有否认 | 新输出 ID 正常不会命中旧视频对；若规范化对意外存在则拒绝覆盖，任务失败并补偿文件 |
| 输出视频后来被软删除 | 任务历史保留，FK 指向软删除记录；现有回收站/关系隐藏规则不变 |
| 权限不足 | 创建前/每批/发布前检查可读写；失败不修改源文件 |
| 无网络或 API 配置缺失 | 不受影响；超分不访问任何 AI API |

## Rationale / 理由与取舍

在首版优先级中，确定可部署、离线、可取消和文件安全高于论文级时序质量与最大吞吐。一个 NCNN sidecar 同时覆盖两种内容，依赖面和故障域显著小于 Python/MPS；2× 将 1080p 上限控制为 4K。代价是 x4 网络以 2× 输出的计算成本、单帧模型潜在闪烁，以及只支持 Apple Silicon 的闭集输入，这些均明确暴露而不是用未验证 fallback 掩盖。

| Alternative | Why Not |
|---|---|
| PyTorch/MPS + `RealESRGAN_x2plus` | 引入第二套 Python ML runtime、包体和版本冲突；官方主路径仍以 CUDA/PyTorch 环境为主，首版运维成本更高 |
| 官方旧 macOS 便携二进制直接随包 | 架构与 M4 GPU 行为不可作为产品承诺；本方案改为固定源码版本构建原生 arm64 并纳入签名/哈希门槛 |
| BasicVSR++ / RealBasicVSR | 多帧时序质量更好，但 MMCV/CUDA 依赖、内存与移植成本不符合本地首版 |
| CoreML 转换 | 缺少本仓库已有运行时先例，需要自行验证算子、tile 与模型一致性；会把模型转换变成新的核心维护面 |
| 先全量导出所有帧 | 实现简单但长视频临时空间与清理成本无界；120 帧批次把峰值工作集固定化 |
| 输出 MP4/H.264 | 兼容性高，但多音轨/字幕复制限制更多且 4K 体积更大；MKV + HEVC 更适合保留本地媒体流 |
| 自动判断动漫/真人 | 误选模型会产生不可逆的输出成本，现有标签也不是可靠内容分类；首版由用户显式选择 |
| 自动改名或覆盖已有结果 | 隐藏冲突并可能破坏用户文件；固定命名 + 冲突拒绝更符合媒体目录安全边界 |
| 把生成关系送入 AI 同源待审 | 生成来源已确定，无需再次猜测；待审会制造无意义工作并污染 AI 质量样本 |

## Compatibility / 兼容性

方案对现有用户和调用方是加法兼容：新增表、服务、Wails 方法、事件、右键/详情入口和 sidecar 资源；不修改现有 Wails 方法、数据库字段含义、扫描结果、软删除、字幕索引、播放统计或 AI API。旧版本应用忽略新增表和 `.enhanced-*.mkv` 记录；若扫描到输出文件，它仍作为普通视频处理。

功能没有总开关；能力由平台/运行时 preflight 决定，任务只由用户显式创建。回滚应用版本不删除任务、输出或同源关系。已完成输出是用户媒体文件，不随应用卸载或版本回滚删除；回滚前 queued/running 任务由新版本先停止并清理，旧版本只会忽略任务表。

## Operational And Security Impact / 运行与安全影响

- sidecar、MoltenVK 和模型纳入应用签名、公证、SBOM、第三方许可证与 SHA-256 清单；构建产物只接受 darwin/arm64。
- 不发起网络请求，不读取 AI Key，不持久化帧、命令 payload 或新增绝对路径副本。
- 一个增强 worker 限制 GPU、CPU 和磁盘争用；帧批次与自动 tile 限制峰值工作集。
- 状态事件包含 task/video ID、profile、phase、帧进度、时间和错误码；日志只含 ID、版本、计数、耗时与已清洗错误。
- 失败可按 `runtime_unavailable`、`unsupported_input`、`output_conflict`、`disk_insufficient`、`source_changed`、`decode_failed`、`inference_failed`、`encode_failed`、`verify_failed`、`publish_failed`、`cancelled` 归类。
- 用户取消和失败均删除工作目录；启动时对所有非终态任务与孤立工作目录执行有界对账。

## Implementation And Transition / 实现与过渡

落地必须先增加可重复的加法迁移和 runtime capability，然后接入持久 worker 与文件流水线，最后开放 UI 入口。用户批准本文之前不得开始任何 P-013 代码或运行时打包。实现完成的真实样片验收必须覆盖一般/动漫、取消、磁盘不足、源文件变化、应用崩溃续跑和 publish 补偿；不得用单元测试替代 M4 真机 GPU 与签名包验证。
