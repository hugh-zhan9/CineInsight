## 背景：盘点到的不统一（2026-10-13 代码实测）

- **刻度缺失**：只有颜色变量。字号 31 种（12px 用了 285 次、12.5px 52 次……），字重 12 种，圆角 29 种，内边距 161 种，z-index 25 种（最高 3000）；5 个变量用了却没定义，深色主题下强调色上写死白字对比度不够。
- **组件各写一套**：页头 12 种以上（标题 26/22/18/17 号与浏览器默认混用，片库页没有标题）；标签页 14 种实现、3 套无障碍写法；48 个对话框标题 h2/h3 各半、4 种关法、只有 17 个能点外面关、5 个自制遮罩按 Esc 关不掉；按钮类名 34 种、141 个按钮用一次性样式、7 种高度；空状态 38 种、错误样式 65 种、进度条约 20 套，没有骨架屏与转圈组件；图标三套加字符（× ▾ ★ ⚠ 🖼）。
- **交互各走各的**：
  - 打开与编辑：分四种（整页详情、抽屉、两个查看器），抽屉里评分即存而年份要点保存。
  - 删除：用词与确认 4 级，输入确认词 3 个（清除记录 / 移除记录 / 清空）；「回收站」40 处、「废纸篓」80 处混用。
  - 撤销：散在 5 处，全局提示放不了按钮。
  - 批量选择：每页布局、用词不同，有一页不选等于全选。
  - 后台任务：反馈分散在抽屉、弹窗、各页状态条和浮动条。
  - 其他：⌘K 打开清理中心；快捷键帮助只列 7 个。

## 核心方案：一套语言，两种场景

观看沉浸、管理高效。两边共用同一套刻度、组件与交互规则，只在「表面」上不同（背景、卡片形状、信息密度）。五条原则：

1. **一件事一种做法**：页头、标签页、对话框、提示、空状态、进度，每类只有一个组件。
2. **同名、同位、同反馈**：同一个动作在哪儿都叫同一个名字，放同一个位置，给同样的确认与撤销。
3. **能撤销就不打扰**：可撤销的不弹确认、做完给「撤销」；不可逆的才确认；只有永久删除类要输入确认词。
4. **内容在前，工具在后**：观看侧只留看片要用的；维护动作在管理侧，按频率分层。
5. **状态说得清**：加载、空、出错、后台任务都有固定样子和下一步。

### 组件

<a id="D-UD-06"></a>
**D-UD-06 · Interface Contract · Accepted（用户 2026-10-13 选定方案与实施顺序）**：每类只有一个组件，放在 `components/ui/`（接口见详细设计）：

| 类别 | 组件 |
|---|---|
| 页面结构 | 页头 `PageHeader`；标签页 `AppTabs`（下划线式，页内一级分区）；分段 `SegmentedControl`（同一内容的不同看法）；筛选芯片 `FilterChip` |
| 标记 | 标签 `TagPill`（用户分类，可点）；徽标 `AppBadge`（数量与状态，不可点）；统计卡 `StatTile`（已有） |
| 浮层与反馈 | 对话框骨架 `DialogShell`（由 `BaseModal` 扩展）；三级确认（扩展 `confirmAction`）；可带一个动作的全局提示（扩展 `notify`）；页级横幅 `AppBanner` |
| 状态 | 空状态 `EmptyState`；骨架屏 `SkeletonBlock`；转圈 `AppSpinner`；进度条 `ProgressBar` |
| 操作与图标 | 选择操作条 `SelectionBar`；图标 `AppIcon`（一套线性 SVG） |

按钮收成 4 种外观（主要 / 次要 / 幽灵 / 危险）× 2 种尺寸，加一种文字链接，作为全局类保留在 `components.css`。

### 交互规则

<a id="D-UD-07"></a>
**D-UD-07 · Behavior Contract · Accepted（用户 2026-10-13 选定方案与实施顺序）**：确认分三级。
1. **可撤销**：不确认，完成后全局提示带「撤销」（8 秒）。例如移到废纸篓、批量编辑、加标签、加入作品集。
2. **要确认**：确认框写清数量与影响。例如从片库移除、恢复备份。
3. **不可逆**：确认框加输入框，输入的就是按钮上的文字（全站同一规则，替换「清除记录 / 移除记录 / 清空」）。例如永久删除、清除失联记录、清空目标库。

实施修订（2026-10-13，B 组实施与删除流程评审，主代理裁定）：
- 设置里已有的「删除前确认」（默认开）优先于第 1 级：开着时「移到废纸篓」照旧先确认，关掉才不确认、只给撤销提示。不改它的默认值。
- 人物页与抽屉里的人物媒体删除总是先确认：按钮写「从片库移除… / 从图片库移除…」，确认框里再选是否把原文件移到废纸篓；「移除」在人物页上容易被理解成解绑，不能不经确认就删。
- 删除作品集（后端直接删除）按第 3 级，输入「删除作品集」。
- 不在第 0 步迁移清单里的既有不可逆操作（删除/合并标签、删除/合并人物、数据体检清理悬空引用）暂保持第 2 级，是否改为输入确认待用户定。

<a id="D-UD-08"></a>
**D-UD-08 · Behavior Contract · Accepted（用户 2026-10-13 选定方案与实施顺序）**：删除只用三个词。
- **移到废纸篓**：文件进系统废纸篓，记录进回收站，可撤销。
- **从片库移除**：只删记录，文件不动。
- **永久删除**：不可恢复。

<a id="D-UD-09"></a>
**D-UD-09 · Behavior Contract · Accepted（用户 2026-10-13 选定方案与实施顺序）**：撤销有两个入口。
- **当场**：全局提示里的「撤销」。
- **事后**：任务中心「最近操作」，列出最近 20 次可撤销的操作。这个列表在第 0 步先接入删除和批量编辑，其余操作在三期接入。

不能撤销的操作，按钮上就写明（「永久删除」），不在提示里假装能撤。

<a id="D-UD-10"></a>
**D-UD-10 · Behavior Contract · Accepted（用户 2026-10-13 选定方案与实施顺序）**：全站一个选择操作条 `SelectionBar`。
- **出现时机**：有选中时才在内容区底部浮出，没选中时页面上没有批量动作。
- **作用范围**：默认只作用于勾选的条目；要作用于整个筛选结果，必须点「全选当前结果（N）」，括号里写出数量。
- **用词**：「全选当前结果 / 取消选择（Esc）」全站一致。

实施修订（2026-10-13，删除流程评审）：
- 没有结果总数的模式（语义搜索、相似片、随机）里，「当前结果」就是已显示的条目：「全选当前结果（N）」只选已显示的，N 为已显示数量，不再往下加载（这些模式没有距离截断，「全部结果」等于整个已索引片库）。
- 要往下加载才能全选时，加载期间按钮显示「正在选择…」，用户在此期间改动选择就取消这次全选；筛选、页签或列表在加载期间变了，什么也不选。
- 宿主隐藏（如 `v-show`）时选择操作条不响应 Esc；清理审阅的勾选是审阅状态，Esc 不清空（「取消选择」仍可清空）。

<a id="D-UD-11"></a>
**D-UD-11 · Behavior Contract · Accepted（用户 2026-10-13 选定方案与实施顺序）**：后台任务只有一个入口。
- **顶栏**：任务指示（转圈 + 数量，失败时红点），点开任务中心。
- **页内**：只显示本页正在做的那一件，用统一的进度条组件。
- **结束**：用全局提示（「完成 · 查看」「失败 · 重试」）。

片库页叠在一起的三四条状态栏收进任务中心。

实施修订（2026-10-13，B1a）：第 0 步只换装、不改后端，片库页的后台任务状态条暂留（统一进度条与样式）：任务中心还没有跳过数、复用/移出范围数、「无需补全」、导出 NFO 的取消等信息，补齐要改任务中心的后端适配，按路线并入三期「后台状态条全部收进来」。语义检索提示条（搜索状态，非任务）与增量扫描的结果条也留在页内。

<a id="D-UD-12"></a>
**D-UD-12 · Behavior Contract · Accepted（用户 2026-10-13 选定方案与实施顺序）**：反馈位置固定。

| 情况 | 放在哪里 |
|---|---|
| 成功 | 全局提示，约 4.5 秒（可撤销的 8 秒） |
| 临时失败 | 全局提示，带「重试」，不露错误代码和路径 |
| 表单输入错 | 就地，写在输入框下面 |
| 持续状态（离线、缺组件、维护中） | 页级横幅 |
| 要用户决定的事 | 对话框，按三级确认 |

修订（2026-10-13，A 组评审）：成功提示的停留时间沿用现有的 4.5 秒（受保护的既有行为），初稿写的 3 秒作废。

<a id="D-UD-13"></a>
**D-UD-13 · Behavior Contract · Accepted（用户 2026-10-13 选定方案与实施顺序）**：打开与编辑。
- **观看侧**：整页详情。收藏、已看、评分即存。
- **管理侧**：抽屉。开关与评分即存，文字字段统一「保存」，离开时如有未保存会提醒。
