## 四、详细设计

### 4.1 D-01：网络与身份（AC-01）

Operational / Interface Contract：监听独立 TCP 端口，默认 8096，默认关。仅接受回环/内网/链路本地地址，不信任转发头。除公开服务器信息和登录外，每条路由包括图片、字幕及 Range 都要 token。Origin 存在时校验同源。只提供一个非管理员账户，不能删除媒体或改全局配置。

配置由独立 Wails 方法保存。通用 SettingsService.UpdateSettings 的整行 Save 必须显式 Omit 全部 Jellyfin 列，避免旧快照覆盖独立配置；独立配置 owner 串行化读取、数据库字段更新、旧连接关闭/令牌失效与按新配置启动，两个配置调用不得交错。数据库写失败保持原实例；写成功但监听失败保留新配置并显示未运行/失败，可修正端口后重试。密码 8–72 UTF-8 字节，bcrypt 哈希；用户名非空且 ≤64 字符。密码留空表示保持；首次开启必须已设置密码。server ID 首次配置时随机生成并持久化。公开状态不含 hash、明文密码、token；日志不得记录凭据或媒体路径；包含 hash 的配置 UPDATE 用局部静默 ORM logger，避免失败 SQL 插值泄露。

随机 token 256 bit，服务端只存 SHA-256 摘要；最多 64 个登录会话，每个有效期 30 天，达到上限拒绝新登录；退出登录清除该会话，关闭/更改配置/重启全部失效。登录限制并发哈希及短窗口尝试次数，失败不泄露账号存在性。请求体读取期限 15 秒，响应不设统一写超时以允许长片播放。停服关闭新请求准入、取消活动连接并等待全部 handler 退出，应用恢复数据库前先停服。

### 4.2 D-02：片库与 DTO（AC-02）

Behavior Contract：顶层提供全部视频、收藏、继续观看、未看、已看、最近添加、最近播放、标签、作品集和每个保存视图。实体用带类型前缀的 32 位十六进制 ID，避免相同数字 ID 跨表碰撞。公开媒体必须是当前扫描范围内的活跃且非失效视频；保存的失效视图不开放失效文件。返回名字、标签、个人评分、时长、现有流快照、观看状态，不返回本机绝对路径。

查询复用 `applyLibraryFilter`；没有扫描根时返回空库。字幕条件只查已有索引，HTTP 不触发全库索引同步；在同一查询追加外部筛选，不覆盖保存视图原筛选。默认每页 100、上限 200，支持 StartIndex/Limit、SearchTerm、标签、收藏/已看筛选；空页 Items 为 []。图片和未知资源类型不能回落为视频。

查询参数口径（V1.0.2）：参数分三类。① 投影提示（Fields、EnableImages、ImageTypeLimit、EnableImageTypes、EnableUserData、EnableTotalRecordCount、GroupItems、api_key/ApiKey、UserId）值被忽略。参数名不区分大小写；列表型参数（IncludeItemTypes、ExcludeItemTypes、SortBy、SortOrder、Filters、MediaTypes、ExcludeLocationTypes、LocationTypes、TagIds、Ids、ExcludeItemIds、Fields、EnableImageTypes 以逗号，Tags、Genres 以竖线）可重复出现并合并，等同 Jellyfin 的逗号分隔绑定器；标量参数重复且值不同时 400。② 语义参数按 Jellyfin 语义实现：MediaTypes 不含 Video、LocationTypes 不含 FileSystem、ExcludeLocationTypes 含 FileSystem、IsMissing=true、ExcludeItemTypes 含 Movie/Video、Filters 含 IsFolder 时视频列表为空集；ExcludeLocationTypes=Virtual、CollapseBoxSetItems、Filters=IsNotFolder 对本模型是空操作；布尔值非法仍 400。③ 其余未知参数继续 400，避免给出错误范围的结果。排序：SortBy 逗号分隔，已知键（SortName/Name/DateCreated/DatePlayed/PlayCount/Runtime/CommunityRating/DateLastContentAdded/Random）映射到列或 RANDOM()，未知键（ProductionYear、PremiereDate、IsFolder 等本模型无对应数据）忽略；全部未知时等同未传 SortBy。SortOrder 逗号分隔按 Jellyfin 规则逐键配对（缺省取第一个，再缺省升序），非法值 400。排序键只经白名单映射，不能拼进 SQL。

组文件夹（作品集、标签）：无 Recursive 或 IncludeItemTypes 只含文件夹类型时返回子文件夹；`Recursive=true` 且 IncludeItemTypes 为空或含 Movie/Video 时返回叶子视频（所有属于任一作品集 / 带任一未删除标签的视频），复用同一可见范围与默认排序。文件夹列表中 IsFavorite/IsPlayed/IsResumable=true 与 Filters 的 IsFavorite/IsPlayed/IsResumable/IsNotFolder 因文件夹 DTO 恒为未收藏、未播放而返回空集，IsUnplayed/IsFolder 为全集；视频 ID 与标签选择仍 400。文件夹在服务内按小写名称、ID 排序，倒序为正序的严格逆；SortBy 缺省或不含名称键时 SortOrder 不生效。Tags/Genres 多值（竖线或重复键）为并集，与 Jellyfin 一致；重复键按键名排序后合并，与大小写无关。

### 4.3 D-03：原片播放与状态（AC-03）

Interface / Data Contract：PlaybackInfo 校验 direct-play 容器/编解码器、码率上限及可判断的 profile 条件（宽高、视频 profile、码率/音频参数/帧率/位深，以及由流快照推导的音轨数、视频流数、是否次音轨、SDR/HDR 范围）；query 的 EnableDirectPlay/MaxStreamingBitrate 同样生效。

条件语义（V1.0.2，对齐 Jellyfin 服务端 ConditionProcessor）：ProfileCondition.IsRequired 缺省为 true；属性值未知（本模型不存该属性，或该视频没有该数据）时条件在 IsRequired=false 成立、IsRequired=true 不成立；未知比较运算符不成立。CodecProfile/ContainerProfile 先用同一套语义评估 ApplyConditions，全部成立才适用该 profile；只看 Type 为 Video/VideoAudio（空视为 Video）的 profile，Type=Audio 对视频不生效；SubContainer 按 Jellyfin 仅在 Container=hls 时替换容器，原片比对只看 Container。编解码器/容器列表支持前缀「-」的排除表，h265 与 hevc 互认。主音轨为第一条默认音轨（无默认则第一条），MediaSource 的 DefaultAudioStreamIndex 与协商使用同一条，与 Jellyfin 一致。不可直放时日志记录视频数字 ID 与原因（容器/编解码器名、失败的属性、运算符与期望值），经控制字符脱敏与长度上限，不记录路径。只声明 direct play，不给转码 URL；视频经 ID 解析原文件，GET/HEAD/Range 复用 ServeContent，不接受客户端路径。缺失流快照可在明确播放请求内调用已有 MediaProbeService.Refresh；失败明确返回不可播放。外置同名 SRT 可由受认证 ID 路由读取。封面复用 ThumbnailService。

Sessions/Playing、Progress、Stopped 写 `UpdateVideoWatchProgress`；到片尾才标记已看；收藏与已看动作分别复用现有 setter。进度秒=ticks/10^7，负数拒绝，超过时长由原服务裁剪。重复回报覆盖同一状态，不新增播放账本事件（现有来源闭集不扩展）。兼容入口写入串行化，保持到达顺序；多设备同一视频沿用现有最后到达写入语义，允许向后 seek，不按时间最大值合并。与桌面并发仍沿用服务的字段级更新，收藏不覆盖进度。

### 4.4 D-04：手机网页（AC-05）

Behavior Contract：FeedSheet Teleport 到 body，跟随 visualViewport 的 height/offsetTop/offsetLeft/width，监听 resize/scroll 且卸载清理；没有该 API 时用原固定满屏。内容区独立滚动，输入框/页脚不被 flex 压扁。标签多行、长名可换行，最多占可见高度约三成，超出可滚动；触摸/滚轮/键盘不转为切视频。

所有模块边界：空输入、缺记录、越界资源直接报错；不自动安装依赖、不新增后台重试。桌面播放、Feed API 和其反馈投影保持原语义。

## 五、存储

D-01 配置在现有 Settings 增加字段，由已有 ApplySchema 自动迁移；哈希 json:"-"，无新业务表。会话与限流 map 有界且随停服释放。无数据库应用锁、无新增第二套视频状态。

## 七、接口

公开：GET System/Info/Public、POST Users/AuthenticateByName。
认证：System/Info、Users/Me、Users/{id}、Users/{id}/Views、Items 与 Users/{id}/Items、单项详情、Items/{id}/Images/Primary、Items/{id}/PlaybackInfo、Videos/{id}/stream、外置字幕、Sessions/Playing[/Progress|/Stopped]、用户 FavoriteItems/PlayedItems、Sessions/Logout。

V1.0.2 补充（从 Fileball 1.4.13 二进制与真机回放取得的调用清单）：Items/{id}/Download 等同原片流并附 Content-Disposition（仅文件名）；Shows/NextUp、Studios、Persons、Artists 返回空页，Movies/Recommendations 返回空数组——本库不含剧集、工作室，人物不在首期暴露，Jellyfin 对这些从不回 404；DisplayPreferences/{id} GET 返回 Jellyfin 默认值，POST 校验 JSON 后返回 204 且不持久化（视图偏好属客户端/桌面，兼容层不新增存储）。

支持标准 Authorization MediaBrowser Token、X-Emby-Token、媒体 URL api_key/ApiKey；所有入口统一校验。具体字段以官方 Jellyfin API 与客户端证据为准，不盲目模拟管理接口。

## 九、维护

状态显示监听地址和启动错误；不会因端口占用拖垮主程序。

客户端请求日志（V1.0.2）：走应用现有 `log` 输出（设置中开启日志后写入数据目录 app.log）。每条记录方法、路由形状（路径中的 32 位十六进制 ID 替换为 `{id}`）、状态码和查询参数名；只有枚举型参数（SortBy、SortOrder、IncludeItemTypes、ExcludeItemTypes、Filters、MediaTypes、ExcludeLocationTypes、LocationTypes、Recursive、Limit、StartIndex、Fields 及布尔筛选）记录值。所有 ≥400 的请求都记录；<400 的请求中原片流、下载、图片、字幕和播放进度回报不记录，其余 API 调用记录，用于取得客户端真实调用清单。只在内网来源校验通过后记录，外部主机不能写日志；方法、路由、参数名和值都经控制字符替换与长度上限（路由 120、单参数 120、汇总 400 字符），防止伪造行或撑大日志。不记录 token、SearchTerm、路径中的资源 ID 或媒体路径；不可直放记录中保留视频数字 ID 供桌面定位。
