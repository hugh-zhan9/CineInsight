## 2 后端接口与数据

<a id="collection-progress"></a>
### 2.1 作品集进度（D-P2-02）

```go
// app_media_details.go
func (a *App) ListCollectionProgress(req services.CollectionProgressRequest) ([]services.CollectionProgress, error)

type CollectionProgressRequest struct {
    CollectionIDs []uint `json:"collection_ids"` // 非空：只算这些（作品集页、封面墙）；最多 200
    ContinueOnly  bool   `json:"continue_only"`  // true：「追到哪了」候选（见下），忽略 CollectionIDs
    Limit         int    `json:"limit"`          // ContinueOnly 时生效，默认 12，最大 50
}

type CollectionProgress struct {
    CollectionID    uint                    `json:"collection_id"`
    Name            string                  `json:"name"`
    HasCover        bool                    `json:"has_cover"`
    TotalWorks      int                     `json:"total_works"`
    WatchedWorks    int                     `json:"watched_works"`
    InProgressWorks int                     `json:"in_progress_works"`
    Complete        bool                    `json:"complete"`
    Next            *CollectionProgressNext `json:"next,omitempty"`
    LastActivityAt  *time.Time              `json:"last_activity_at" ts_type:"string"`
}

type CollectionProgressNext struct {
    VideoID              uint    `json:"video_id"` // 该部的代表视频（版本组取组代表）
    Title                string  `json:"title"`
    WorkIndex            int     `json:"work_index"` // 第几部，从 1 起
    Resume               bool    `json:"resume"`     // 有续播位置
    WatchPositionSeconds float64 `json:"watch_position_seconds"`
    Duration             float64 `json:"duration"`
}
```

- **计算**（`services/collection_progress.go` ✚，纯 Go 汇总，一次查询取成员）：
  - 查询：`collection_videos` 联 `videos`（活跃、未失效）左联 `video_version_members`，按 `(collection_id, position, video_id)` 排序。
  - 「一部」：同一 `group_id` 的成员合并，取它们中最小的 `position` 定位置；代表视频取该组代表（与 `CollapseVersions` 同一规则）。
  - 看过：组内任一成员 `is_watched`。在看：没看过且任一成员 `watch_position_seconds > 0`。
  - 活动时间：组内成员 `max(last_played_at, watch_progress_updated_at, watched_at)`。
  - 下一部：按概要设计 D-P2-02 的顺序选；`Resume` 为在看那一部。
- **`ContinueOnly` 候选**：至少一个成员有活动时间的作品集；算完后过滤「总部数 ≥ 2、看过或在看 ≥ 1、未完成」，按 `LastActivityAt` 倒序取 `Limit`。
- **失败**：数据库不可用返回错误（前端该区块显示错误、不影响其他区块）；作品集 ID 不存在的跳过。
- **性能**：成员总数在几千量级，单次查询 + 内存汇总；不加缓存。

<a id="watchlist-links"></a>
### 2.2 想看条目与片库的关联（D-P2-03）

**数据**：

```go
// models/watchlist.go ✚
// WatchlistVideoLink：非豆瓣来源想看条目与片库视频的关联，以及所有来源的「解除过」记录。
type WatchlistVideoLink struct {
    ID               uint   `gorm:"primarykey"`
    WatchlistEntryID uint   `gorm:"not null;uniqueIndex:idx_watchlist_video_links_pair,priority:1"`
    VideoID          uint   `gorm:"not null;uniqueIndex:idx_watchlist_video_links_pair,priority:2;index"`
    Origin           string `gorm:"size:16;not null"` // auto | manual | dismissed；不设 gorm default，创建时显式赋值
    Entry            WatchlistEntry `gorm:"constraint:OnDelete:CASCADE;" json:"-"`
    Video            Video          `gorm:"constraint:OnDelete:CASCADE;" json:"-"`
    CreatedAt, UpdatedAt time.Time
}

// models/product_completeness.go：MovieVideoLink 增列
Origin string `gorm:"size:16;not null;default:''"` // '' = 手动（存量）、auto = 自动匹配
```

- **一处一份**：豆瓣来源（`source_name = douban` 且 `source_item_id` 非空）的已关联存在 `movie_video_links`（榜单的已看同步依赖它）；其他来源存在 `watchlist_video_links`（`auto` / `manual`）；所有来源的「解除过」都存在 `watchlist_video_links`（`dismissed`）。读取一个条目的关联 = 对应那张表的已关联行，减去它的 `dismissed` 行。
- 迁移：两张表经 `AllModels` 自动迁移（拓扑序：`WatchlistVideoLink` 在 `WatchlistEntry`、`Video` 之后），`TestModelSchemaGolden` 更新。不回填。

**接口**：

```go
func (a *App) ListWatchlistLibraryState(entryIDs []uint) (map[uint]services.WatchlistLibraryState, error) // 最多 200
func (a *App) LinkWatchlistEntryVideo(entryID, videoID uint) error   // 手动确认；豆瓣写 movie_video_links，其余写 manual；清掉这一对的 dismissed
func (a *App) UnlinkWatchlistEntryVideo(entryID, videoID uint) error // 删关联并记 dismissed（豆瓣同时删 movie_video_links 那一行）
func (a *App) ListWatchlistInLibrary(limit int) ([]services.WatchlistInLibraryItem, error) // 首页：已关联且代表视频没看过，按关联时间倒序，默认 12、最大 50

type WatchlistLibraryState struct {
    Linked []WatchlistLinkedVideo `json:"linked"` // {video_id, title, origin: auto|manual, is_watched}
}
```

- 「片库中可能已有」的建议继续用 `SuggestLibraryMatchesBatch`（按片名 + 年份查，与来源无关），前端过滤掉已关联与已解除的。
- 原有 `LinkMovieToVideo` / `UnlinkMovieVideo`（榜单页用）不变；`UnlinkMovieVideo` 不写 dismissed（榜单解除不影响想看的自动匹配记录）。

**自动匹配**（`services/watchlist_library_match.go` ✚）：

- 输入：没有任何已关联、片名非空、年份 > 0 的条目。
- 规则：`normalizeLibraryTitle(条目片名)` 与视频 `display_title` / `original_title` / 去扩展名 `name` 的规范化结果**完全相等**（不接受前缀），且 `videos.year` 等于条目年份；命中的视频按版本组合并后**恰好一部**才关联（关联到代表视频；豆瓣写 `movie_video_links(origin=auto)`，其余写 `watchlist_video_links(origin=auto)`）；这一对有 `dismissed` 记录的跳过。
- 时机：
  - 条目新增、改名、在线补全成功后（只算这一条）；
  - 扫描同步完成且新增了视频后（全部未关联条目，后台、空闲门外——与想看条数成正比）；
  - 应用启动后一次（后台，数据库就绪后）。
- 并发：同一时刻只跑一轮（进行中再触发就记一次「再跑」）；写入用唯一索引兜底，冲突视为已关联。

### 2.3 片库新排序（D-P2-01）

| `sort_mode` ✚ | 排序 | 游标字段 ✚ |
|---|---|---|
| `added_desc` | `created_at DESC, id DESC` | `CreatedAt *time.Time` |
| `year_desc` | `year DESC NULLS LAST, id DESC` | `Year *int`、`YearIsNull bool` |
| `title_asc` | `title_sort_key ASC, id ASC` | `TitleKey string` |

- `validateLibraryVideoCursor` 按模式校验各自字段（其他模式的字段必须为空）。
- **排序键** `videos.title_sort_key`（`size:512;not null;default:''`，与 `id` 组成复合索引）：
  - 取值：`display_title`，为空时取去扩展名的 `name`；用 `golang.org/x/text/collate`（`language.Chinese`，忽略大小写与宽度）算出排序键，十六进制存储。两种数据库按字节序比较，顺序一致。
  - 维护：`models.Video` 的 `BeforeSave` 钩子在 `display_title` 或 `name` 变化时用 `Statement.SetColumn` 写入；不走钩子的批量更新（`Model(&Video{}).Where(...).Updates(map)` 改标题或文件名的路径）必须改为调用 `services.UpdateVideoTitleFields(...)` 统一写法。启动时后台补齐 `title_sort_key = ''` 的行（分批 500）。
  - 守卫测试：列出所有写 `display_title` / `name` 的服务入口（重命名、NFO 应用、元数据编辑、批量编辑、扫描建档、迁移），每条写完后断言排序键正确。
- `LibraryFilter.SortMode` 的取值校验加入三种新模式；Jellyfin 与手机端不暴露新排序（它们不传 `sort_mode` 或只传既有值）。

### 3.4 统一搜索（D-P2-05）

- `utils/unifiedSearch.js` ✚：给定查询，按组并行发起：
  - 视频：`SearchLibraryVideoPage({ filter: { keyword, search_mode: 'file', collapse_versions: true }, limit: 5 })`

- **固定**：两项用户裁决；命令 ID、手机端、Jellyfin 不变；不加剧集模型；统一设计规范与守卫清零；先二期后三期。
