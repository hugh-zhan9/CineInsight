# 姓名标签转为人物与分类留白修复

## 用户裁决

- 分类之间不保留大块空白，标签仍按分类全部展开。
- 仅“人物”分类的姓名标签可以转换为人物条目，关联所有打了该标签的视频和图片。
- 成功后删除原标签，改用人物关联。

## 实现边界

入口为「标签管理 → 对应标签 → 转为人物」，仅“人物”分类的非自动标签可用，分类名去首尾空白后精确匹配。其他分类与未分类隐藏入口，后端预览和事务提交同时校验分类；预览后被移到其他分类的标签也拒绝转换。未保存的标签编辑先保存。转换页读取服务端已保存名称及关联数量，明确告知原标签会删除；展示显示名或原名匹配的已有同名人物。出现候选时必须选择具体人物或明确新建，不自动挑选或合并人物。

`PreviewTagPersonConversion` 只读；`ConvertTagToPerson` 在同一事务中锁定并校验来源标签、校验预览名称、创建或读取指定人物、合并两类关联、删除来源标签及关联、使失效的 AI 待审候选退出待审。插入关联使用复合键冲突去重。转换包含软删除媒体，恢复媒体后人物关联仍在。人物既有头像、姓名及其他关联保持不变，文件不移动、不改名。删除沿用标签软删除和既有历史保留语义，没有数据库 schema 变更。

提交期间禁用重复提交和返回；失败保留选择与预览。转换成功局部移除标签管理中的来源行，刷新片库和预览详情，通知已挂载的图片页重新读取媒体及可用标签；当前筛选中删除失效标签条件。人物页按需挂载，进入时直接读取转换结果。

分类留白来自 WebKit 对嵌套换行 flex 的 grid 行高缓存：初始窄窗口中人物分类高 241 px，窗口变宽后标签实际只需 151 px，旧高度留下 90 px 空白；反向缩窄还会溢出分隔线。改为横向 flex 分类行后，行高随换行重新计算。

- `go test ./... -run '^$'` 编译检查通过。
- 前端 68 个组件/工具测试文件、772 项用例通过，含转换表单、标签管理入口、片库/图片页和 App 刷新接线；`npm run build` 通过。
- WebKit 18.2 实际渲染：1024 → 1440 → 2048 → 1024 → 1440 px 反复调整宽度，分类末行下方额外留白均为 0；1024 px 转换界面无水平或垂直溢出，同名未选择时禁止提交，提交后原标签行移除。使用本地界面夹具，未修改真实片库。
- 完整 `npm test` 在组件测试通过后被缺失的历史基线 `.loopx/workspace/2026-09-02-capability-batch/baseline/data-test-set-2026-09-02.txt` 阻断，不能宣称整条命令全绿。
- 跳过上述缺失基线检查后，其余 13 组前端脚本检查单独执行全部通过。

- 分类限制补充验证：24 项转换表单与标签管理测试通过，Go 转换回归通过；覆盖其他分类、未分类、相似分类名、未保存分类编辑及预览后分类变更，拒绝转换后原标签和两类媒体关联保持完整。
