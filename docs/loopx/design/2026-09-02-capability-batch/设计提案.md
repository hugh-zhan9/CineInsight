## Abstract / 摘要

我们把九项能力全部作为**加法**接入现有 Wails v2 + Go + Vue 3 模块化单体，不改任何既有公开方法签名、不改随机算法、不写用户媒体目录。每项能力遵循仓库已经验证过的四条模式：文件与既有业务表是事实源；后台任务单 worker、可取消、可续跑、进度事件；AI 与算法产出只生成候选，用户确认后才写关系；数据库只做加法迁移且 SQLite / Postgres 双后端都必须工作。

三处最难回退的决定已由用户裁决：转封装产物是**隐藏代理文件**而不是片库记录；人脸识别**同时覆盖视频与图片，人物实体共用**，这重开并替换了 2026-08-07「人物不覆盖图片」的裁决；代理目录**有可配置上限并按 LRU 淘汰**。其余方向由本提案在仓库证据上作出选择：播放历史用只追加的事件账本而不改计数列；人脸运行时用托管 Python sidecar；人脸向量以 BLOB 存储、相似度在 Go 侧算，不依赖 pgvector；通知与 Dock 角标引入仓库第一个 darwin 专属 cgo 文件；空闲调度是一个集中门，只挡自动触发的任务。

代码健康治理同批进行且行为保持：`app.go` 拆同包多文件，`VideoListPage.vue`（Options API，3130 行脚本）抽子组件，绑定重生成后 diff 为空是完成证据。

## Background / 背景与动机

仓库证据说明九项能力各自补的口子（详见 `clarification.md` Brownfield Evidence）：

- 内嵌预览白名单只有 `.mp4 .m4v .webm .ogv .ogg`（`services/preview_service.go:44-50`），手机端 Feed 复用同一张表。MKV 是最常见的容器，既不能内嵌预览也进不了手机端。
- 热力图按 `last_played_at` 分组（`services/library_stats_service.go:108-122`）。同一部片重看，上一次那天的记录就被覆盖，热力图系统性偏少；仓库没有任何播放事件明细。
- 字幕、超分、AI 打标、语义索引、备份都是分钟到小时级任务，代码里没有一处系统级通知。
- `people` 与 `video_people` 已有，`images` 表族已有，但人物关联全部手工；图片侧完全没有人物维度（`ImageFilter` 无人物字段）。
- 作品集全手工；仓库没有任何剧集模式解析。
- pHash 只存早/中/晚三点，同源判定只覆盖「同片不同转码」，识别不了「B 是 A 的一段」。
- 应用 236 个导出方法、十几个页面弹窗，快捷键只在审阅页有。
- `runPostScanAutomation` 一旦开关开着就立即启动 pHash、技术信息、清理分析（`app.go:1796-1829`），与用户正在做的事抢 CPU。
- 两处字幕翻译都按 50 条一批、批次之间零上下文（`subtitle_service.go:1026`、`subtitle_workbench.go:254`）；没有术语表。
- `VideoListPage.vue` 4874 行、`app.go` 2598 行、`video_service.go` 2633 行、`SettingsPage.vue` 2041 行。

用户在 `search/` 下放了三个参考项目（Viso 的截取识别、FrameStack 的 same_person 通道、Caption-Trans 的上下文翻译），与第 6、4、9 项一一对应，说明这些方向是用户已经在看的。

## Goals And Non-Goals / 目标与非目标

目标：

- 九项能力独立发布、独立关闭；关闭不删数据。
- 不改现有 Wails 导出方法签名、事件名、随机算法、布局与信息层级。
- 所有新表在 SQLite 与 Postgres 上都通过既有双后端测试基座。
- 除既有 AI 接口与显式模型下载外不新增网络出口；人脸数据、帧、字幕正文不出本机。
- 代码健康：四个巨型文件拆分，行为完全保持。

非目标（沿用 requirements.md）：手机端 Jellyfin / 浏览模式 / PIN；联网元数据；改随机算法；DeepL 术语表 API；实时转码；替换或删除原文件；人脸不经审阅自动关联；作品集覆盖图片；Rust/SwiftUI 重写；三栏布局；超分 P-013 真机验收与未提交文件的提交。

## Proposal / 设计方案

### 1. 转封装：代理文件是派生缓存，不是媒体

**规则**：每个视频最多一份代理，放 `~/.CineInsight/proxies/<videoID>-<源指纹前 16 位>.mp4`；`video_playback_proxies` 记录 video_id（唯一）、源 size+mtime 指纹、策略（remux / transcode）、产物大小、状态、`last_used_at`。代理不进 `videos`、不建同源关系、不写用户目录。

**例子**：`Show.S01E01.mkv`（H.264 + AAC）→ 触发后 3 秒内产出 `proxies/1042-3f9a….mp4`；`GetPreviewSession(1042)` 返回 `mode=inline`，`/preview/media/1042` 服务的是代理字节；手机端 `/short-media/video/1042` 同样。`videos` 表行数不变。

**边界**：源文件 size 或 mtime 变化 → 代理立即失效并删除，预览退回今天的行为；视频记录软删除或永久删除 → 代理连带删除；代理缺失时所有路径与今天完全一致。

**编码策略**：技术快照（`ffprobe`）已在库里。视频流为 H.264/HEVC 且音频为 AAC/MP3 → `ffmpeg -c copy` 只换容器（秒级、无损）；否则 VideoToolbox H.264 + AAC 转码，不放大，高于 1080p 缩到 1080p。代理只服务预览与手机端，remux 路径已保全质量；需要转码的编码（Xvid、RMVB、WMV）几乎不存在 4K 素材，1080p 上限的代价接近零。

**体积**：`ProxyCacheLimitBytes` 默认 50 GiB，0 表示不限。新代理写入后若总占用超限，按 `last_used_at` 最早者依次删除直到不超限；正在被预览会话或手机端请求引用的代理不在本轮淘汰。被淘汰的视频退回无代理行为，再次触发可重建。`last_used_at` 在预览会话建立与手机端媒体请求时更新，写入节流到每视频每分钟最多一次，避免手机端逐段 Range 请求把表打爆。

**触发**：详情抽屉与右键菜单单视频；对当前筛选或选中批量；`AutoCompatibilityProxy` 开关默认关，开启时进入后扫描自动化并受空闲调度门控。

**新行为 vs 不变行为**：新增的只有「代理存在时预览与手机端换源」。预览的统计语义（内嵌预览不计播放）、外部预览降级、失效标记、缩略图与 sprite 全部不变。

### 2. 播放历史：账本只追加，计数列照旧

**规则**：`play_events(id, video_id, played_at, source, created_at)`，`source ∈ {desktop_play, desktop_random, mobile_feed, legacy}`。只在今天已经递增计数的三处各插一行：桌面正式播放、桌面随机播放（`video_service.go:2500-2504`）、手机端 Feed 播放（`short_feed_service.go:550`）。内嵌预览、IINA 断点回读、观看进度更新都不产生事件——它们今天也不动计数。

**为什么不改计数列**：`play_count` / `random_play_count` / `last_played_at` 是随机算法的输入，requirements.md 明确本批不改算法。账本与计数并存，账本服务统计，计数服务算法，两者由同一个事务写入。

**迁移**：为每个 `last_played_at` 非空的视频回填一条 `legacy` 事件，幂等（存在则跳过）。不回填的话热力图会在升级当天清零，这比「legacy 事件时间不精确」更糟。

**边界**：视频永久删除时级联删事件；软删除保留（历史统计仍计入，与 AI 质量评估对软删除的处理一致）；保留期无限，一行 40 字节左右，十万次播放也只有几 MB。

### 3. 通知与角标：第一个 cgo 文件，隔离在 build tag 后面

**规则**：`services/desktop_notify_darwin.go`（`//go:build darwin`）用 cgo 调 `NSUserNotificationCenter` 发通知、`NSApp.dockTile.badgeLabel` 设角标；`desktop_notify_other.go` 是空实现。触发清单固定：字幕生成完成/失败/需确认幻觉、超分完成/失败、转封装批量完成、备份失败、语义索引完成/失败、人脸分析完成/失败。窗口在前台时不发系统通知，只走既有 `AppFeedback`。`DesktopNotificationsEnabled` 默认开。

**角标**：一个进程内的 `BackgroundTaskRegistry` 记录运行中的后台任务数；各长任务服务在 start/finish 时登记。角标 = 该计数，0 时清空。

**为什么接受 cgo**：`osascript display notification` 能发通知但发件人显示为 Script Editor，且没有任何 exec 途径能改 Dock 角标。Wails v2 在 darwin 本来就要求 cgo 工具链，增加一个 40 行的 `.m` 桥接不改变构建要求。用 build tag 隔离后 Windows/Linux 构建不受影响（image_library 曾因平台隔离出过一次基线遗留，本次直接按 `*_darwin.go` / `*_other.go` 对拆）。

### 4. 人脸识别：本地 sidecar，簇进审阅台，人物覆盖两种媒体

**人物覆盖图片（用户裁决）**：新增 `image_people(image_id, person_id)`，与 `video_people` 完全对称（复合主键、级联删除）。`ImageFilter` 加 `PersonIDs`；人物详情增加「图片」区块，与「视频」区块分开分页，不混排；「删除最后一条关系时确认并清理人物」的语义对两种媒体一致——判定条件变成「视频关系与图片关系都为零」。

**为什么是对称并行表而不是多态 `media_people`**：手机端交互表已经用「并行表 + 服务层分派」验证过零迁移风险（`docs/short-feed-lan.md`「互动与回写」）；多态表会让现有 `video_people` 的 21 处读写全部改写并迁移数据，收益只是少一张表。

**运行时**：托管 Python sidecar，InsightFace 检测 + ArcFace 512 维向量，onnxruntime（Apple Silicon wheel 走 CPU，可选 CoreML EP）。管理方式对齐 WhisperX：托管 Python、venv、显式模型下载、镜像可配（本机直连 GitHub 不通）、manifest sha256 校验；运行时未就绪时入口置灰并说明原因，与语义检索不可用的处理（P-008）一致。

**为什么不是 Go 原生 ONNX 或外部 API**：Go 侧 onnxruntime 需要 cgo 链接动态库并随应用分发，比 Python venv 更难打包签名；外部多模态 API 做不了稠密人脸向量，且把人脸送出去与本仓库一贯的数据外发边界冲突。

**数据**：`face_observations`（media_kind, media_id, frame_ms nullable, bbox, quality, embedding BLOB 2048 字节, 源指纹）、`face_clusters`（代表观测、person_id nullable、状态 unnamed / named / ignored）、`face_person_candidates`（cluster → person 建议与置信度）。向量以 BLOB 存、余弦相似度在 Go 侧算：十万张人脸 × 512 维暴力比对在 M4 上是百毫秒级，不值得为它引入 pgvector 依赖——而且 SQLite 后端根本没有 pgvector。人脸裁剪缩略图放 `~/.CineInsight/faces/`，只经受控路由 `/preview/face-crop/{id}` 读取。

**证据来源**：视频复用 AI 打标抽帧（每分钟 1 帧、至少 10 帧、5%–95%，`ai_tagging_extractor.go:148`）；图片走既有解码矩阵产出 JPEG（RAW/HEIC 经 sips）。

**审阅**：分析任务单 worker、按源指纹跳过已分析项。聚类结束后未命名簇进入待审工作台新 section「人物候选」（视频侧在 `AITagReviewDialog` 与 tags / same-source 并列；图片侧对应面板）。三个动作：命名为新人物、关联到现有人物、忽略。人物已有头像时用头像向量给「可能是 X」建议。**绝不自动写关系**；忽略的簇持久化，源指纹不变不再提示。

**隐私**：向量与裁剪图只在本地；设置页披露并提供「清除全部人脸数据」——删三张表与裁剪目录，不影响已确认的 `video_people` / `image_people`。`AutoFaceAnalysis` 默认关。

### 5. 建议作品集：候选表 + 忽略表，不碰标题

**规则**：同一扫描根、≥2 个文件、文件名命中剧集模式之一（`SxxEyy`、`第 N 集/话`、`EP/E NN`、`[NN]`、` - NN`）且去掉集号后的系列名规范化后相同 → 一条 `collection_suggestions`（系列名、成员与集号、状态）。确认时复用 `CreateCollection` + `AddCollectionVideos` + `ReorderCollectionVideos`。已在任何作品集中的视频不再建议；忽略持久化。任何视频的 `display_title` / `name` / 文件名都不动。

**例子**：`Show.S01E01.mkv`、`Show.S01E02.mkv`、`Show.S01E03.mkv`、`random-clip.mp4` → 一条建议「Show」含三个成员按 E01/E02/E03 排序；`random-clip.mp4` 不出现。

### 6. 截取片段：新的逐帧序列表，现有三点 pHash 不动

**规则**：`video_frame_hash_sequences(video_id, interval_ms=2000, hashes BLOB, 源指纹)`；独立回填任务，`AutoFrameHashSequence` 默认关。判定：B 时长 ≤ A 的 90%；把 B 的序列在 A 的序列上滑动，某偏移处逐点汉明距离 ≤ 10 的比例 ≥ 70% 则成候选；阈值为常量并由 fixture 钉住。进清理中心新类别「截取片段」，并排 A/B、显示对齐偏移与命中率，默认建议保留较长者，**默认不勾选**；删除走回收站；忽略持久化。

**为什么不复用三点 pHash**：三个点无法表达「B 从 A 的第 37 分钟开始」；序列子序列匹配需要按固定间隔覆盖全片。2 秒间隔下两小时电影只有 3600 × 8 字节。

### 7. 命令面板：注册表驱动，不硬编码

⌘K 打开、Esc 关闭、方向键 + 回车。三组条目：导航（页面、智能视图、保存视图、作品集、人物）、动作（扫描、随机、立即备份、各后台任务的启动/取消、打开设置分区）、视频快速打开（复用既有文件搜索）。动作由各页面向一个前端注册表登记，面板只渲染注册表。它是 `BaseModal` 之上的独立组件，不触碰任何现有 DOM 结构。

### 8. 空闲调度：一个集中门，只挡自动任务

**规则**：`IdleGate` 是进程内单例，`runPostScanAutomation` 与各自动唤醒路径在调用 `Start` 前先 `gate.Acquire(ctx, taskKey)`；用户显式点击启动的任务不经过门。空闲判定 = 无键鼠输入 ≥ N 分钟（macOS `ioreg -c IOHIDSystem` 读 `HIDIdleTime`，exec 实现，非 darwin 视为始终空闲），可叠加「仅接电源」（`pmset -g batt`）与时间窗。运行中用户变活跃：单 worker 在项与项之间检查门，当前项完成即暂停并把状态标为 `waiting_idle`，再空闲时续跑。每个任务面板有「忽略空闲立即运行」。默认开、N=5 分钟。

**为什么不改每个服务**：门放在启动路径而不是服务内部，服务只多一个「项间检查点」回调；服务的 Start/Cancel/Status 契约不变。

### 9. 术语表与上下文：只改提示词，不改协议

**规则**：`translation_glossary_entries(source_term, target_term, note, collection_id nullable)`，`(collection_id, source_term)` 唯一。只注入 OpenAI 兼容翻译器的提示词：术语表区块（作品集级覆盖全局级同源词）+ 前一批尾部 5 条原文/译文作为只读上下文，提示词明确「上下文条目不要翻译、只返回本批」；返回条数校验仍以本批为准。DeepL 请求体不变，设置页明示「术语表不适用于 DeepL」。字幕生成与工作台选区重译两处调用都生效。

### 10. 代码健康：拆文件不改行为

`app.go` 按领域拆为 `app_video.go`、`app_image.go`、`app_ai.go`、`app_subtitle.go`、`app_settings.go`、`app_tasks.go` 等同包文件，`App` 结构体与全部方法签名不变——Go 允许方法分散在同包多文件，`wails generate module` 后 `frontend/wailsjs` diff 为空就是证据。`video_service.go` 按关注点拆文件。`VideoListPage.vue` 是 Options API（模板 906 行、样式 837 行、脚本 3130 行），抽出清理审阅、字幕预览/生成弹窗、超分弹窗、三个重命名/保存视图弹窗、批量操作栏、后台任务状态条为子组件；保留全部 `data-test` 钩子与事件名。`SettingsPage.vue` 按分区拆。暗色字面色改令牌；Windows 字幕依赖下载 TODO 收口为明确「不支持」错误；README/GUIDE 标注 macOS 专属能力。

## Boundary Scenarios / 边界场景

| 类别 | 场景 | 处理 |
|---|---|---|
| 无效/过期输入 | 代理创建时源文件已被替换 | 创建前后核对指纹，不一致则丢弃产物并报 `source_changed`，不写表 |
| 无效/过期输入 | NFO 式脏文件名（`[Group] Show - 03v2 [1080p].mkv`） | 模式解析去掉方括号组名与质量标签后再匹配；`v2` 视为同集，两个版本同集时只建议一次并标注 |
| 权限 | `~/.CineInsight/proxies/` 不可写 | 任务失败并报路径与错误；预览退回今天行为 |
| 重复/幂等 | 同一视频重复触发转封装 | 已有有效代理直接返回 `already_exists`；进行中返回 `in_progress` |
| 重复/幂等 | legacy 回填重跑 | `NOT EXISTS (source='legacy' AND video_id=?)` 才插入 |
| 重复/幂等 | 同一人脸簇被两次命名 | 第二次返回冲突，前端刷新簇状态 |
| 并发 | 代理淘汰与正在播放的手机端请求 | 淘汰跳过 `last_used_at` 在 60 秒内的代理；请求方 open 成功后即使文件被删也能读完（Unix 语义） |
| 并发 | 空闲门放行后用户立刻活跃 | 单 worker 只在项间检查；当前项做完再暂停，不中断 ffmpeg |
| 并发 | 人脸分析与图片删除 | 观测写入前重查 image 存在；外键级联清理孤儿 |
| 部分失败 | 批量转封装 30 个成功 2 个失败 | 逐项结果；成功的代理保留；失败项可重试 |
| 部分失败 | 人脸 sidecar 中途崩溃 | 已写观测保留；重启按源指纹跳过；任务状态 `interrupted` 可续跑 |
| 依赖超时 | `ioreg` / `pmset` 调用失败 | 视为「不空闲」并在状态里报原因，不放行也不死锁；用户可立即运行 |
| 依赖超时 | 模型下载中断 | 临时文件删除、状态 `download_failed` 带来源 URL；重试从头 |
| 遗留数据 | 旧库无 `last_played_at` 的视频 | 不回填 legacy 事件 |
| 遗留数据 | 现有 `people` 头像质量差、检不到脸 | 不生成种子向量，只走无建议的簇 |
| 迁移重叠 | 用户在 SQLite ↔ Postgres 之间用双向迁移器 | 新表进入 `AllModels()` 即被迁移器覆盖；BLOB 列两端类型对齐（`bytes`） |
| 回滚 | 关闭任一功能开关 | 停 worker、藏入口；表与文件保留 |
| 回滚 | 回退到旧版本应用 | 新表被忽略；`settings` 新列被忽略；代理目录成为死文件，用户可手工删 |
| 限值 | 术语表 5000 条 | 提示词只注入命中本批原文的条目（子串匹配），不是全表 |
| 限值 | 代理上限设为 0 | 表示不限，不触发淘汰 |
| 空状态 | 命令面板无注册动作 | 显示导航组即可，不报错 |
| 不变行为 | 无代理时的预览、手机端、统计 | 与今天逐字节一致，由现有测试钉住 |
| 不变行为 | 随机算法 | 计数列不变、公式不变，回归用例比对分数序 |
| 不变行为 | 精确重复/近重复/同源候选 | 新类别独立计算，旧三类结果与本批前一致 |

## Rationale / 理由与取舍

| Alternative | Why Not |
|---|---|
| 转封装产物入库为新记录（同超分） | 片库出现成对条目；清理中心会把它们当同源候选；用户裁决否决 |
| 原地替换原文件 | 破坏性；对用户媒体目录写入需逐次确认；用户裁决否决 |
| 代理不设上限 | 用户裁决要上限 + LRU |
| 用事件表替代计数列驱动随机算法 | 需改算法与游标分页排序键，requirements 明确本批不改算法 |
| 通知用 `osascript`、不做角标 | 通知发件人显示为 Script Editor；角标没有 exec 途径 |
| 人脸用 Go 原生 onnxruntime | cgo 链接动态库、随应用分发与签名成本高于 venv；仓库已有 Python 运行时管理先例 |
| 人脸向量存 pgvector | SQLite 后端没有 pgvector；十万级暴力比对在 Go 侧足够快 |
| 多态 `media_people(media_type, media_id)` | 需迁移 `video_people` 并改写全部读写；并行表零迁移（短视频交互表先例） |
| 人脸只做视频 | 用户裁决选了视频 + 图片 |
| 截取识别复用三点 pHash | 三个点无法定位子序列 |
| 空闲门下沉到每个服务内部 | 改动面大且每个服务契约都变；集中门只改启动路径 |
| DeepL 术语表 API | 需创建/同步远端 glossary 资源；本批非目标 |
| `app.go` 拆成多个 Wails 绑定结构体 | 会改前端绑定路径（`wailsjs/go/main/App` → 多个），违反「签名不变」 |

## Compatibility / 兼容性

**纯加法，不破坏。**

- 现有 Wails 导出方法签名、返回结构、事件名全部不变；新增方法与事件另起名字。
- `settings` 新列全部有默认值；默认为 true 的布尔列（通知、空闲调度）沿用 `migrateLibraryWatchSetting` 模式：表已存在且列刚创建时显式 `UPDATE`，避免 GORM 零值把默认写成 false。
- 七张新表进入 `models.AllModels()`，双向迁移器自动覆盖。
- 代理、人脸裁剪图、模型缓存都在 `~/.CineInsight/` 下，用户媒体目录零写入。
- 旧版本应用打开新库：忽略新表新列；代理目录成为无引用文件。
- 前端：无布局变化；命令面板、人物候选、建议作品集、截取片段、术语表都是新组件或新 section。

**唯一的语义重开**：人物覆盖图片。这是 2026-08-07 Round 2 的裁决被用户在 2026-09-02 Round 2 明确替换，记录在 `clarification.md`。

## Operational And Security Impact / 运行与安全影响

- **磁盘**：代理默认上限 50 GiB 可调；人脸裁剪图每张约 10 KB；帧哈希每视频约 30 KB；事件表可忽略。设置页显示代理与人脸数据占用。
- **CPU/GPU**：转封装、帧哈希、人脸抽帧共享一个 `MediaWorkSlot`（容量 1），任何时刻最多一个重 ffmpeg 任务；自动触发的全部受空闲门。超分 sidecar 与字幕转写各有自己的槽，不并入（避免一个 3 小时超分挡住 3 秒 remux）。
- **网络**：仅新增「显式人脸模型下载」一个出口，镜像可配、来源 URL 展示、sha256 校验；其他一切本地。
- **隐私**：人脸向量与裁剪图不出本机；日志只记计数、耗时、状态；「清除全部人脸数据」一键删除。手机端 Feed 换用代理不改变其无鉴权边界（既有已接受边界）。
- **cgo**：第一个仓库自有 cgo 文件；`go vet` 与 `go test` 在 macOS 上覆盖，非 darwin 用 `_other.go` 空实现保证可编译。
- **可观测**：每个新任务有 `*-state` 事件与状态查询；`BackgroundTaskRegistry` 是角标与命令面板的共同数据源。

## Implementation And Transition / 实现与过渡
