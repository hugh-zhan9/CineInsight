## 2. 应用内字幕

<a id="D-F01"></a>
**D-F01 · Behavior / Interface Contract · 已接受并实施。** 来源：同名外置字幕不能进入应用内播放。归属 SubtitleService/工作台读取逻辑；调用方为详情播放器与队列播放器。

桌面绑定 `GetPlaybackSubtitle({video_id, source_version, queue_token?})`，返回以下互斥状态：

| 状态 | 返回内容与处理 |
|---|---|
| `ready` | `subtitle_fingerprint`、`cues[{start_ms,end_ms,text}]`；正文只作为字幕文本处理 |
| `absent` | 没有同名 SRT；显示无外置字幕，不启动任何生成任务 |
| 读取失败 | 编码、解析、权限、源变化分别报错；保留视频播放，明确字幕不可用，不冒充 absent |

`video_id` 必须是当前可读取的活跃视频；`source_version` 采用既有视频源版本。队列请求额外校验当前 inline token、video ID、源版本；token 失效不能读取或贴回新会话。客户端不能提交字幕路径。不增加局域网公开路由。

读取复用工作台的有界文件读取、UTF-8 校验与严格解析，沿用 `MaxEditorFileBytes` / `MaxEditorSegments`；校验阻断项不静默丢弃。读取前后核对文件指纹，遇文件修改要求刷新，不把两个版本拼在一起。两种播放器共享「cues → WebVTT Blob → track」的前端模块，卸载或切换时撤销 Blob URL、丢弃旧请求；不能把字幕文本拼为 HTML。

默认显示可用字幕；提供开关及当前会话偏移，范围 -60 至 +60 秒、步长 0.1 秒，正数表示更晚显示。偏移后负时间裁到 0，整个区间早于 0 的条目仅在播放投影中略过，原文件不改。退出会话重置偏移。双语两行保持原顺序。字幕更新只换 track，不换视频 src，不重置断点、计数或队列 token。

所有经字幕写入器成功替换的路径发 `subtitle-changed`，两种播放器重新读取；共享同名 SRT 的视频也会刷新。外部编辑通过「刷新字幕」刷新，不增加全目录监听。真实 WKWebView 合成夹具已验证两类播放器的 Blob track、双语纯文本、偏移及同源重建；最终集成复验也已通过，证据与设备限制见第 12 节。

## 3. 自动关联失效与纠错

<a id="D-F02"></a>
**D-F02 · Data / Behavior Contract · 已接受并实施。** 来源：更正视频资料后旧自动关联仍显示。复用 WatchlistService；不建立第二份作品身份表。

| 场景 | 预期行为 |
|---|---|
| 已自动关联，视频片名/原名/文件名/年份改变 | 重新检查原关联，并对受影响条目计算候选 |
| 原对象仍符合完全相等、同年、唯一作品 | 保留原关联，不无故更新关联时间 |
| 原对象不匹配，或当前出现多个不同作品 | 原 auto 关系失效；唯一新候选可重建，否则显示建议或未匹配 |
| manual 或 dismissed | 不由自动对账修改；仍保留既有榜单读写规则 |
| 仅离线、暂时不可读 | 不因一次 IO/数据库失败撤销关系；区分关联身份与当前可播放性 |
| 版本合并、拆分、成员调整或来源补全改变 | 纳入输入变化触发，重新判断作品唯一性；人工解除仍按作品生效 |

视频资料及版本关系变动复用现有防抖和单轮合并，批量对账条目及历史 auto 关系，不再跳过所有已有链接的条目。实际实现按每批 500 条目处理；年份去重后分段，视频每批 500 行先筛完全标题命中，再有界读取版本代表；同一规范片名/年份保留至多两个作品即可判定歧义。启动同样分批对账，不在 schema 迁移里改写用户关联。版本创建、成员变动、解散及独立提交的不足两成员清理均在提交后通知。

读取 `ListLibraryState` / `ListInLibrary` / 对应分页时，对 auto 关系做同一校验：在同一数据库读快照内获取条目、相关视频、版本身份和候选唯一性。自动关系无效即不投影为已在库；人工关系不受标题纠正影响。读失败保留错误状态，不能返回空列表伪装未匹配。查询须批量取数，不能每条片单再扫一次全库。

写侧用事务与条件 DML：只删除本轮读到且 `origin=auto`、行身份及 `updated_at` 仍匹配的旧行；已被改成 manual/dismissed 时零行退出。插入沿用唯一键 `ON CONFLICT DO NOTHING`，已有人工行优先。无需应用控制的数据库锁。跨表输入在读后仍可能变化，故不承诺「写入瞬间永不陈旧」：读取校验负责不展示当前读快照内已失效的 auto，后续事件负责收敛。不能仅凭事务包裹就宣称已解决并发。

自动纠错不写 `movie_video_links`，不删除想看条目，不标记榜单已看，不改视频观看状态。若目标变化仅影响可播放性，沿用既有离线展示，不把它升级为身份不匹配。

## 4. 作品级选片

<a id="D-F03"></a>
**D-F03 · Behavior Contract · 已接受并实施，替代旧合同对应条款。** 来源：随机候选可能是同作品多个文件。只改变随机播放、随机 N 部、今晚看什么及首页同源推荐；继续观看、字幕命中、清理、批量文件任务不改。

作品键为已确认 `version_group_id`，无组则为 `video_id`，使用不同类型避免 ID 碰撞。组变化按每次请求的读快照确定；不承诺跨多个请求冻结版本关系。

| 数据 | 当前计算口径 |
|---|---|
| 可选版本 | 现有扫描/黑名单/非失效及 LibraryFilter，再叠加收藏与时长等文件条件；至少一项满足才纳入作品 |
| 已看/未看条件 | 在当前允许访问范围内，任一未删除版本已看则作品算看过；离线但仍在该范围的历史成员也参与已看判断，避免拔盘后变成「没看过」 |
| 代表版本 | 可选版本中按既有版本 position、video ID 取首位；不从不符合筛选的主版本起播 |
| 作品权重 | 对允许访问范围内未删除成员计算现有时间衰减播放分数，取最大值；沿用现有「分数越低权重越高」换算，不按版本个数求和或增加抽签次数 |
| 近期排除 | 现有 `exclude_ids` 在服务端扩成当前作品身份；换一个与换一批排除整部作品 |
| 播放记账 | 仍只写实际播放的 video ID；组本身没有播放计数，读取推荐不写观看事实 |

最大分数的取舍：看过较多的一个版本会降低整部作品的探索机会；增加一个零播放版本不会立即让作品重新变成高权重。这是已接受的选片规则，不迁移或修正历史计数。没有版本组且无推荐反馈时，候选和权重与旧算法一致。

不把 `LibraryFilter.collapse_versions` 变成随机行为开关：随机入口统一使用作品语义，前端展示偏好不应改变概率。请求中的硬条件和 smart_view 若互相矛盾，返回无候选，不放宽。容量少于 N 返回全部符合的不同作品；零候选沿用已有明确空态/失败。延迟记账、换一个令牌、正式播放失败处理保持现有规则。

默认不增加表。既有本机最近 ID 记录按读取时组关系展开，无需伪造新历史；组解散后无法追溯过去整组身份，是本阶段明确限制。若以后需要跨组变更的推荐历史，再另立数据合同。

## 5. 失败明细与选择性重试

<a id="D-F04"></a>
**D-F04 · Data / Operational Contract · 已接受并实施。** 首批覆盖 AI 视频打标、技术信息补全、播放代理；其他任务保留现有单项重试，不承诺一次统一所有任务。

当前 AI 状态、技术信息最近探测错误与代理记录继续决定「当前仍失败」。新增 `task_failure_runs` 与 `task_failure_items` 保存诊断区间和完整失败明细，不接管 worker；task_key 为 `ai_tagging`、`technical`、`proxy`：

| 实体 | 实际字段与约束 | 所有者与用途 |
|---|---|---|
| run | `id, task_key, started_at, finished_at?, state, records_complete` | 所属服务记录诊断批次；state=running/completed/cancelled/interrupted |
| item | `id, run_id, media_kind, media_id, attempt_key, source_version, state_version, error_code, error_summary, failed_at` | append-only 失败事实；(run_id, attempt_key) 唯一，索引 (run_id,id) |

AI 连续 worker 在每次启动到停止之间作为一个诊断批次，界面明确时间范围，不叫「本次全库处理完成」。`attempt_key` 依据原服务的媒体与失败状态身份稳定生成，同一次失败重复上报不新增记录；`state_version` 是认领时复核的失败身份，调用方不能用新读到的失败替换冻结版本。媒体 ID 为逻辑引用，不因原片删除而抹掉历史；不复制字幕正文、凭证或外部模型响应。错误说明按既有脱敏规则保存。

run 的合法转换为 running → completed/cancelled/interrupted。启动把遗留 running 改 interrupted，并将 `records_complete=false`：进程可能在原服务失败提交后、诊断追加前退出，不能证明尾部记录完整。只恢复诊断状态和清除技术/代理遗留 claim，不自动重新排队。其他状态转换拒绝，读取不建 run。记录写失败同样标不完整并在任务中心告警；该区间已存明细仍可读，但批量预览拒绝，原单项重试入口保留。

提供 `ListTaskFailures({task_key,run_id,cursor_id,limit})`，默认 50、最大 200，返回 items、total、next_cursor、records_complete。明细摘要仍可只露前 50；展开走分页，不把全部错误塞进事件。历史上线前没有保存的明细不回填冒充历史；可另列「当前失败」查询。

批量重试先预览，冻结 `(item_id, media_id, attempt_key, source_version, 当前失败状态版本)`；确认仅消费本次令牌。`PreviewTaskFailureRetry({run_id,item_ids?})` 返回 `token,eligible_count,skipped_count,expires_at`，省略 item_ids 表示该批全部失败，显式空数组表示没有选择、拒绝执行；`ConfirmTaskFailureRetry(token)` 返回批量操作 ID，后续分页读取逐项结果并通过原任务中心显示进度。令牌无效、过期或记录不完整分别报错，不在确认时扩大集合。复用 AI 批量审批的「预览—确认—后台进度」交互模式，但不复用批准标签的业务状态机。预览令牌有效 10 分钟、至多保留 2 份，成员上限 100 万；超限拒绝，不截断后称全部。另有 `ListTaskFailureRuns(task_key)` 返回区间与告警；`GetTaskFailureRetryResults(operation_id, offset, limit)` 返回提交状态、accepted/skipped/failed 汇总、items 和 next_offset（默认 50、最多 200），`CancelTaskFailureRetry(operation_id)` 停止尚未提交项。令牌和提交结果只在本进程保留，重启失效；确认新操作时裁剪旧完成结果，操作存量上限为 4。

执行前逐项向原服务重新确认：

| 当前状态 | 结果 |
|---|---|
| 同一次失败、同一源，尚未重排 | 原服务条件认领后入队；返回 accepted，不宣称处理成功 |
| 已成功、已排队/运行、失败已更新 | skipped，并说明具体原因；不重复触发 |
| 删除、范围外、离线或源版本改变 | skipped，提示恢复文件或重新分析；不拿旧授权处理新文件 |
| 入队失败 | failed；其他独立项继续，展示实际汇总 |
| 用户取消或进入维护 | 停止尚未提交的入队；已接受项按所属服务原有取消/维护流程处理 |

双击确认不得产生第二批；来源服务以失败 attempt/version 做条件更新，同一次失败仅认领一次。批量结果的 accepted/skipped/failed 与随后任务运行成功/失败分开展示。不增加隐式自动重试。

原 owner 的授权数据如下，三列均为 `NOT NULL DEFAULT ''`、长度 64；不把诊断表当作队列状态源：

| 所有者表 | 字段与使用 |
|---|---|
| `ai_tagging_states` | `failure_retry_source_version` 随显式重试写入 pending，实际分析前复核；源变改 skipped/source_changed，不发 AI 请求。普通重新分析清旧授权，内部标签库变化重排保留冻结源 |
| `video_technical_metadata` | `failure_retry_claim` 按原失败版本条件认领，不改失败 updated_at；取消未执行项按本次 claim 和原身份释放 |
| `video_playback_proxies` | 同名 `failure_retry_claim`，与原代理入队互斥；成功、失败、取消或启动恢复按 owner 清理 |

技术补全先短锁预约 Preparing，再执行可取消的逐项认领，状态读取与取消不被整批数据库查询堵住；已有一轮运行时返回 already_running，不把旧授权偷偷并进全库补全。技术/代理队列中还保留冻结源，真正取得每视频 probe gate 后、runner 前再次核对；换文件即跳过。携带冻结源但尚未执行的取消只返回取消，不沿用普通 Refresh 的取消记账去覆盖新源失败。普通 Refresh 原语义保留。

每类保留最近 20 个已结束且无当前未解决失败的诊断区间；运行中、不完整、取消/中断后仍有失败的区间保留。清理批次与明细同事务提交，后台清理由 store 负责取消和等待。历史上线前没有完整记录的失败不冒充某次诊断区间；原摘要上限继续用于事件和旧面板，新增分页读取持久化的完整记录。

## 6. 精确 IINA 播放

<a id="D-F05"></a>
**D-F05 · Interface / Operational Contract · 已接受并实施。** 来源：普通 IINA 断点文件观察不能可靠证明自然结束。采用明确选择的新播放模式，不改变原系统播放器派发路径的默认行为。

`controlled_iina.go` 提供从原队列实现提取的无数据库、无队列顺序受控播放器适配，负责启动本进程、握手、装载、位置/暂停/seek/EOF 事件与停止；普通 VideoService 播放 owner 和 PlaybackQueueService 分别消费事件。不能为了复用而让普通播放修改 `playback_queue_states` 或 entries。

沿用已验证的私有 socket、独立进程、path/playlist-entry/source-version 校验、15 秒握手与 5 秒控制命令期限。仅真实位置推进进入观看累计；EOF 是完成候选，沿用当前媒体身份与 seeking 复核。暂停、关闭窗口、进程错误、IPC 断开、换入别的文件都不是完成，也不推进队列。不可用时明确失败，用户可以重新选择系统播放器，不自动外派。

`settings.desktop_player` 为空或 `system` 时保留原路径，显式选 `iina_controlled` 才进入精确同步。普通受控会话唯一 token 归 VideoService 的播放 owner；队列仍归队列 owner。普通受控播放与全部队列播放器类型共享准入占用，不能相互抢占；两者各自拥有专用进程。普通会话默认一次一个，开始新会话前停止自己上一会话；不终止用户自行打开的 IINA。队列正在播放时，新普通受控播放不得静默抢占，提示先停止队列或继续使用队列入口。

| 转换 | 守卫与效果 |
|---|---|
| idle → starting | 已明确选择精确模式；校验源与维护准入 |
| starting → playing/paused | 当前 token 握手成功；之后允许上报观看事实 |
| playing ↔ paused | 实际 pause 属性变化，不增加播放次数 |
| playing → ended | 当前 token、当前观看 cycle 的 EOF 复核成功；一次性结算 |
| 任意活动态 → stopped/failed | 用户停止、身份改变、进程错误或维护；作废 token，拒绝迟到回调 |
| ended → playing | 用户实际重播，建立新的观看 cycle；不冒充新派发 |

正式起播计数沿用原 PlayVideo / 随机延迟记账，不叠加队列派发；有效观看增加可识别的 `desktop_controlled_view` 来源，复用 VideoService 的会话去重与日记事务核心。所有枚举消费者、回顾、导出与数据迁移清单同步检查，不把此来源伪装成 inline_view 或 queue_view。私有 watch_later 不交给旧 IINAProgressService 再次推断。

维护与退出先关闭准入、取消握手并等待回调，再停止自有进程；关闭成功前不丢失 process/run/占用。关闭失败保留清理对象并中止维护推进，界面显示「操作未完成」和「重试停止」；队列失败也保留实例，以独立清理 token 重试，迟到的旧 Stop 不能停止新实例。暂停不累计观看时长、不新增正式派发，原生重播开启新观看 cycle。重启不自动播放。真实 IINA 合成样片的普通短片、暂停、结束、重播和换片已有定向证据；最终集成复验已通过，设备相关限制见第 12 节。

## 7. 提取已有文字字幕

<a id="D-F06"></a>
**D-F06 · Behavior / Interface Contract · 已接受并实施。** 来源：内嵌字幕不能进入已有 SRT 工作流。归属字幕服务，复用 ffprobe 轨道信息、FFmpeg 有界子进程、字幕写入器及既有覆盖信息。

`ListExtractableSubtitleTracks(video_id)`，返回轨道绝对序号、语言、标题、codec、是否支持及不支持原因；不让前端提交文件路径。当前支持 codec 白名单 `subrip`、`srt`、`mov_text`、`ass`、`ssa`、`webvtt`、`text`；其他格式及 PGS/VobSub 等图片字幕明确不支持。ASS 样式转换为 SRT 会丢失，轨道选择时明确说明。

`PreviewSubtitleExtraction({video_id,source_version,track_index})` 只提取所选绝对轨道为隐藏临时产物，严格解析后返回 token、entries、expires_at 及源/目标指纹；预览有效 10 分钟，最多保留 2 份。`ConfirmSubtitleExtraction({token,video_id,source_version,track_index,target_fingerprint})` 消费一次性预览，目标不存在也以零指纹作为条件，并复核隐藏预览文件的指纹；源变或目标被外部修改时拒绝写入，要求重做预览。FFmpeg 只映射所选字幕轨，不能转码原视频。

输出只有现有同名 `.srt`。覆盖前调用 `GetSubtitleOverwriteInfo`，显示共享同名文件影响范围；最终写入持既有字幕锁，并通过 `SubtitleFileWriter.Replace` 备份、原子替换与恢复权限。原片和已有字幕在校验成功前保持原样。成功刷新字幕索引和当前播放器；索引失败沿用 saved_index_pending，不谎称原文件未写入。

`CancelSubtitleExtraction(video_id)` 取消提取或尚未发布的确认，并清理临时文件；确认等待共享 SRT 锁也可取消，维护 Quiesce 无需等另一个写入者释放锁。空结果、解析失败不发布，已完成的原子保存不因随后取消而回滚。不自动追加语言后缀、不启动 Apple Speech、不调用外部模型。与其他同名 SRT 写入的互斥必须按实际目标路径验证，不能因两个 video ID 不同而同时覆盖同一个 SRT。

## 8. 推荐反馈

<a id="D-F07"></a>
**D-F07 · Behavior / Data Contract · 已接受并实施。** 来源：当前条件与随机权重不能表达「暂时不看」和「少推荐这类」。依赖 [D-F03](#D-F03)，只作用于选片入口。

两种已接受动作：作品「7 天内不推荐」是硬排除；标签「减少推荐」是权重乘 0.5，长期有效直到撤销。标签由用户明确选择，不能把视频的所有标签自动降权；多个被降权标签同时命中仍只乘一次 0.5。临时反馈不改正式标签、收藏、评分或观看历史。

实际表名为 `recommendation_feedbacks`：`id, target_kind(work_video|work_group|tag), target_id, effect(snooze|downweight), expires_at?, revision, created_at, updated_at`，唯一键 (target_kind,target_id,effect)，索引 (effect,expires_at)。组合须校验：作品只允许 snooze 且期限非空，标签只允许 downweight 且期限为空。目标必须存在且可访问；`SetRecommendationFeedback({target_kind,target_id,id,expected_revision})` 的首次创建传 id=0、expected_revision=0，只接受 work_video 或 tag；work_video 在服务端解析当前版本组后记录作品身份。后续更新传管理列表的真实行 id 和 expected_revision（可为 work_group），按行身份与 revision 条件更新，创建冲突不自动续期。`ListRecommendationFeedback()` 返回标签、期限、revision、active；`RevokeRecommendationFeedback(id, revision)` 条件撤销，冲突刷新，不用数据库锁。

现有组收到暂避时记录 group ID；组内新增版本同样暂避，组解散即失效。单文件的反馈遇其加入组时，在查询阶段扩展到当前作品，移出后只影响原视频。软删、超出扫描范围或黑名单中的作品目标不作用于存活组成员；管理列表 active 与候选过滤共用有效性查询。离线但仍可访问范围内的身份保留。失效目标不作用于其他同名对象，界面可清理失效反馈。标签合并时归并同类反馈、删除时使其失效，不能给新建同名标签继承旧偏好。

选片先应用全部硬条件与暂避，再按现有作品权重乘降权系数。零候选显示哪些反馈在起作用，并允许用户主动撤销；不自动越过排除。解释文字只说明真实条件与反馈，不声称 AI 理解了情绪。首页、随机、今晚看什么共用后端规则，条件参数的既有差异继续保留。

提供「管理推荐反馈」列表与单项撤销；反馈存现有数据库、进入备份与后端迁移，不只写 localStorage。查询本身不写推荐曝光历史、不调用模型。

## 9. 剧集完整度

<a id="D-F08"></a>
**D-F08 · Behavior / Data Contract · 已接受并实施。** 来源：在已有季集识别、作品集与续播基础上检查缺集。首版是作品集内的资料检查，不新增在线追剧或下载系统。

解析复用 `ParseEpisodeFromFileName` 与既有目录识别；结果是建议。为纠正文件名误判，已新增作品集内季集覆写表 `collection_episode_assignments`：主键 (collection_id,video_id)，`season?、episode?、excluded、revision`。未覆写的继续动态解析；缺季号不是 S00，不默认为第一季。另加 `collection_season_expectations`：主键 (collection_id,season)，`episode_count>0、revision`，只存用户手填总集数。两表跟随对应作品集/成员关系删除，不按文件名认领重新导入的另一记录。

赋值与修改使用 expected_revision 条件更新；批量改集号必须单事务预检，冲突整批拒绝。解除成员、删除作品集须与覆写清理原子提交。`collection_episode_assignments` 以 belongs-to 复合外键 `(collection_id,video_id)` 引用 `collection_videos` 的同一复合主键，解除成员时级联；总集数外键指向作品集，软删作品集时在原事务显式清理。SQLite/PostgreSQL 已验证真实成员外键与级联。

| 输入 | 报告结果 |
|---|---|
| S01E01、02、04，总集数未知 | 已识别 3 集，中间编号空缺 E03；总集数未知，不推断 E05 以后 |
| 手填总集数 6，同上 | 空缺 E03、E05、E06；若发现 E07 则报预期范围冲突，不忽略 |

| S00 特别篇、没有季号的文件 | 独立分区，不参与其他季的缺集推断 |

用户尚未给总集数时，缺口只按同季、同一已确认系列的已知最小集号至最大集号之间计算，不把从 E05 开始的剪辑集自动报缺 E01–04。提供手填总集数后才以 1..N 检查。excluded 用于明确不参与完整度的花絮/预告，不删除文件或作品集成员。

报告读侧复用作品集成员、扫描范围和黑名单，保留离线成员，批量取元数据和版本关系。`GetCollectionEpisodeReport(collection_id,cursor,limit)` 默认 50、最多 200，返回 seasons、members、total、uncertain、mixed_series、next_cursor；cursor 是上一页成员 video_id。每季返回 recognized/playable/offline/duplicate_episodes、expected_count、revision、missing_ranges、range_conflicts。写入口为 `SetCollectionEpisodeAssignments(collection_id, edits)`（每项 video_id、season、episode、excluded、expected_revision；1–200项）及 `SetCollectionSeasonExpectation(collection_id,season,count,expected_revision)`；首写revision=0，后续必须匹配当前值。空缺用区间而不是生成上万个空卡片。现有「下一部」继续按用户作品集顺序，不根据新解析自动重排。报告与进度的差异必须标明：总收录包含离线，当前可播放不包含离线。
