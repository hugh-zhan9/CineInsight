## Abstract / 摘要

图片管理作为一条与视频管线完全并行的独立链路落地：独立 `images` 表族（`images`、`image_tags`、`image_directories`、`image_trash_entries`、`image_ai_descriptions`、图片语义索引三件套与 `image_semantic_vectors`），不给 `videos` 表加任何字段，不做多态外键，不重构任何现有视频路径。前端新增独立照片页（CSS Grid + IntersectionObserver 哨兵分页，首期不做网格虚拟化），与视频列表、视频搜索完全不混排。

解码链固定为：JPEG/PNG/GIF/WebP 走现有 ffmpeg 调用模式；HEIC/HEIF 与主流 RAW 仅在 macOS 上经系统自带 `sips` 解码为 JPEG（build tag 隔离，零新增外部依赖）；非 macOS 平台这些文件照常入库但无缩略图、显示占位。AI 对图片产出自然语言描述而非标签候选，复用现有 OpenAI 兼容 chat completions 多模态调用（`image_url` + base64 data URL）；描述文本进入现有文本 embedding 链路（`/v1/embeddings`），写入独立的 `image_semantic_vectors`（HNSW + cosine），语义检索入口只在照片页内部。

标签共享现有 `tags` 表。删除沿用全局回收站语义（同级 `trash/` 目录 + 可恢复条目 + 绝不覆盖）。清理审阅对图片提供精确重复（size + 采样 MD5，分析时实时计算）与近似重复（基于缩略图的 dHash，汉明距离阈值）两类候选。整个功能是纯增量变更：新表、新 API、新页面，现有视频功能的表结构、API 签名与可观察行为一律不变。

## Background / 背景与动机

用户磁盘上除视频外还有大量图片需要纳入管理。仓库调查（见 clarification.md 的 Brownfield Evidence）确认了三个事实：

1. 现有核心表 `videos` 挂着 17 张 `video_id` 外键关联表，扫描、清理、语义索引、回收站条目全部以视频为唯一一等公民；没有 `media_type` 字段。
2. 语义检索链路完全是文本的：`buildIndexText`（`services/semantic_index_service.go:528`）→ `/v1/embeddings` → `video_semantic_vectors`，且向量表主键与外键锁死 `videos(id)`（`database/semantic_vector.go:42-52`），无法直接容纳非视频实体。
3. 可复用资产充足：chat 侧已有 `type: image_url` + `data:image/jpeg;base64` 的多模态调用（`services/ai_tagging_client.go:216-245`）；与 ffmpeg 解耦的纯 Go 感知哈希 `differenceHash`（`services/ai_same_source_fingerprint.go:96`）；文件级零 DB 耦合的回收站（`services/trash_service.go`）；内容寻址托管图片服务与原子发布模式。

用户已裁决：独立 `images` 表（方案B）、独立照片页、支持 RAW/HEIC、AI 产出描述而非标签，以及后续五轮澄清确认的标签共享、人物/作品集不覆盖、照片页内语义检索、仅 macOS 解码、独立扫描目录、清理审阅/收藏评分/洞察全部纳入。本提案不重新讨论这些方向，只固化方案B框架内的技术取舍。

## Goals And Non-Goals / 目标与非目标

目标：

- 图片独立扫描入库（独立目录配置、独立扩展名设置、name+size 迁移检测），与视频扫描互不影响。
- 照片页完成浏览、查看、标签筛选、收藏/评分、语义检索、清理审阅与回收站闭环。
- macOS 上 HEIC/HEIF 与主流 RAW（`.dng/.cr2/.cr3/.nef/.arw/.orf/.raf/.rw2`）可生成缩略图并在查看器中预览。
- AI 描述与语义索引契约固定为可测试状态机（与现有语义索引/AI 打标同款模式：CAS 状态、可取消、可续跑、失败留痕）。
- 全部变更纯增量，`go test ./...` 现有基线不降。

非目标：

- 不给 `videos` 表加字段，不引入 `media_type`，不做多态外键，不重构视频扫描/清理/语义索引代码路径。
- 人物页、作品集页首期不展示图片；全局/视频页搜索不混排图片。
- 非 macOS 平台不承诺 RAW/HEIC 解码；不引入 libheif/libraw/CGO 图像依赖。
- 图片不接入字幕、播放统计、观看进度、超分、短视频流、AI 同源检测（多帧指纹）与 AI 质量评估。
- 不读取/存储 EXIF 拍摄时间与相机信息（列为后续独立需求）。
- 图片目录不接实时监听（watcher）；首期只有启动/手动扫描。
- 不做在线图片元数据、云同步、图片编辑。

## Proposal / 设计方案

### 1. 独立并行管线：复制模式而非泛化现有代码

新增 `ImageService`（扫描/增删/迁移/回收站）、`ImageThumbnailService`、`ImageAIDescriptionService`、`ImageSemanticIndexService`、`ImageCleanupService`（或并入 ImageService 的分析方法），全部按现有视频侧同名服务的既有模式书写（context 优先、哨兵错误、CAS 状态更新、per-ID 锁、临时文件 + `os.Rename` 原子发布、Start/Status/Cancel 长任务三件套）。规则边界：**只复制模式，不抽公共基类**——凡是纯函数级可复用的（`differenceHash`、`getPartialHash`、`TrashService`、`parseScanExcludePaths` 等）直接调用；凡是与 `models.Video` 类型绑定的流程一律新写，不为共享而把现有函数改成泛型。

图片路径变更使用独立的 `imagePathMutationMu`（镜像 `libraryPathMutationMu` 语义），与视频锁互不阻塞。

### 2. 表设计：七张新表 + 一张向量表，零改动老表

- `images`：文件身份（`name/path/directory/size/width/height/is_stale`）+ 用户态（`is_favorite/personal_rating`）+ 感知哈希（`perceptual_hash/hash_source_size/hash_source_mod_time_ns`）+ 软删除。路径上建部分唯一索引 `idx_images_path_active (path) WHERE deleted_at IS NULL`，复刻 `idx_videos_path_active`。
- `image_tags`：GORM many2many，指向现有 `tags` 表。标签删除/合并的现有语义自动生效（tag 侧操作按 tag_id 级联，实现时补 `image_tags` 的清理与合并 UNION，见详细设计）。
- `image_directories`：镜像 `scan_directories`（path/alias/软删除）。
- `image_trash_entries`：镜像 `video_trash_entries` 全字段与状态机（`image_id` uniqueIndex，`pending_move/deleted/restoring/rollback`），文件操作复用 `TrashService`。
- `image_ai_descriptions`：单表同时承载结果与状态（`image_id` uniqueIndex + CASCADE、`status/description/model_identifier/error_code/last_error/attempt_count/generated_at`）。不建独立 run 历史表——AI 质量评估不覆盖图片，是已裁决非目标。
- `image_semantic_indexes` / `image_semantic_index_attempts`：镜像视频侧同名表（`image_id` 替换 `video_id`，唯一键结构一致）。
- `image_semantic_vectors`：DDL 镜像 `video_semantic_vectors`，外键 `REFERENCES images(id) ON DELETE CASCADE`，HNSW + `vector_cosine_ops`。
- `image_near_duplicate_dismissals`：镜像 `near_duplicate_dismissals`（低 ID 存 low 位）。

`SemanticIndexProfile`（全局单行，id=1）**由视频与图片共享**：整个应用只有一个活跃 embedding 模型身份与维度。代价是重建（generation 递增）全局生效——视频侧触发重建后图片索引同样过期待重建；这是可接受的一致性行为，比双 profile 的模型漂移简单。同一时间只允许一个语义索引构建任务运行（视频或图片，应用层互斥）。

### 3. 解码链：ffmpeg 打底，sips 只管 macOS 的 HEIC/RAW

| 格式 | 探测尺寸 | 缩略图 | 查看大图 |
|---|---|---|---|
| jpg/jpeg/png/gif/webp | ffprobe（现有调用模式） | ffmpeg `scale=480:-2`（无 `-ss`） | 直接回原文件 |
| heic/heif/RAW（darwin） | `sips -g pixelWidth -g pixelHeight` | `sips -s format jpeg --resampleHeight 480` | `sips` 转 JPEG，长边 2560，缓存 `<id>.view.jpg` |
| heic/heif/RAW（非 darwin） | 不探测（0×0） | 无（404 → 前端占位） | 无（前端占位卡片） |

sips runner 以 `//go:build darwin` 隔离，非 darwin 平台提供返回"平台不支持"哨兵错误的 stub（复刻 `library_watcher_support_*.go` 的先例）。缩略图缓存放独立目录 `~/.video-master/image-thumbnails/`——**不能复用视频的 `thumbnails/` 目录**，因为视频缓存文件名就是 `<videoID>.jpg`，图片 ID 会与视频 ID 冲突。失效判定复刻现有 `validThumbnailCache`（存在 + 非空 + mtime ≥ 源文件 mtime）。

HTTP 路由新增两条前缀：`/preview/image/<id>`（原图或转码大图）与 `/preview/image-thumbnail/<id>`（缩略图，`private, max-age=300`），注册进 `newAssetHandler` 的现有前缀分发，ID 解析复用 `assetVideoIDFromPath` 的纯数字规则。

### 4. AI 描述：chat 多模态单图请求，描述即语义索引文本源

- 请求形态复用 `doChatCompletion` 模式：单图一次请求，content 为提示词 + 一条 `{"type":"image_url","image_url":{"url":"data:image/jpeg;base64,..."}}`；输入图片统一用缩略图管线产物降采样（最长边 512，对齐 `aiTaggingFrameMaxWidth` 惯例），HEIC/RAW 因此天然被转码覆盖。`temperature: 0.1`，超时沿用 5 分钟。
- 提示词要求输出一段 80–200 字的中文自然语言描述（画面内容、场景、风格），明确禁止输出标签列表或 JSON。
- 配置完全复用 `SettingsAITaggingConfigProvider`（`ai_tagging_base_url/api_key/model`）；未配置时批量任务与单张重跑都返回明确的"AI 配置不可用"错误。
- 批量生成走 Start/Status/Cancel 三件套（单 worker，处理所有无描述且状态非 processing 的图片），单张"重新生成"直接同步调用并覆盖旧描述。

### 5. 语义检索：照片页内独立入口，offset/limit 语义与视频侧一致

- 图片索引文本 = `标题`（文件名）+ `标签` + `AI 描述` 三段（`appendSemanticSection` 同款结构与脱敏/截断/指纹逻辑）。**无 AI 描述的图片跳过索引**（计入 Skipped）——描述是图片唯一的语义内容，仅文件名不值得占向量位。
- 查询镜像 `querySemanticDistances`：`images JOIN image_semantic_vectors`，`<=>` 余弦距离，`ORDER BY distance ASC, images.id ASC OFFSET/LIMIT`，`limit+1` 探测 hasMore；结果只在照片页展示。视频页任何搜索路径不查图片表（AC-6）。

### 6. 清理审阅：精确 + 近似两类候选，删除统一走回收站

- 精确重复：分析时实时按 `size` 分桶 + `getPartialHash`（采样 MD5）配对，与视频清理同款算法；不落库。
- 近似重复：入库/回填时基于缩略图 JPEG 计算 dHash（`differenceHash` 全图 region，8×9 灰度 64 位），存 `images.perceptual_hash` 并绑定 `hash_source_size/hash_source_mod_time_ns` 判 stale；分析时按 16 位前缀分桶限流后组内汉明距离 ≤ 8 判相似，连通分量成组。用户忽略写 `image_near_duplicate_dismissals`。
- 候选一律不自动勾选；删除走 `BatchDeleteImages(ids, deleteFile)` → 图片回收站。分析产出结构镜像 `CleanupAnalysis` 的 `DuplicateGroups/NearDuplicateGroups`，无 `LowDuration/LowResolution/SameSourceGroups`（判据不适用，已裁决）。
- 图片清理审阅 UI 放在照片页内部，不改动 `VideoListPage.vue`（153KB 巨型组件）里的视频清理入口。

### 7. 前端：照片页走 EntityLibraryPage 已验证的模式

- 新增 `PhotoLibraryPage.vue`，`currentPage === 'photos'` 时 `v-if` 挂载（与人物/作品集/洞察/设置一致）；顶部导航胶囊组加"图片"按钮。
- 网格：CSS Grid `repeat(auto-fill, minmax(180px, 1fr))` + IntersectionObserver 哨兵无限加载 + 手动"加载更多"兜底——这是 EntityLibraryPage 已验证的组合。**首期不做网格虚拟化**：现有 `calculateVirtualWindow` 是一维行高模型，且视频页网格模式本来就显式关闭虚拟化（`VideoListPage.vue:248`），照片页与该先例保持一致；万级图片的性能靠分页节流（哨兵 rootMargin + 每页 60 张）而非虚拟化，虚拟化列为后续优化。
- 列表 API 采用 request-DTO + 不透明游标形态（照抄 `SearchLibraryVideoPage` / `LibraryVideoPageRequest` 模式），不用散参 + 满页推断。
- 查看器：页内 lightbox 覆盖层，`<img src="/preview/image/<id>">`，左右方向键切换、Esc 关闭；HEIC/RAW 在 macOS 上由路由回转码 JPEG，非 macOS 显示占位与文件信息。
- 设置页新增"图片扫描目录"管理块（复刻现有目录块的 Add/Update/Delete + BaseModal 模式）与 `image_extensions` textarea（复刻 `video_extensions` 交互，空值回退默认清单）。
- 洞察页新增图片分区（图片总数、存储占用、按目录/格式分布），数据来自新 API `GetImageInsights()`，图表直接复用 `BucketChart.vue`，不引入图表库。

## Boundary Scenarios / 边界场景

- **空目录/无图片目录**：照片页显示空态与"添加图片目录"引导；扫描空目录成功返回 0 条。处理：现在支持。
- **重复路径入库**：`idx_images_path_active` 拒绝 + `Unscoped` 预查返回已存在错误（复刻 `addVideo`）；重扫幂等（TC-1）。处理：现在支持。
- **视频目录与图片目录重叠**：允许配置重叠；同一文件只会按扩展名进入一侧（扩展名集合不相交是用户配置责任，两侧默认清单不相交）。处理：现在支持，不做目录级互斥校验。
- **HEIC/RAW 在非 macOS**：入库、可打标签/收藏/评分/删除，缩略图路由 404 → 前端占位；AI 描述任务跳过（无法产出降采样 JPEG）并记失败码 `decode_unsupported`。处理：明确降级。
- **sips 失败/超时**（损坏文件、异常 RAW 变体）：单文件失败留痕（`is_stale` 不动，缩略图缺失 → 占位），不中断批量任务；`exec.CommandContext` 超时 30s。处理：现在支持。
- **AI 未配置**：批量描述与单张重跑返回明确错误；语义索引因无描述全部 Skipped；照片页语义搜索入口显示"需先生成 AI 描述"。处理：拒绝并提示。
- **pgvector 不可用/非 Postgres**：镜像现有 `SemanticVectorCapability` 语义，图片语义功能显示不可用原因；其余功能不受影响。处理：降级。
- **语义任务并发**：视频索引运行中启动图片索引（或反之）→ 返回"已有语义索引任务运行中"。处理：拒绝。
- **模型/维度重建重叠**：视频侧触发 rebuild（generation+1）后，图片已有索引行 generation 过期，下次图片索引任务全量重建。处理：延迟一致，文档化。
- **删除与扫描并发**：`imagePathMutationMu` 读写锁镜像视频侧语义；删除中扫描不会把回收站 `trash/` 目录扫回（复用 `isTrashPath` 过滤）。处理：现在支持。
- **恢复冲突**：原路径已有同名文件 → 拒绝恢复不覆盖（TC-5，复用 TrashService 既有语义）。处理：现在支持。
- **重复删除同一图片**：`image_id` uniqueIndex 拒绝第二条回收站条目（镜像视频 deleteVideo:614 行为）。处理：拒绝。
- **应用中途崩溃**：`pending_move/restoring` 条目按镜像状态机对账；AI 描述/语义索引的 `processing` 状态启动时复位（镜像 `recoverInterruptedRuns`）。处理：现在支持。
- **超大图片库（10 万张）**：列表 keyset 分页 O(页)；近似重复分析靠前缀分桶 + 邻居上限（镜像 `perceptualHashMaxBandNeighbors/MaxCandidates` 常量思路）避免 O(n²)；洞察聚合是全表 GROUP BY，量级与现有视频洞察一致。处理：现在支持，虚拟化列为后续优化。
- **迁移重叠/老库升级**：全部新表 AutoMigrate 增量创建；`Settings.ImageExtensions` 新列零值 "" 由代码回退默认清单，无需数据回填。处理：现在支持。
- **回滚**：功能整体回滚 = 回退二进制；新表留存无害（无老代码读它们），可选手工 DROP。不存在改写老数据的路径。处理：现在支持。
- **必须不回归的旧行为**：`videos` 表结构、全部现有 Wails API、`/preview/` 现有五条路由、视频清理/回收站/语义索引/洞察行为与统计数值（AC-8、AC-11 后半句、TC-6）。处理：不变，回归由现有测试套件 + 新增测试保障。

## Rationale / 理由与取舍

| Alternative | Why Not |
|---|---|
| 方案A：`videos` 表加 `media_type` | 用户已裁决方案B；且 8 个视频专属列在图片行永久空置、全部列表查询要补防御性过滤，命名与语义永久脱节 |
| 泛化 `video_semantic_vectors` 为多态（entity_type 列） | 现有主键/外键锁死 `videos(id)`，改造要重建主键并失去数据库级 CASCADE；独立表零风险且查询天然隔离 |
| 独立的图片 SemanticIndexProfile | 双 profile 允许视频与图片用不同 embedding 模型/维度，但被裁决的"embedding 复用 AI 接口"下无此需求；双 profile 引入模型漂移与两套重建语义，成本大于收益 |
| 图像向量模型（CLIP 类）直接对图片做 embedding | 引入新模型配置与新依赖，违背"embedding 复用现有 AI 接口"裁决；AI 描述 → 文本 embedding 已满足 AC-6 的检索场景 |
| libheif/libraw（CGO 或外部工具链） | 已裁决仅 macOS；sips 系统自带、零依赖、覆盖 HEIC 与主流 RAW |
| 用 ffmpeg 解 HEIC | 依赖用户 ffmpeg 的编译选项（libheif 非默认），支持不确定；RAW 基本不可用 |
| 泛化 `VideoTrashEntry`/`ScanDirectory` 等表加类型列 | 触碰现有表与现有状态机代码，回归面大；镜像新表是纯增量且两侧可独立演进 |
| 首期实现二维网格虚拟化 | 现有虚拟化是一维模型且视频网格模式本来就关闭虚拟化；新写二维窗口计算是独立的性能优化需求，不应与功能首版耦合 |
| AI 描述建独立 run 历史表（镜像 AITaggingRun） | AI 质量评估不覆盖图片（非目标）；单表 status+attempt_count 已满足续跑与失败留痕 |

## Compatibility / 兼容性

**纯增量，无破坏性变更。**

- 老库升级：AutoMigrate 建 8 张新表 + `Settings` 加 1 列（零值回退默认清单，无回填）；`PrepareImageSemanticVectorStorage` 与现有语义存储同款幂等 DDL。
- 不变面：`videos` 及其 17 张关联表、全部现有 Wails API 签名、`/preview/` 现有路由、`models.AllModels()` 现有成员的结构、前端现有五个页面的行为。
- 回滚：回退二进制即可；新表无老代码依赖，留存无害。
- 新 API 全部 `Image*`/`*Image*` 命名，与现有命名空间不冲突。

## Operational And Security Impact / 运行与安全影响

- 外部进程新增 `sips`（仅 darwin，系统自带）；调用带 context 超时与有界输出，失败不中断批量流程。
- 数据外发面与现有 AI 打标完全一致：仅降采样 JPEG（≤512px）与提示词发往用户配置的 AI 端点；描述与索引文本落库前走现有脱敏（API key、绝对路径正则）。不新增任何网络端点配置。
- 磁盘：`image-thumbnails/` 缓存目录新增；查看大图缓存 `<id>.view.jpg` 与缩略图同目录，按视频 seek-sprite 的 LRU 模式设上限（256 MiB）。
- HTTP 资源路由维持现有"无鉴权、纯数字 ID、服务层路径校验"的边界，不扩大攻击面（本地 Wails 资产服务）。

## Implementation And Transition / 实现与过渡

自然的落地顺序（仅为兼容性排序，不是任务计划）：表与扫描 → 缩略图/预览路由 → 照片页浏览 → 标签/收藏/评分/回收站 → AI 描述 → 语义索引与检索 → 清理审阅 → 洞察。每段独立可验收，前段不依赖后段。
