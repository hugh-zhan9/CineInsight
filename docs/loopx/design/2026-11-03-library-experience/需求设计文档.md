## 2. 通用接口、身份与生命周期

<a id="D-LE-04"></a>
**D-LE-04 · Interface / Operational Contract · Proposed，来源 R-01–09。** 仅新增桌面 Wails 绑定。HTTP/LAN/Jellyfin 入口不得自动暴露新增地图坐标、查询文本、专题或摘要接口。所有请求仍经 App 的数据库维护、待重启和路径围栏。下游按本节统一处理新增接口，不批量修改旧接口响应。

- 新增 DTO 的字段为 snake_case；时间区间统一毫秒整数 `[start_ms,end_ms)`，日期是 `YYYY-MM-DD`，网络发送字幕时用毫秒和纯文本；ID/版本须满足现有 JS 安全整数约束，BT ID 保持字符串。
- 除专门注明外，新列表默认 50、最多 200；拒绝负数、超限、重复或不存在的目标，不自动截断写集合。数组空值明确：查询空集合代表不筛；写入成员空集合只有明确的“清空”动作才接受。
- 新增同步接口统一返回 `Result<T>={status:ok|error,data:T|null,error:{code,message,field?}|null}`。`ok` 与 `data` 非空、`error` 空绑定，空列表也是成功；`error` 不附可误用的数据。Wails transport reject 仍由调用方单独显示连接/调用失败。旧接口保持原映射，适配层不从任意错误字符串猜成功状态。
- 共通 code：`invalid_input`、`not_found`、`conflict`、`source_changed`、`maintenance`、`relaunch_pending`、`cancelled`、`dependency_unavailable`、`dependency_timeout`。领域特定 code 在所属节定义。消息固定中文，不暴露路径、token、字幕正文或外部响应原文。
- 新增长任务启动成功只代表 `job_id` 已登记；任务 owner 的状态才表示结果。App generation、任务 attempt、源版本与请求代次分别校验，避免切库、重试或换视频后的晚回包落到新对象。取消与完成由条件更新决定胜者；取消输给提交时返回实际已完成状态。
- 本地重任务复用 MediaWorkSlot 与现有单 worker 约束；文本摘要任务串行。不把新增地图请求、搜索页面或准备引导注册为“禁止退出”的后台重任务。退出/维护取消并等待本地工作；不停止外部 BT 下载。
- 读写只访问当前可见范围，不能仅用 ID 绕过目录范围或软删除。源版本复用 `videoSourceVersion`，它是文件身份/size/mtime 验证，不声明能检测“原地改内容且伪造同样元信息”的攻击。

<a id="D-LE-05"></a>
**D-LE-05 · Data Contract · Proposed，来源 R-01、04、07–09。** 所有新编辑带 expected_revision；服务端在同一事务先 CAS 聚合根，再校验/修改其成员，冲突整次回滚。版本单调增加，删除再创建不得复用身份，处理 ABA。外部请求不在数据库事务内，不因 CAS 冲突自动重放网络副作用。关系和迁移范围见[数据集成](#data-integration)。

## 3. 缺集补齐

<a id="D-LE-10"></a>
**D-LE-10 · Behavior / Interface Contract · Proposed，来源 R-01。** 复用 CollectionService 与 BTService。遵守[现有下载用户确认边界](../2026-10-30-prowlarr-download/概要设计.md)，具体跨系统顺序由概要拥有。新增的本地关联不控制远端下载。

### 入口与事实区分

`CollectionEpisodePanel` 中每个 missing range 可选择一个或多个具体集号，最多 200 个；不展开未知总集数之外的缺口。混合剧集或季号未知时先要求用户选季并核对搜索词。离线集展示“已收录但离线”，不混入缺集选择。

`PrepareEpisodeResourceSearch({collection_id,season,episodes[]})` 返回 `origin_token,expires_at,query,targets[],report_signature`：query 为可编辑标题与季集提示；targets 只含明确选择的集号。token 在当前 App/DB generation 内存中有效 10 分钟，不是凭据；提交下载时来源被持久化，之后不依赖 token 存活。查询动作不改变作品集或下载状态。

资源列表的标题推断使用“可能包含第 N 集”，点击后复用既有草稿文件清单。清单可以展示文件级推断；多集一文件、季号缺失、不同作品同名标 `uncertain`，不自动选中或写季集。`已在库` 只有现有显式作品集关联支持时成立，`下载中` 仅统计本应用带来源关联且仍受控的任务，不扫描/管理外部任务。

`DescribeEpisodeCandidates({origin_token,result_tokens[]})` 仅对本次缓存资源标题做最多 200 项本地注释，不新增站点请求；返回标题提示，以及明确标为“当前作品集此集”的收录/受控下载状态。缺少季号或多集文件保持待核对，不能据此断言资源与作品同一。注释失败单独显示，不改原搜索结果或宣称没有匹配。

### 选择与入库关联

新绑定 `SubmitEpisodeDownload({draft_id,expected_revision,selected_file_ids,origin_token,file_episode_choices[]})` 在 BTService 内调用既有提交核心；单一事务持久化原下载意图与来源快照，然后继续原远端协议。`file_episode_choices` 是用户确认的 file ID → 一个 season/episode；不允许替清单外文件填映射。未映射的选中文件照常下载，入库后标待核对，不自动归入作品集。

提交前复核来源签名与文件清单、选择代次；作品集成员/纠正/期望总数已变化或目标不再缺失，返回 `episode_context_changed` 供用户刷新。远端写成功未知沿用原合同，不自动再次添加。来源绑定失败必须在远端副作用之前拒绝，不能形成已下载但来源悄悄丢失的成功响应。

`ListEpisodeAcquisitions({collection_id,cursor,limit})` 返回按下载意图建立的季集状态：`selected / transferring / imported_unlinked / linked / import_failed / detached`，附 task_id、file_id、video_id、标题、季集、可用动作。这是由 BT 文件事实和关联事实投影的状态，不新存一列重复进度。远端已下载但本地入库失败仍是 `import_failed`，不能算收齐。

`PreviewEpisodeAssociation({task_id,items:[{file_id,origin_id,expected_origin_revision,season,episode}]})` 接收用户逐文件补充或纠正后的明确映射，最多 200 项；UI 可从已有 confirmed_mapping 预填，未映射项必须由用户填写，不能用 requested 集号冒充文件结果。只接受已成功入库的指定文件，重复 file_id、非法编号、跨当前来源作品集的混合选择拒绝。预览不写来源行，返回 10 分钟 token、目标作品集、精确 video/season/episode 映射与冲突项，并冻结原来源 revision 和用户选定映射。

`ConfirmEpisodeAssociation({preview_token})` 只提交已预览的集合，执行时再检查来源 revision、BT 文件入库身份、现有成员及人工修订。任一目标冲突整次拒绝；用户重新预览可明确去掉冲突项。成功事务同时添加作品集成员、必要的人工季集映射，并按原 revision 更新来源行的 mapped_season/mapped_episode/confirmed_mapping 和新 revision；复用 CollectionService 内部事务方法，不能跨多个独立提交拼装。用户可把文件纠正到原请求以外的集号，但预览须显著显示“与最初请求不同”，确认的是这项具体映射，不扩大到其它文件。

新增 `collection_episode_revision` 聚合根（collection_id 唯一，revision）在成员增删、季集纠正、期望总数变更及本功能确认中同时 CAS；新建作品集同事务建立 revision=1，历史作品集由迁移补齐。所有直接写成员的现有调用方必须接入，否则预览防过期不成立。标题改动、源文件名/离线状态等影响预览的输入另纳入签名并在确认事务/路径围栏内复核。单靠前端的 report_signature 不作写入授权。

受影响写路径包括 `collection_service.go`、`collection_episodes.go`、`video_detail_service.go`、`metadata_batch_edit_write.go` 及撤销、`automation_rules_apply.go`、`enhancement_metadata_copy.go`、`media_metadata_merge.go`、`collection_suggestion_service.go`，以及媒体永久删除/关系级联路径。复用事务内成员操作，但新关联路径不调用现有 `lockActiveCollection` 的 FOR UPDATE 作为并发保证；上述成员写路径统一经 CollectionService 的事务 helper 领取 revision，按集合 ID 稳定顺序处理多集合，保留其原业务结果。受影响的作品集行锁以 CAS 替代，其他人物/视频领域的既有锁不随本次扩展改写。失败交回原调用方按该操作的既有失败机制处理，不新增自动事务重试。

作品集删除后来源行保留标题快照并投影为 detached，不取消下载、不创建同名作品集。任务历史回收只删除其来源记录，不删除片库视频。相同 task/file/collection 来源只有一行，映射修改校验该行 revision；并发失败者返回 conflict，成功后的重复确认返回原关联结果，不重复插入成员。

补充裁定 Q3（2026-11-03，用户已确认）：下载完成后或关联确认前，若另一视频已占据同季同集，新下载文件保留为未关联，提示“这一集已补齐”；需要另一版本时由用户另行手动整理，不自动删除、替换或加入。该下载视频自身已按同一映射关联时，按已关联/幂等结果处理。同一确认批次不能把两个不同视频填进同一季集；任一目标被补齐仍按原规则整批拒绝，重新预览后可明确去掉冲突项。

## 4. 字幕显示与同步台词

<a id="D-LE-11"></a>
**D-LE-11 · Behavior / Interface Contract · Proposed，来源 R-02。** 扩展共享播放器字幕组件，详情与队列共同使用；不改变外部播放器、SRT 文件、翻译或索引规则。

| 设置 | 拟议值与默认 | 保存范围 |
|---|---|---|
| 字号 | small / medium / large / xlarge，默认 medium；相对播放器宽度且有上下界 | 本机 UI 偏好，不进数据库备份 |
| 背景 | none / translucent / solid，默认 translucent | 同上 |
| 位置 | bottom / middle / top，默认 bottom | 同上 |
| 时间偏移 | 保留 ±60 秒、0.1 秒步长 | 仍仅当前播放会话 |
| 台词侧栏 | 打开/关闭、跟随播放开关 | 会话状态 |

字号映射使用设计系统变量；位置通过同一 cue 投影，先保留原生 track 渲染并验证 WKWebView 全屏表现，不承诺原生画中画或系统播放器继承样式。若需要自绘字幕才能达标，应在此决定中修订渲染方案并验证可访问性，不能双重显示字幕。

复用 `GetPlaybackSubtitle` 已有 `cues` 与 fingerprint，无须另一份读取接口。侧栏虚拟化，不对每行发后端请求。当前行按 `cue.start_ms + offset <= time < cue.end_ms + offset` 判定，多行重叠按开始时间和原序号排序高亮；点击定位 `max(0,start_ms+offset)`，夹在当前合法播放区间内。超出区间的行在专题预览中不可跳转，不扩大区间。

用户滚动侧栏后暂停自动滚动，点击“跟随播放”恢复；仍更新当前行标记。`subtitle-changed`、手动刷新、换视频、换队列 token 时使旧 cue/选择/异步读取失效。晚回包不能替换新视频台词。台词纯文本展示，保留换行，不使用 v-html。

无字幕显示创建/提取/生成的既有入口；坏字幕显示工作台修复入口；读取失败不停止视频。样式偏好无效时按字段使用默认值并显示当前选项，不能清除其他播放器偏好。

## 5. 检索汇总、分组与连续预览

<a id="D-LE-12"></a>
**D-LE-12 · Behavior / Interface Contract · Proposed，来源 R-03。** 新增薄的 `SearchResultsPage` 组织已有查询能力，ScenesPage 保留专业模式并共用结果分组组件。⌘K 原直接跳转继续有效，新增“汇总结果”。

`SearchRequest` 为 `{query,filter,group,mode,image_ref?,cursor?,limit?}`。group 是 video/person/collection/dialogue/visual/image；全页分别请求各组，不用一个失败让所有成功结果消失。`query` 文字规则沿用原接口，后台不记录查询正文；拖入图片沿用既有本地处理与大小上限。图片只在会话内保留，不将 base64 放 URL 或长期本地存储。

响应由每组返回 `{items,next_cursor,coverage,notices,extent}`，extent 为 `exhaustive_page` 或 `ranked_top_k`。视频/人物/作品集复用原分页；对白新增按视频分组分页，不能先取 200 个片段再声称找到了全部影片。画面/以图沿用现有最多 200 个相关片段并明确显示“最相关的前 N 段”，truncated 时提示缩小范围；它们不展示虚构的全量命中总数。

对白组 `SearchDialogueVideoGroups({query,filter,cursor?,limit=20})`：DB 先按可见范围筛出命中视频，以 video_id 升序键集分页，每页最多 50 部；返回 video_id、标题、该片命中数、首批最多 3 个片段。`ListDialogueVideoHits({query,filter,video_id,cursor?,limit=30})` 以 start_ms、segment_id 升序继续取，最多 200。命中数与当前页在一个数据库读取快照中求得，跨页不是冻结片库；前端按 ID 去重，明确刷新会重新计算。

游标包含规范化查询/筛选签名和排序键，换条件须清空游标；伪造、错签名或失效返回 `search_cursor_invalid`，不静默回到第一页。分组以具体 video_id 为单位，不把不同版本的时间轴合并；可显示版本组徽标。视觉同片同起点命中合并展示来源，但保留供播放验证的源版本和区间。

新结果页点击单条命中的“预览”与“连续预览本片命中”都把精确选择送入[区间队列](#D-LE-17)，前者只有一项；不调用会记录有效观看的原 InlineVideoPlayer 详情路径冒充中立预览，也不隐式选中未加载的结果。台词区间带前后各 2 秒上下文并夹在片长范围内，视觉区间用已有段边界；最终区间显示在确认摘要。预览向现有队列追加并定位到新项，保留原条目，不清空用户队列；如当前有播放则明确显示将切换到此区间，沿原 queue revision 处理冲突。未知时长或已变源不能入队。返回时恢复查询、展开影片、滚动和已有结果；数据事件只标记可刷新，不在用户浏览中重排。

“观看整片”先停止/退休 clip token，再通过原正式播放入口建立新会话；先前预览秒数不带入正式观看阈值，也不补记观看事实。仅浏览搜索结果、展开影片或台词不算观看。⌘K 旧直接跳转与原场景页既有动作保持原行为；只有新增明确标为预览的入口承诺上述中立语义。

## 6. 推荐偏好与场景预设

<a id="D-LE-13"></a>
**D-LE-13 · Behavior / Data Contract · Proposed，来源 R-04。** 仅影响今晚看什么和随机选片，不改一般搜索结果、收藏、评分或观看事实。正向偏好先面向标签；不推断年龄、敏感属性或用户没有表达的偏好。

预设“短一点”=最大 30 分钟、“重温收藏”=watched+favorites、“探索没看过”=unwatched；其它当前条件保留，界面明确显示被预设覆盖的字段。用户可改时长，空候选保持空并显示冲突条件，不放松筛选。已有无偏好用户得到原行为。

扩展 `recommendation_feedbacks` 的 tag effect 为 boost/downweight；work_video/work_group 的 snooze 仍是现有 7 天。一个标签只存在一个有效方向，“恢复中立”删除该偏好，不删除标签。新 `SetRecommendationTagPreference({tag_id,effect:boost|downweight|neutral,id?,expected_revision?})` 使用目标唯一与 CAS；创建必须不带 id/revision，修改/删除必须同时带二者，不能按 tag_id 无条件覆盖。旧减少推荐入口适配同一写核心。

当前唯一键实际是 `(target_kind,target_id,effect)`，必须迁为 `(target_kind,target_id)` 才能防并发创建两个方向。新键以新索引名建立并验证后移除旧冗余键；历史数据预检同一目标多行时报告冲突、阻止该迁移，不任意删用户偏好。创建冲突返回 conflict 并重读；方向切换 CAS 原 row id+revision，revision 单调增加；删除后新建获得新 id，旧版本请求不能操作它。标签合并时归并源/目标偏好，downweight 优先于 boost，仅保留一个目标行；合并确认界面列明冲突后的方向。事务校验两侧已审阅 id/revision，任一改变整次合并拒绝，不覆盖并发编辑。

拟议权重：硬筛选、作品去重和 snooze 后，任何降权标签命中则 factor=0.5；否则有正向标签则 factor=1.5；否则 factor=1。多标签不累乘，负向优先，避免既有“少推荐”被抵消。接入原 feedbackFactor 位置，原基础权重、最近排除、30 秒换片和统计提交时机不变。应用后展示“来自：探索、≤30分钟、科幻偏好”等实际命中理由，不宣称模型理解心情。

偏好页展示目标、方向、有效期和影响范围，支持逐项撤回。版本合并/拆分、标签合并/删除沿用原归属流程并扩展 effect 判断；当前源码对 tag 未区分 effect，实施时必须改所有读路径，不能只加写入枚举。旧数据不重算、不新增默认偏好。

实施接口细化（2026-11-03，不改变上述行为）：新增 `PreviewTagMergePreferences(sources,target)` 与 `MergeTagsFromPreferencePreview(token)`，均走 D-LE-04 新响应形态；无偏好时保留旧 `MergeTags` 绑定，但提交必须再次确认无偏好，有偏好则拒绝并要求预览。TagService 保存至多16个、10分钟的预览，绑定 App 维护 context 与数据库身份。`tags.preference_revision`（默认0、不对前端返回）保护“尚无偏好”的空状态：偏好增删改和合并都在同一事务CAS该行，合并按标签ID顺序领取；预览冻结根版本与具体偏好行版本。否则在用户确认期间新增偏好会绕过只核对已有行的校验。旧库仅加零默认列，无历史偏好推断。

## 7. 按目标准备能力

<a id="D-LE-14"></a>
**D-LE-14 · Behavior Contract · Proposed，来源 R-05。** 首次进入空片库提供可关闭的准备入口；已有用户不强制弹出。设置和 ⌘K 始终可进入。

| 目标 | 展示事实 | 明确动作 |
|---|---|---|
| 看片 | 扫描目录、已入库数量、播放工具能力 | 选择目录、扫描、打开第一部片 |
| 整理片库 | 技术资料、元数据完整度、待审阅数量 | 进入现有补全或待处理 |
| 搜画面 | 当前运行时、模型准备、索引覆盖 | 显式准备模型、对选定范围建索引 |
| 制作字幕 | 系统版本、Speech/Translation 资源、权限与 ffmpeg | 准备语言、权限说明、选择视频生成 |

前端基于 `GetSystemHealthSection` 与既有能力接口投影 `ready / needs_action / preparing / unsupported / unknown / failed`，每项带 checked_at、中文原因和既有 command ID。不保存一份“已完成步骤”作为真实能力；只保存用户跳过提示的本机偏好。状态 unknown 时“检查”才执行原能力探测；页面挂载不启动 Python、请求系统权限、下载或安装依赖。

动作执行后仍由原 owner 上报状态，任务已受理不等于准备完成。可以离页，回来重新读状态。部分能力不可用不阻止其他目标；全空、只缺一个依赖和任务失败均有下一步。模型所需体积有可信 manifest 才展示，无法估算写“大小待确认”，不虚构剩余时间。

## 8. 自然语言组合搜索与外部文本请求

<a id="D-LE-15"></a>
**D-LE-15 · Interface / Data Contract · Proposed，来源 R-06，外发上限受[用户裁定](概要设计.md#D-LE-02)约束。** 用户选择普通搜索、本地解析或外部 AI 解析，不设失败后的隐式模式切换。

本地首批语法覆盖“未看/已看/收藏”“N 分钟/小时以内”“人物 X”“标签 X”；自然语言任意措辞由可选外部模式处理。两个模式统一产出下面的草稿，不要求本地正则声称理解全部中文：

```text
ParseLibraryQuery({text,mode:local|external})
 -> {draft_id,expires_at,conditions[],unresolved[],unsupported[],status:ready|needs_input}
condition = {kind:watch|favorite|duration|person|tag,
             operator:eq|lte|gte|and,value,source_text,entity_id?,label}
unresolved = {source_text,reason,candidates:[{id,label,disambiguation}]}
```

输入去首尾空白后 1–500 字，拒绝仅空白；draft 在当前 generation 内存保留 10 分钟。模型只输出白名单类型的结构化 JSON，不允许 SQL、路径、命令、工具调用或自选接口。数值有限且时长在 0–86400 秒范围，0 不作为“未知时长也匹配”的捷径。无法支持的 OR、否定人物、情绪等条件出现在 unsupported，用户必须编辑/显式移除才可搜索；不会当作全文关键词偷偷忽略。

实体解析只在本地：将模型返回的名字匹配现有人物/标签；重名列出候选和本地关联概况，零命中要求改名或移除。完整人物库、候选列表、影片列表都不送模型。现有人物没有角色语义，“出演/导演”等需用户接受转换为“人物关联”，否则 remains needs_input。

`SearchParsedLibraryQuery({draft_id,resolved_conditions,acknowledged_removals,cursor?,limit?})` 服务端重新校验白名单、实体存在与筛选范围，返回普通 LibraryVideoPage 投影。合法草稿不是持续写权限；它只能查询。`保存为视图` 调用既有保存视图能力，并持久化明确条件，不保存自然语言作为可自动执行代码。

LibraryFilter 加性新增 `watch_state=any|unwatched|watched`（空同 any）、`favorites_only`（默认 false）、`min_duration_seconds`、`max_duration_seconds`（默认 0）。watch_state 与 favorites_only 是正交 AND，能表达“未看＋收藏”；smart_view 保留原管理视图与旧调用兼容，新条件与它同时出现时求交。新增明确条件与旧 watched/unwatched 视图相互矛盾时返回 invalid_input，不能默默舍弃任一条件；新字段全默认时严格保留旧请求行为。时长 0 表示不限制，正值时排除 duration<=0；min>max 拒绝。

字段落在共享 normalization/query builder，计数、分页、保存视图、随机和场景范围一起支持。现有 SavedLibraryView 是分列模型，仅人物/标签为 JSON：为四个新字段新增对应列和默认值，并更新 buildSavedLibraryView、UpdateSavedLibraryView、读出到前端的转换、命名视图应用和条件 chip；旧行迁移为 any/false/0/0。随机请求已有 watch_state/favorites_only/max_duration_seconds，调用共享规范化合并：观看状态矛盾拒绝、仅收藏取 OR、两个正的时长上限取更小值；不能两个路径分别解释同一条件。人物 AND 及版本折叠原语义不变；结果页仍是片库文件筛选口径，随机仍按原作品观看口径，界面明确当前口径。

实施接口细化：`GetTextAIStatus()` 只读返回两用途开关、服务/模型显示名及查询用途 `provider_revision`、摘要用途 `summary_revision`，不返回密钥，也不联网探测。外部解析请求必须携带该披露对应的 revision；配置变化后重新读取并由用户重新点击解析。revision 是当前 App/DB generation 的短期不透明身份；同一用途关闭再开启也换身份，旧请求和旧外部草稿不可复用；用途开关只失效该用途，服务地址/模型/密钥或DB变化才同时失效两种用途。摘要准备响应的 `provider_revision` 承载其 `summary_revision`，查询旧字段保持兼容，不额外持久化密钥副本或请求正文。

每个草稿条件有稳定的 `condition_id`；条件值使用规范字符串（观看状态、true、十进制秒数或实体名）。`resolved_conditions` 只提交条件 ID、选定实体 ID 及明确接受“人物关联”转换的标记，服务端从原草稿取回实际条件，不信任客户端重写值。`acknowledged_removals` 对应明确勾选移除的条件/未解决项 ID，未知、重复和未处理项拒绝；至少保留一个可执行条件，不能把空解析当成无条件全库查询。检索结果同时返回已校验 `filter` 与原 `LibraryVideoPage`，供预览、应用到片库及原保存视图入口使用。游标绑定该次条件签名。

解析请求另带唯一 `request_id`，`CancelLibraryQuery(request_id)` 取消该次执行，关闭解析窗口调用同一路径。owner 保留当前 App/DB generation 内10分钟的最小请求状态：先取消后到达的解析不得外发；重复 request_id 不重复执行；取消输给草稿提交时返回实际 completed。取消不影响另一请求，切库使旧请求/草稿失效。关闭窗口只能停止后续处理，不能撤回已发出的正文。

模型输出还须与本地可识别的原子约束交叉校验：一个整句 source_text 不能吞并未表达的收藏/时长等条件，已知“未看”不能反转为“已看”。只有可核对的谓词片段或用户原文中的实体名计入已解释范围；整句来源不能掩盖未知要求。模型不能可靠转换的部分必须明确进入 unsupported，继续由用户处理。

### 外部请求隔离

两种用途分别显式开启：`query_parse` 与 `chapter_summary`。可选择复用已有 AI 服务地址/模型配置引用，但启用状态独立；更换提供方/模型后使尚未提交的请求快照失效并重新展示发送范围。查询界面发送前显示“发送这段查询给 <服务/模型>”，用户点解析即确认当前文本。摘要发起页显示视频、字幕来源、字数/区间和外发说明，需明确启动。关闭能力取消飞行请求并丢弃晚回包，已发送内容无法撤回，界面据实说明。

只复用基础传输，新增无工具的 `TextAIClient`，固定用途 schema；查询单次截止 20 秒，摘要分段每请求 60 秒、整任务 15 分钟，均可取消；这些是拟议预算，超时明确失败、用户可手工重试，不自动退回其它模型或本地模式。响应最大 1 MiB、JSON 解析失败为 `ai_output_invalid`。返回文本不执行 HTML/Markdown 内嵌脚本，不访问模型给出的 URL。日志只记操作类型、状态、耗时、模型标识，不记请求/响应正文或密钥。

## 9. 照片地图与旅行回顾

<a id="D-LE-16"></a>
**D-LE-16 · Behavior / Data Contract · Proposed，来源 R-07，联网边界已由[用户裁定](概要设计.md#D-LE-01)固定。** 前端地图组件打包到应用，拟用 Leaflet；不加载第三方远程脚本。底图拟用 OpenStreetMap 标准栅格瓦片，用户开启前显示服务名和区域请求披露；不接逆地理编码。

`QueryPhotoMap({bounds:{west,south,east,north},zoom,person_ids[],date_from?,date_to?})`：经 ImageService 作用域、人物 AND、日期条件和有效 GPS 筛选，本地按视口网格聚合，返回 `{clusters:[{key,center_lat,center_lon,count,sample_image_id}],matched_count,missing_gps_count,undated_count}`。zoom 0–19；坐标有限，纬度 -90..90、经度 -180..180，west>east 表示跨日期变更线，SQL 拆为两个经度区间，不当无效或整个地球。Web Mercator 可显示纬度以约 ±85.0511 为限，超出部分保留照片记录并显示不可投影计数，不篡改 EXIF。

网格按 z/x/y 的下一层级聚合，最多 1000 个聚合点；超过时服务端降低聚合层级并返回实际层级，不丢弃照片。同一照片只计一次。点开聚合通过 bounds+filter+cell_key 查询图片分页（50/200，taken_at、id 稳定排序，空日期排后），cursor 绑定完整条件签名，不能仅信任客户端随意指定的 key。计数与该次聚合在同一只读快照产生，不声称不同请求之间冻结。

“旅行回顾”是选定闭区间日期与人物的本地视图，按拍摄日期分组，复用 PhotoLightbox。日期筛选沿现有 EXIF 墙钟语义，跨时区不重新解释历史数据；无日期不混入旅行时间线。第一版不推断出行次数、不生成道路路线、不自动命名城市。用户可把当前条件保存为本地命名回顾，`photo_recaps(id,name,date_from,date_to,person_ids_json,revision)` 只保存选择条件；同名允许，不存照片拷贝。人物删除后显示失效条件，用户修改前不自动扩大为所有人物。

### 底图请求边界

新增仅桌面媒体 handler 可调用的瓦片适配器，输入 provider_id+z/x/y，服务端计算允许的 HTTPS URL；不接受任意 URL。默认 provider_id=osm，跨域重定向拒绝，不携带 BT/AI 凭据、照片参数或本地路径。维护/退出及关闭联网地图取消请求；关闭后不新发请求，已有本地缓存可以继续显示并标注“联网已关闭”。底图失败显示地图底图不可用，照片点和本地时间线仍是独立可用功能，不更换地图服务商。

OSM 请求使用识别 CineInsight 的 User-Agent、保留可见署名，按 HTTP 缓存头缓存并条件更新，不提供区域预下载或批量抓取；磁盘缓存是可清理派生数据、不进备份。设 256 MiB 预算，仅缓存当前视口请求；达到预算时停止请求新瓦片并提示清理/调整，不能以持续淘汰重下的方式规避服务缓存要求。并发最多 2、单请求 10 秒，无自动重试。当前底图部署环境是否可达尚未实测，也不承诺公共服务可用性。

依据：[Leaflet TileLayer](https://leafletjs.com/reference.html#tilelayer)、[OSM 瓦片政策](https://operations.osmfoundation.org/policies/tiles/)，于 2026-11-03 查阅。实施前核对实际依赖版本和服务政策；替换供应商须重新展示隐私范围，不静默切换。

## 10. 片段专题与区间队列

<a id="D-LE-17"></a>
**D-LE-17 · Behavior / Data Contract · Proposed，来源 R-08、R-03。** 专题是有序的书签关系；书签仍拥有时间区间、标题、正文、局部标签和源版本。已有整片队列不改统计语义，新增区间项用于统计中立预览。

`clip_topics(id,name,note,revision,created_at,updated_at)`；`clip_topic_members(topic_id,bookmark_id,position)`，主键(topic_id,bookmark_id)，按(topic_id,position,bookmark_id)查顺序。主题 1:N 成员，书签 1:N 专题成员；成员到两侧有删除级联，原片与书签仍是逻辑关联不级联。删除专题不删书签，删除书签移除所有专题关系并增加涉及专题 revision；确认删除书签时告知受影响专题数量。正文仅在书签维护，不另建专题成员备注副本。

`SaveClipTopic({id?,expected_revision?,name,note})`（name 去首尾空白后 1–100 字、note ≤5000）；`ListClipTopics({cursor,limit})`；`ListClipTopicMembers({topic_id,revision?,cursor,limit})`；`EditClipTopic({topic_id,expected_revision,action:add|remove|move,bookmark_ids?,before_bookmark_id?})`。单次增删最多 200、单专题最多 10000，新增重复书签返回原成员且不移动已有位置；move 必须点名精确成员。分页 revision 不一致返回 conflict，不拼接不同顺序代次。

实现并发：专题关联集合属于书签的版本化事实；实际新增/移除关联、删除专题时，相关书签 revision 也通过条件更新递增，因此旧的编辑或删除影响提示不能覆盖后来变化的关联。删除书签先以调用方 revision 条件认领，再收集受影响专题并逐个 CAS 根；任一零行更新整次回滚。新增重复关联不移动成员。新建书签与首次加入专题仍是一笔创建，不额外制造一次编辑。

入队不修改书签或专题内容/版本：在更新 queue 根 revision 的同一 SQL 条件中检查全部已审阅书签 revision 和专题 revision，形成完整快照 CAS；零行更新拒绝整批，不使用 FOR UPDATE、FOR SHARE 或以等待锁为正确性依据。与来源编辑重叠时，以条件更新的成功检查点确定先后；入队后的队列条目仍是独立快照。专题分页在同一读取快照中返回根版本和成员，不能混合两次顺序。

从场景结果创建书签再加入专题时，两项写入必须同一事务完成；复用 BookmarkService 的校验与事务内保存入口，不能先独立保存后再以异常丢失关联。只有时间点的书签可入专题，连续预览前要求补 end_ms，不猜一个默认长度。空专题不能启动，单片段到末尾停止。

### 入队快照与播放器约束

新增 `PreviewClipQueue({topic_id,topic_revision,bookmark_ids[],queue_revision})` 返回精确有序选择、各 bookmark revision、源版本、区间、不可用原因和一次性 preview_token（10 分钟）。空 selection 不代表整个专题；“全部”先由服务端解析全集并展示数量，超过既有单次 1000 项时要求分批。关闭未提交的确认窗口时调用 `DiscardClipQueuePreview(preview_token)` 撤销该预览；已消费回执保留至原到期时间，避免取消误伤已完成操作。确认 `AppendClipQueue({preview_token,switch_to_inline})` 复核 topic/bookmark/queue 修订和源版本，任何冲突整批拒绝，不默默跳过或扩大；调用原 queue CAS 提交。搜索结果连续预览使用同一事务入口和范围验证，但不为临时预览创建持久书签。

扩展 PlaybackQueueEntry：`entry_kind=video|clip`（旧行默认 video）、`clip_start_ms?`,`clip_end_ms?`,`source_size?`,`source_mtime_ns?`,`origin_bookmark_id?`，以及 `preview_batch_id?`,`preview_position?`,`preview_count?`。clip 四个源/区间字段和三个批次字段必填，start>=0,end>start、1<=position<=count；video 的新增字段全部为空。批次 UUID 在一次确认中生成，全部成员和 position/count 同事务写入，unique(preview_batch_id,preview_position)。queue entry 保存快照，专题后续重排/编辑不会变更已排队区间。来源书签逻辑关联，不因删除书签删除正在播放条目。

预览批次冻结本次有序成员与末项。自动前进只能查找同 batch 的 position+1，绝不能按全局队列位置取下一项；到 preview_count 必须停止，后续追加片段/整片不扩大该批次。连续预览的批次内前进来自用户本次“连续预览”动作，不继承或改写全局整片 autoplay；单条批次只有一项，末尾同样停止。用户手动选择其它全局条目意味着结束当前预览会话，按所选条目原语义开始。

队列中 clip 批次顺序不可局部重排，界面提示回专题重排后重新入队；移除批次成员若影响正在运行的批次则先停止并退休其 token，再提交删除，剩余条目仍可手动播放，但缺少下一 position 时停止并提示“预览列表已变化”。原 video 项的重排/追加行为不受影响，不以新增批次限制普通队列。

区间预览首版只在应用内播放器执行。当前队列是 system/IINA 时，确认页要求用户明确切为 inline；不能默默切换。混合队列存在 clip 时拒绝选择不支持区间的播放器，移除所有 clip 后原选择恢复可用。切换播放器与入队在同一个 queue revision 提交中发生。

| 当前状态/事件 | 守卫与结果 |
|---|---|
| clip 启动 | 原 owner 获取 media lease、核对源版本/时长、从 start_ms 播放；失败保留当前项并显示原因 |
| clip 暂停/继续/seek | 原会话 token 必须有效；seek 夹到 `[start,end]`，到 end 走一次完成事件 |
| 到 end 或源提前 ended | 原 owner 校验 token 和 attempt；到 end 才完成，提前结束为 source_changed/区间不可播放；只在本批次确定成员内前进，末项强制停止，不接全局后续项 |
| 重复 ended/晚回包 | token 已退休则忽略，不跳过第二项 |
| 下一段源已变/失联 | 停在该项，提示核对或用户跳过，不自动播放错误位置 |
| 应用重启 | 沿用队列 interrupted，不自动起播；重启后重验 clip 源 |

clip 全程不写观看进度、play_events、日记、已看或随机次数；按整片观看按钮明确退出区间预览再启动原正式播放。前端进度上报和后端提交两侧都按 entry_kind 保护，不能仅靠 UI 不发请求。区间完成不能走整片自然结束标已看路径。它仍使用原 activePlayer 单播放器协调。

## 11. 章节与带时间点的摘要

<a id="D-LE-18"></a>
**D-LE-18 · Behavior / Data Contract · Proposed，来源 R-09。** ChapterService 拥有人工章节、生成草稿和当前采纳版本；MediaProbeService 拥有从原文件读到的章节快照。两者来源独立展示，不做隐式覆盖优先级。

### 原有章节与人工编辑

ffprobe 增 `-show_chapters`，复用当前有界捕获、超时和源版本检查；[官方文档](https://www.ffmpeg.org/ffprobe.html)明确提供该输出。技术快照加 chapters 投影，旧快照“未读取”区别于已读空列表。原文件章节的坏时间/不可解析内容单独标记为章节不可用，不影响原来正常的容器、时长、编码和音轨快照（保持 D-LE-03 既有行为）；原章节不套用人工稿的标题长度、500章及不重叠限制，复制为人工稿时再完整校验。后台补探测沿用原任务，不在打开播放器时全库探测。

人工章节集合保存 `video_id` 逻辑引用、title_snapshot、source_size/source_mtime_ns、revision；章节成员存 position、start_ms、end_ms、title、summary。首次可从文件章节复制为人工稿；之后重新探测不覆盖人工稿。要求已知时长、时间有限、0<=start<end<=duration，相邻不重叠，允许间隙；标题 1–200 字，摘要≤2000字，最多 500 章。未知时长先明确补全技术信息。删除原片保留人工内容供阅读，回跳显示不可用。

`GetVideoChapterSets({video_id})` 返回来源列表（embedded/manual）、各自 source_status 和 revision；`SaveVideoChapters({video_id,expected_revision,source_version,chapters[]})` 原子替换人工集合，空数组要求 `clear=true`，不修改视频容器；`ResolveChapter({set_id,chapter_id,revision})` 复核源并返回可用定位。章节编辑用同一父 revision CAS，删除/排序/改时间不接受陈旧集合覆盖。

### 自动章节摘要

只针对选中的一部视频、已准备的同名有效 SRT。不会为了生成摘要静默执行语音识别、内嵌提取或发送音视频；没有字幕时展示已有入口。输入快照复用严格 parser，带视频源版本、字幕 fingerprint、已存在人工集合 revision。明示“摘要仅依据字幕，可能遗漏无对白画面”。

`StartChapterDraft({request_id,video_id,source_version,subtitle_fingerprint,expected_chapter_revision,provider_revision,scope:{start_ms,end_ms},confirmed_scope})` 返回 job_id；发起时重读快照并核对披露内容。request_id 是每次明确发起动作的 UUID，唯一入库；同一 ID 与相同请求只返回原 job，不重复外发，ID 与不同内容组合则拒绝。任务 queued 先提交后才能调用模型。首次尚无人工集合时 expected_chapter_revision=0，以 video_id 唯一约束保护创建；其后使用已存在集合 revision。

全文最多 100000 字、字幕 20000 条；超限返回 `summary_input_too_large`，由用户缩小明确区间后重启，不能只送前一部分冒充整片摘要。按不切断 cue 的 8000 字分段，最多重叠 300 字，尾段不丢；每个请求带实际区间及 cue 编号。界面显示生成范围，部分区间的产物只能标“局部摘要”。局部 scope 必须落在 cue 边界，准备时展示扩展到完整 cue 后的精确范围，由用户确认，不能确认后再扩大外发字幕。

模型返回章节标题/摘要及引用的 cue ID，时间由本地从 cue 映射，拒绝伪造 ID、越界、重叠或倒序；段间合并也经过同一验证。以输入片段为证据，不允许模型自由产生外部事实或工具调用。任何一段失败整次草稿标 failed，保留旧人工集合；已有分段结果不展示成完整成功，不自动重试。

状态转换如下，未列转换拒绝；attempt 单调增加，取消后的晚结果不能提交。`draft_ready` 的最后复核与写入保持在已有路径/SRT协调区间内，并由 TextAI 用途 grant 守住短提交，避免字幕替换或用途撤销在核对后穿入；这里不持锁调用模型。

| 状态 | 事件 | 新状态与可见效果 |
|---|---|---|
| queued | owner 获取工作槽 | running，任务中心显示范围与进度 |
| queued/running | 用户取消、关闭能力、维护 | cancelled，清理未完成内存正文，旧章节保留 |
| running | 全部段完成且仍是原源/字幕/配置 | draft_ready，持久草稿，展示校对与回跳 |
| running | 输入变更 | obsolete，要求重新选择/生成，不写新人工集合 |
| running | 外部/校验/保存错误 | failed，显示可处理原因，旧集合保留 |
| draft_ready | 用户确认应用预览且源、字幕及人工 revision 匹配 | applied，按预览范围原子合并，注明生成后采纳 |
| draft_ready | 源/字幕/人工集合变化 | obsolete，保留草稿可读，不直接应用 |
| draft_ready | 用户放弃 | discarded，删除草稿正文，只留最小任务状态 |
| queued/running | 应用中断后恢复 | interrupted，用户显式重新生成，不自动再次付费调用 |

`GetChapterDraft({job_id})` 返回范围、章节、证据 cue 与状态。`PreviewChapterApplication({job_id,expected_job_revision,expected_chapter_revision})` 给出待删除章节 ID、待新增章节、保留数量及 10 分钟 apply_token。全片草稿替换整个人工集合；局部草稿只替换完全位于 scope 内的章节，范围外章节原样保留（含 ID/文本/时间）。已有章节跨 scope 边界时返回 `chapter_range_conflict`，列出这些章节；用户必须先编辑边界或显式扩大范围重新生成，不能自动拆分、截断或删除它们。无覆盖章节时可以在合法空隙插入草稿。

`ApplyChapterDraft({apply_token})` 只对已预览的范围事务合并，并重验 job/人工 revision、源和字幕；新集合仍需全局无重叠。应用状态与集合写入同事务。`DiscardChapterDraft` / `CancelChapterDraft` 分别使用对应 owner 的 revision。重新生成新 job 不覆盖旧 draft。最多展示最近 20 个无草稿正文的终态任务；更旧终态压缩为最小幂等占位（job_id、request_id、请求摘要、terminal status），清除视频引用、内容与诊断字段但不删除唯一 request_id。重复请求命中占位返回 `job_compacted` 和原 job_id，不重新外发；新动作必须使用新 request_id。占位随数据库备份/迁移，保证当前库历史内幂等。draft_ready 和人工章节不自动删除，用户主动管理。持久草稿仅存必要章节输出与 cue 位置/摘要，不复制完整字幕输入。

摘要默认收起；用户展开只改变界面，不改变“已看”。从某章播放是原播放器的明确 seek，不引入第二个播放器。生成任务的诊断只记状态、阶段和模型，不保存网络请求正文。

## 12. 大片库搜索性能评估

<a id="D-LE-19"></a>
**D-LE-19 · Operational Contract · Proposed，来源 R-10。** 此项交付为可重复基线、候选方案对比和采用结论；当前不承诺性能数字或新增索引。现有场景对白是转义后的 `LOWER(text) LIKE` 字面匹配，必须保护这一语义。

评估使用合成数据库，两个后端各覆盖 1万/10万/100万字幕段，空库、小库、常见词/稀有词/无匹配、中文1/2/3字、大小写、标点、`% _ \\` 字面量及人物/标签/时长联合筛选。报告数据分布、查询计划、冷/热延迟 p50/p95、内存、索引体积与写入开销；至少 30 个样本/查询组，串行、固定机器与参数。不访问真实片库做压测，也不从测试规模反推用户实际片库规模。

候选：当前 SQL 索引与分组查询优化；SQLite FTS5 trigram；PostgreSQL 合适的子串索引。评估先查实际打包 SQLite compile_options，不能假定 go-sqlite3 已启用 FTS5。标准全文 MATCH 改变语义，不可直接替换 LIKE。SQLite 官方说明 trigram MATCH 对少于 3 个 Unicode 字符不匹配，且带 ESCAPE 的 LIKE 无法使用该索引；这是本项目短中文词和特殊字符的重要约束。[FTS5 官方说明](https://sqlite.org/fts5.html#the_trigram_tokenizer)。

采纳条件：结果集合与片段位置一致、中文短词不退化为零结果、源变更/删除/恢复不留下幽灵命中、目标规模收益足以抵偿写入和分发成本。若没有足够收益，保留当前引擎并交付评估结论，属于完成评估而非省略已承诺功能。若采用派生索引，必须先在本节补齐维护、重建、中断、迁库和备份合同，再实施；不在本方案凭空加一个后台索引服务或自动回退路径。
