### 临时处理的唯一所有者

`MediaProcessingService`是所有图片编辑导出/压缩和图片/视频试增强请求的临时状态唯一owner：持有不可复用的request ID、当前数据库epoch、媒体源指纹、参数快照、cancel与进程停止回执、私有工作目录和结果token。图片模块沿用既有可见范围与解码规则，副本发布也归MediaProcessingService，EnhancementService只提供模型能力和串行的无状态推理原语，不互持会话表。新增协调器是对原代码缺少该生命周期的窄补充，不变成通用作业平台。

实现接口：`Begin(request)`返回请求状态；`Get(id)`读取并在ready状态复核来源；`OpenAsset(ctx,id,part)`只返回有效且同epoch/同源的只读文件租约；`Save(id, 用户原生选择的路径)`进行最终校验和发布；`Release(id)`停止并释放会话；`StopAndWait(ctx)`先拒绝新请求、取消所有活动请求、等待子进程真实退出后才撤销资源。每个开始仅占用一个共享重处理槽；后端排队和运行都可取消，不允许请求通过轮询重复启动。

App在`app_settings.go`维护入口先关闭MediaProcessingService自己的请求接收门、取消并等待所有请求真实停止，成功后才取得原全局路径/数据库维护锁并替换库；不能先等全局锁排空再执行取消。关闭同样接入原退出守卫。失败或超时保留服务拒绝接收、窗口和待停止对象供显式重试，不能继续恢复/切库，也不能声称尚未取得的全局围栏已建立。恢复失败续跑时先为当前epoch恢复服务接收；成功恢复/重启会创建新服务实例与新epoch。旧请求/旧token永不跨库使用。临时目录在dataDir专用子目录内，只回收带本服务身份的目录，不扫描或删除用户输出。可比较结果与未保存编辑的退出提示分别由会话owner和查看器处理。

从`enhancement_pipeline.go::runChunk`提取不调用updatePhase/transitionStatus的抽帧、单帧推理和编码原语；原持久任务仍由原wrapper更新阶段和检查点。新试处理不得伪造task ID调用现有runChunk，不能取消/清除原持久任务。推理资源的串行边界在EnhancementService持有，两个调用方都必须经过它。

## 视口与轻量编辑

视口保存倍率和归一化焦点。适应尺寸不超过可用画布；1:1明确采用CSS像素对原图像素的既定显示关系，并在真实Retina WebView核实显示倍率。缩放以指针下的图片点为锚，平移在图片边缘夹紧；尺寸变化、信息栏收起与双图布局变化重新计算合法视口。临时放大保留进入前快照，keyup、blur和卸载都恢复。只在最上层查看器且非输入控件内响应快捷键。

两图共享归一化焦点和相对适应倍率，各自按真实尺寸换算；宽高比不同时保留各自空白边，不能拉伸或裁掉一侧来伪造相同清晰度。同步可开关，单侧加载失败不禁用另一侧。图片选择复用原picker，两个ID相同不启动无意义对比。

编辑顺序固定为：方向归一化 → 拉直/旋转/镜像 → 裁剪 → 调色 → 编码。预览和完整导出共用参数与运算；滑块预览可使用缩小图，但导出不得拿预览分辨率冒充原图。编辑导出为明确告知的普通图片副本，格式/尺寸/色彩处理在导出前可见；这与严格保留原容器语义的无损压缩是两条独立路径。撤销至少覆盖本次会话连续操作，恢复原图只清当前参数，按住原图对照不写历史。

解码、导出和增强先按像素与工作集估算资源，超过实际安全上限明确拒绝并说明；不只按文件字节数判断内存。用户源路径、图像内容和处理参数正文不写调试日志。加载失败保留操作草稿与明确错误，不以黑图替代成功。

## 严格无损的证明

压缩能力按输入格式、位深、动画及可用工具返回可处理或具体不可处理原因。实现路径为PNG原数据流无损重压与JPEG系数域熵编码优化；WebP等仅在能证明完整像素和元数据保留时开放，不以格式转码达成“无损压缩”名义。JPEG工具从固定源码构建为macOS15/arm64（D-MU-09），必须随构建正确装配或明确报告缺失，不能以开发机Homebrew已安装代表发布包可用。

PNG保留IHDR、调色板、透明度、方向/色彩/文本等原块语义，仅替换经过验证的压缩数据；不把16位降到8位。动画必须证明全部帧、帧序/时间与循环保留，否则以不支持此输入结束。JPEG不调用普通质量参数重编码，保留额外标记与方向/ICC等；工具完成后核对尺寸、解码像素、元数据及原文件身份。可参考[libjpeg-turbo官方jpegtran合同](https://github.com/libjpeg-turbo/libjpeg-turbo/blob/main/doc/usage.txt)的系数域变换与`-optimize`、`-copy all`，仍需本机测试证据。

准备结果区分`ready`、`not_smaller`、`unsupported`和`failed`。只有ready可保存；显示源字节、输出字节和差额，不将刚保存副本的差额加入已释放空间。保持原格式和扩展名，不能用删除EXIF/GPS换空间。用户选择路径后再次核对源身份与输出，原图/现有目标不可覆盖；并发冲突明确失败，不自动重命名到未经用户选择的目录。

## 试处理与输出生命周期

所有预览由后端核对可见性、源文件版本及请求身份。前端只传媒体ID、合法参数与有界选区，不传任意可读文件路径。临时资源只经受控随机token路由读取，不能由前端指定磁盘路径或遍历会话目录；不同库/源/请求不得互读。读取再验证当前会话和文件身份，图片/视频请求有明确尺寸、区间、运行时限与输出上限。

| 当前状态 | 操作/条件 | 结果 |
| --- | --- | --- |
| 空闲 | 合法来源及参数开始 | 准备/处理中；登记可取消任务 |
| 准备/处理中 | 来源改变、取消、关闭、维护或退出 | 作废本请求，停止子进程并清理临时产物；迟到结果丢弃 |
| 准备/处理中 | 校验成功且请求仍有效 | 可比较结果；保留有限临时文件 |
| 准备/处理中 | 失败/超限 | 明确失败并保留原图/原片；不发布残缺结果 |
| 可比较结果 | 调整参数或重选来源 | 作废旧结果；显式开始新请求 |
| 可比较结果 | 保存副本 | 原生保存框，取消无效果；临时写入/校验/不覆盖发布，返回实际保存结果 |
| 可比较结果 | 明确运行整片增强 | 调用原CreateTask；不复用试处理token作为整片授权 |
| 任意 | 过期token/旧代次请求 | 返回失效；不能取消或覆盖新请求 |

图片选区使用原图坐标并处理必要上下文边缘；对比以相同源范围呈现，不能把2×结果按两倍显示尺寸营造虚假清晰度。视频样片支持明确起点及5～10秒范围，末尾不足时用户可选择合法短区间；不擅自改起点。输出时间从零开始，前端以源起点映射同步位置，音频不双重播放，整片推理与试处理不得并发占用同一增强资源。VFR、HDR、音轨与字幕支持沿用原增强的实际能力，不能因是样片绕过原输入检查。

临时结果总量有界，活动会话不会被另一会话误删；释放后不存在仍可访问的旧路由。关闭等待实际进程停止，停止失败明确保留待清理状态，不报告已结束。现有持久超分任务的断点恢复保持，临时试处理不会占用或清除它的检查点。

## 目标空间方案

磁盘选择来自可见媒体所在的在线卷，显示实际可用字节与采样时间；用户输入的是希望额外释放的GB，不能混为“最后保留这么多空闲”。物理卷身份复用原扫描/迁移和空间检查能力，离线卷不给清理方案，不能按目录字符串冒充物理卷。

方案行至少有媒体类型/ID、原因、原大小、可回收估计、是否待复核、保留对象、收藏/评分提示与原清理入口。已知重复候选保留现有保留锁，至少一份保留；以物理文件身份去重跨类别/路径，硬链接只在实际释放条件成立时估计，无法核实不当确定可回收。不同卷分别计，不把另一盘副本的大小算入目标盘。APFS克隆或共享块无法准确估计时明确逻辑估计，不承诺实测释放相同。

有效保护快照由`CleanupReviewPanel`和`PhotoCleanupPage`各自提供，只投影原owner的分析身份、保留覆盖、ignoredGroupKeys、选择修订及`cleanupSelection.js::lockedIDs`计算结果。App仅转交不可变快照，不另建一份可写审阅状态。保留锁合并须复用同一纯函数，不能在StorageReportService重新实现推荐保留策略。当前库epoch、分析身份或审阅修订任一变化立即使对应方案失效；owner未挂载或快照不可取得时，对应重复候选和已知组成员不计入确定方案，并明确提示先打开清理审阅，不按“没有保护”处理。久未观看候选也须排除快照中的锁定ID与未知保护的已知组成员。

只读方案请求携带上述快照身份和已计算保护集合，后端核实库/分析身份后选取可见媒体；这些输入只能减少候选，不能授权删除或访问不可见媒体。进入原清理页时传分析身份、目标媒体ID和原因的待审阅草稿，由原owner按最新状态裁剪，并在不一致时作废旧选择提示重新核对；不是直接覆写原owner的选择/保留状态。方案中的用户调整与快照修订相绑定。

候选构建用有界分页读取，不把原体检最多500条显示上限当成全量候选。输入变化清除旧方案；候选达到显示上限时说明截断与未覆盖部分，不把未列出的数据默认为已审阅。建议累计到目标后停止默认推荐，用户仍可调整；精确重复与待确认分别汇总。缓存清理仅来自原owner可枚举的可重建缓存，不删备份、模型、源文件或保留中的检查点。

只读方案不生成“批量删除令牌”。用户进入原清理时重新加载/核对原分析及当前来源；方案中的选择是待核对草稿，不能绕过旧流程的确认、保留锁或撤销。处理后报告本次已处理文件和磁盘重新采样值，不把移到同卷废纸篓的逻辑字节算作已释放。目标未达成保留真实缺口，不自动执行后续候选。

## 数量与视频缩略图

数量输入为整数1～12，默认6，以独立localStorage键保存合法值，读取损坏或存储不可用时使用明确默认且不影响打开。数量变化沿原300ms代次隔离重新抽样，数量不回写随机条件。候选不足不重复凑数；换一批保留原“无更多候选仍保留上一批”行为，错误与空结果区分。

缩略图时间映射夹在0到合法片尾内；指针事件合并，单卡最多一个进行中的取帧与一个最新待请求。仅可见且当前交互的卡片读动态帧；离开/失活/卸载撤销，未命中缓存时沿原取帧服务限额，不另开无界请求。概览只在用户显式展开时加载有界采样帧。点击定位携带本次源版本和时间，沿原详情预览入口，不把浏览改为正式播放。

### Verification Strategy

TC-01/02/07由视口纯计算、组件代次/预加载测试及真实WKWebView手势夹具验证；TC-03/04由合成方向/透明/高位深样图、预览与导出比对及文件失败注入验证；TC-05/06由PNG/JPEG等格式保真与元数据逐项核对验证，不以“文件能打开”作为无损证据。TC-08/09由悬停请求合并、定位、数量边界和陈旧回包回归验证。TC-10/11用临时卷身份/硬链接夹具、重叠清理类别、候选不足、离线/源变化与真实free-space采样语义验证。TC-12/13使用可控推理替身验证状态/取消并用随包真实runtime及合成素材完成局部/短样片检查。

文档推演：用户请求100GB但当前盘只有40GB合格候选时，返回40GB与60GB缺口；不能借其他盘或待清空废纸篓补齐。源在压缩后发生变化时，保存/清理重新核对并拒绝旧输出动作，原图保留。PNG已经最优时返回not_smaller，不制造新文件。数量从6改1而旧6条回包迟到时，旧代次被丢弃。以上为合同推演，尚非执行测试。
