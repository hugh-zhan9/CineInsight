# 观看回顾：实时 / 月度 / 年度

状态：2026-10-11，Ready。用户原话：“在视频和图片增加一个播放/查看次数，基于此和现有数据可以弄一个月度回顾，比如这个月你最爱看的是xxx，标签是xxx，相关视频还有xxxx 等等一些信息，这部分你可以拓展，增加一些趣味性。除了月度还可以有年度和实时。”用户授权由设计方拓展内容，下面的产品取舍为设计方默认，用户可再调整。

## 事实来源与新增数据

<a id="D-RECAP-SOURCES"></a>
**D-RECAP-SOURCES · Data Contract**

- **视频播放**：复用只追加的 `play_events`（`desktop_play`、`desktop_random`、`inline_view`、`mobile_feed`、`jellyfin_view`、`legacy`），按 `played_at` 落入时间窗；`videos.play_count` 仍是既有的“正式播放次数”，不改口径、不回填。`legacy` 只有历史最后播放时间，计入总数但单独标注，不参与“新发现/重温”判定。
- **图片查看（新增）**：`image_view_events(id, image_id → images ON DELETE CASCADE, viewed_at, source, created_at)`，索引 `(image_id, viewed_at)`、`(viewed_at)`，只追加；`images` 增加 `view_count`（默认 0）与 `last_viewed_at`，与事件在同一事务内更新。来源 `desktop_viewer`（桌面查看器显示该图满 1.5 秒）与 `mobile_feed`（手机端已有的图片查看计数处同时记事件）。同一图片同一来源 30 分钟内只记一次（以数据库里该图最近一条事件判定，不靠内存），翻来翻去不灌水。软删除保留事件，永久删除级联。迁移不回填（没有历史时间点），手机端已有的 `view_count` 不合成事件。
- **展示**：视频行与详情显示“播放 N 次”（`play_count` + 时间窗内事件按页面口径），图片单图详情与查看器显示“查看 N 次”。
- 不推算观看时长：回顾只用次数、天数、时间分布等事实，延续“缺失历史不编造”的既有裁定。

## 回顾内容

<a id="D-RECAP-CONTENT"></a>
**D-RECAP-CONTENT · Behavior Contract**

一个服务 `RecapService.GetRecap({period: live|month|year, year, month})` 按本机时区计算时间窗：实时=今天 0 点至今（附近 7 天逐日），月度=自然月，年度=自然年；未结束的月/年标“进行中”。返回只读事实与据此生成的文案：

| 区块 | 内容 |
| --- | --- |
| 总览 | 播放次数、看过的不同视频数、图片查看次数与张数、活跃天数、最长连续活跃天数、与上一同期相比的增减（上一期无数据时不显示百分比） |
| 本期最爱 | 播放次数最多的视频（并列取最近播放），附它的标签、人物、作品集、本期播放次数；“相关视频还有”：与它共享标签/人物/作品集最多、且本期没看过的片库视频（按共享数、评分、最近入库排序，最多 6 部）；本期最爱的图片同理（按查看次数） |
| 排行 | 视频 Top 10（次数）、标签 Top 10（按播放加权，排除带 automatic_kind 的自动标签）、人物 Top 5、作品集 Top 5、图片 Top 12 |
| 习惯 | 每天/每小时分布、最忙的一天、最常看的时段、周末占比、深夜（0–5 点）占比、来源占比（桌面/内嵌/手机/Jellyfin/随机） |
| 新鲜度 | 新发现（本期第一次出现播放事件的视频，排除 legacy）、重温（本期播放且本期开始前已有事件的视频）、本期新评分/新收藏数 |
| 称号与趣味 | 由事实按固定规则给出 1–3 个称号与说明：夜猫子（深夜≥30%）、周末影迷（周末≥60%）、重温派（重温占比≥50%）、探索家（新发现≥50%）、连续打卡（连续≥7 天）、标签专一（Top1 标签占比≥40%）、图片控（图片查看次数≥视频播放次数）等；每条带依据数字，绝不编造 |
| 年度附加 | 12 个月柱状、每月之最（各月 Top1 视频）、全年 Top 标签演变（每季 Top3） |
| 实时附加 | 今天的播放/查看流水（最近 30 条，时间+媒体+来源）、近 7 天柱状、正在播放（待播队列当前项或 2 小时内最后一条播放事件，仅作提示）；页面可见时收到 `recap-activity` 事件刷新，另每 60 秒兜底刷新 |

空期（无任何事件）显示空态与引导，不出称号。所有排行按 ID 稳定排序；查询一次性聚合，Top 列表只水合需要的行（标签/缩略图），不全库加载。

## 界面与入口

<a id="D-RECAP-UI"></a>
**D-RECAP-UI · Behavior Contract**

顶栏「片单」组新增“回顾”页，页内三个分段：实时 / 月度 / 年度；月度与年度带上一期/下一期切换。用户要求（2026-10-11）：页面要有设计感与动感、以视频和图片为主角，不能只是柱状图。采用叙事式版面：本期最爱的全宽主视觉用该片多个时间点的真实画面（`/preview/frame/`）交叉淡入并缓慢推拉，叠加大字号文案、标签与人物；热门视频海报墙/缓慢滚动的胶片条、热门图片瀑布拼贴、“相关视频还有”横向卡片条；数字进入视口时滚动计数，区块依次淡入；标签云按权重缩放、称号做成带依据数字的徽章卡；24 小时分布与日历热力作为次要视觉。实时页为带缩略图的动态流水与“正在播放”卡，年度页为“每月之最”胶片条。遵守 `prefers-reduced-motion`，图片懒加载并限制并发取帧，深浅色均适配。点击视频打开详情抽屉、点击图片打开查看器入口（跳转到图片页定位）、点击标签跳到片库并按该标签筛选。复用既有缩略图路由与样式原语，深浅色均适配。观看笔记里原有的“年度回顾”（日记口径）保留，回顾页年度视图附“查看观影日记”链接。

## 实现记录（2026-10-11）

**落点。** 模型 `models/image_view_event.go`（`ImageViewEvent`，`AllModels` 末尾）与 `models.Image.ViewCount/LastViewedAt`；写入 `services/image_view_events.go`（`recordImageViewTx`、`ImageService.RecordImageView`）与 `services/short_feed_service.go` 手机端看图同事务；通知 `services/recap_activity.go`（播放事件各写入点提交后调用，App 转发为 `recap-activity`）；计算 `services/recap_{types,window,tally,habits,rankings,related,facts,titles,steps,extras,assemble,service}.go`；App `app_recap.go`：`GetRecap(RecapRequest) → RecapResult`、`RecordImageView(imageID) → ImageViewResult`。前端 `RecapPage.vue`、`components/recap/*`、`utils/recap.js`；照片页查看器 1.5 秒计时与 `locateImage`；片库 `applyTagFilterCommand`；行与抽屉的“播放 N 次”。

**按本设计默认、可再调整的取舍。**
- “播放 N 次”在片库行与详情抽屉显示 `videos.play_count`（正式播放口径不变）；回顾页里的次数一律是时间窗内的事件数。
- 新发现 / 重温：legacy 可以作为“本期之前看过”的证据（判重温），但期内首条是 legacy 的视频不算新发现；只有 legacy 的视频不参与判定。
- “本期新评分”：片库评分没有时间戳，无法归期；改为报告期内带评分的观影日记条数，并在页面注明。新收藏按 `favorited_at` 落在期内且至今仍收藏。
- 习惯分布与周末 / 深夜占比按“活动”计：视频播放与图片查看各算一条。深夜指 0:00–5:59。
- 称号占比类要求分母至少 3 条；一个都不满足时给只陈述条数的“记录者”；多于三个时按超出阈值的倍数取前三。
- 进行中的期次与上一期同样长的一段比较；已结束的期次与整个上一期比较。
- 实时分段只在页面可见时随 `recap-activity` 刷新（防抖 600ms）并每 60 秒兜底；月度 / 年度在回到本页时静默刷新一次。
- 正在播放：待播队列状态为 starting / playing / dispatched 时取当前项，否则取 2 小时内最后一条播放事件。
- 点图片：已在照片页当前结果里就直接开查看器，否则切回照片流、清掉其余筛选、按文件名搜到这一张再打开。

**并发说明。** 30 分钟去重是“同一事务内先查最近事件再写”。SQLite 以 `_txlock=immediate` 串行写事务；PostgreSQL 读已提交下两个几乎同时的同图同来源请求理论上可能各记一条（查看器每次停留只上报一次，实际不会出现），未加锁。

**验证。** Go：`services` 下 `TestRecap*`（月 / 年 / 时区边界、空期、并列、标签排除、相关视频排除、新发现与重温、上一同期、称号阈值、实时窗口、习惯、软删与级联、图片最爱、提交后通知）与 `TestRecordImageView*`、`TestShortFeedImageViewAppendsDedupedViewEvent`，SQLite 与 PostgreSQL 均通过；迁移往返 `TestMigrateCarriesImageViewEventsAndCounters`。前端：`RecapPage.test.js`、`utils/recap.test.js`、照片页计时与定位、片库标签筛选、App 导航。变异检查 6 项（去重边界、月末边界、相关视频排除、称号阈值、自动标签排除、晚到响应）均使对应测试失败后原样恢复。视觉：临时 harness 用无头 Chrome（CDP）截取浅 / 深色的月度、年度、实时、空态，1024 与 1440 宽。真机（真实片库的帧加载速度、WKWebView 下的动效表现）未验证。

**2026-10-11 用户裁定：** 已删除或已移除（路径失效）的视频与图片没有预览图，回顾不再展示：本期最爱、各类排行、相关推荐、新发现样本、每月之最、实时流水与正在播放只取仍可用的媒体（`recap_availability.go` 一次批量判定）；总数、习惯分布与新发现/重温计数仍是期内事实，照常统计。
