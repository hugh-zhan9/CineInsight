## 随机序列与场景

<a id="D-ME-06"></a>
**D-ME-06 · Data / Behavior Contract · Accepted；来源 U2–U3，细化 [D-ME-03](概要设计.md#D-ME-03)。**

### 身份与范围

范围 `all | video | image` 各有一个状态。模式 `gallery | wall` 只属于显示方式，不新开随机轮次。

候选单位：`image:<id>`、`video:<id>`、`version-group:<id>`。读取视频可见性后归并现有版本组；同组均匀选一个可见成员作为本轮代表，保存代表 ID 和本轮成员 ID 集合。图片和无组视频各为单项。全部范围在归并之后按候选单位均匀洗牌，不按文件夹或类型加权。

首次初始化读取完整候选的必要 ID/版本关系，在 Go 中无放回洗牌并持久化顺序；不 `ORDER BY RANDOM() LIMIT N`，不截取前 N 个候选充当全库。初始构建需要 O(N) 轻量 ID 数据和 O(N) 状态行，N 为该范围候选数量；不加载所有封面、完整模型或字幕。数据库事务中不得执行 stat、抽帧、读取图片或外部调用。

初始候选读取采用同一读取快照；后续列表变化不自动改变当前场景。候选只是当时的引用，发出项和实际打开媒体均要通过当前 owner 再核对可见性。查询故障整次失败，不能把只读到的视频或图片当作“全部”成功返回。

### 持久化模型

| 表 | 关键字段与含义 | 约束 / 访问路径 |
| --- | --- | --- |
| `media_exploration_states` | `id`；`scope`；单调 `revision`；随机 UUID `round_id`、`scene_id`；`scene_sequence`；`view_state`（结构化序列化，见下）；`last_request_id/hash/kind/result_revision/result_scene_id` | `scope` 唯一；每个当前库最多3行。revision 用 int64，不能随重新洗牌归零。 |
| `media_exploration_entries` | `id`；`state_id`；`unit_key`；`media_kind`；`media_id`；`member_ids`（版本组快照）；`order_position`；`presented_at` 可空；`scene_id` 可空；`slot` 可空；`sample_points`（最多3个毫秒位置及其来源版本） | FK→state；唯一 `(state_id, unit_key)`；索引 `(state_id, presented_at, order_position, id)` 用于未展示池，`(state_id, scene_id, slot)` 用于当前墙。仅保留当前轮，不做终身浏览日志。 |

`view_state` 仅包含模式、墙倍率/平移、画廊当前项及当前批次最多24个entry_id、选中项；接口必须返回结构化字段，不传 JSON 字符串给前端。记录尺寸设置上限16KiB，不写媒体字节、路径、查询文本或凭据。`member_ids` 是逻辑引用，不级联删除媒体；媒体删除后保留本轮“已展示”事实直到换轮，避免恢复文件后立即再次推荐。

每个 entry 只属于一个 state；state 最多一个当前 scene；scene 的成员由 entries 的 `scene_id + slot` 表达，没有第三份媒体库或常驻全文元数据副本。显示标题、可用状态、缩略图 URL 在有界读取时由原 owner 投影。

### 关键流程

```text
打开范围 → 无状态：初始化候选与首场景 / 有状态：读取当前场景
    ↓
先返回轻量位置索引，再按视口读取卡片和缩略图
    ↓
成功显示并满足展示阈值 → 确认展示（原子写入）
    ↓
用户换墙 → 提交尚未确认的展示 → 释放旧场景未展示项到剩余池尾
    ↓
同步新增/删除可见候选，选出最多1024项并保存新scene和固定slot
    ├─ 有未展示候选：返回实际数量，不填充重复项
    ├─ 无候选且库本身为空：返回空库
    └─ 无未展示候选：返回本轮结束，等待用户重新洗牌

任何数据库失败 → 整次回滚，保留原scene；不先清空屏幕
```

1. 展示确认阈值定义在概要；缩略图 `load` 成功是必要条件。后台页、遮挡在大预览背后的墙、预加载区不计时。窗口失焦时暂停累计；重新可见后重新满足连续300ms。
2. 确认以 `scene_id + entry_id` 绑定，校验整批属于当前场景再写；重复确认保留首次 `presented_at`。不允许前端提交任意媒体 ID 来消耗候选。
3. 换墙必须先成功确认积压展示，再在同一状态 owner 下完成旧预留释放与新预留。确认失败时保留墙和待确认项，显示“浏览进度未保存”，不默默清空记录继续换批。
4. 释放的未展示项按旧场景随机次序追加到已有剩余项之后；新入库项随机插入剩余部分。当前场景的 slot 永不改写。下一次分配重新编号 slot，而不是改已有画布。
5. 先计算新候选是否存在，再决定替换scene；无剩余时保留旧scene/slot并返回本轮结束。有新场景时，真正展示过的旧scene项保留 `presented_at`，清除旧scene/slot。进入详情期间保留当前场景，不提供无限历史墙；成功换墙之后不承诺回到更早墙。
6. 重新洗牌是显式新轮：先捕获刚结束场景已展示单位，重建候选并清空本轮展示状态，`round_id` 更新、revision递增。候选足够时把刚展示单位放在其他单位之后，各分区内部均匀随机；候选不足时只能减少相邻重复，UI不得声称完全避免。
7. 不可见项在分配时跳过，已展示记录保留；当本轮不可见项恢复可见时，未展示的重新进入剩余池，已展示的仍不再发出。不能删除展示记录来“修复”计数。
8. 版本组变化由库事件提示，不在用户眼前重排。结构重算在下一次显式换墙时进行：按旧entry的成员ID传播已展示事实，新候选与本轮已展示成员有交集即按已展示处理；合并不复活已展示项，拆分保留成员的旧状态。未展示成员重新归并。当前scene保持旧身份快照，`refresh`只把受影响格子标为“版本关系已变化，请换一墙”，不把两个旧slot合成一个新slot。当前预览中发生来源变更先关闭旧来源；数量可变化，不伪称轮次初始总量恒定。
9. 条目缩略图生成失败不计展示，换墙仍允许释放；若剩余只有失败项，说明“剩余内容暂时无法预览”，允许用户主动重试或重新洗牌，不将失败数量算进已浏览数。

### 状态转换

| 状态 / 操作 | 守卫 | 结果 |
| --- | --- | --- |
| 未初始化 → 打开 | scope合法、非维护 | 原子建立状态及首场景；空库为成功空结果。 |
| 当前场景 → 确认展示 | epoch、revision、scene匹配 | 原子更新首次展示时间，返回新revision。 |
| 当前场景 → 换墙 | 积压确认完成、版本匹配 | 原子释放、补候选、分配新scene；若耗尽则保留旧墙并给结束状态。 |
| 当前场景 → 保存视口 | 版本和scene匹配 | 仅保存视口，不改变候选、展示或播放事实。 |
| 本轮结束 → 重新洗牌 | 用户显式触发、版本匹配 | 新round/scene，revision继续递增。 |
| 任意 → 维护/切库/退出 | 沿用现有准入围栏 | 禁止新写入、停止读取和预览；完成已准入短事务后再切换。 |

未列出的动作、旧场景操作或未知枚举拒绝；不自行换库、重抽或重试。

## 接口、事务和异步边界

<a id="D-ME-07"></a>
**D-ME-07 · Interface / Data Contract · Accepted；细化 D-ME-05/06。** 仅新增桌面 Wails 绑定，原绑定语义不变，不新增对外 HTTP 查询服务。

| 绑定 | 请求与上限 | 返回及用途 |
| --- | --- | --- |
| `OpenMediaExploration` | `scope` 必填；首次建立通过唯一scope约束 | 返回当前快照，已有状态时只读；初始化竞争失败读取已建立状态，不建立第二轮。 |
| `GetMediaExplorationItems` | 当前 `database_epoch/scope/scene_id`、`entry_ids`，1–256个，须属当前scene | 原序返回卡片投影；已删除/不可见单项返回明确 `unavailable` 占位，数据库查询故障整次失败。 |
| `UpdateMediaExploration` | `database_epoch/scope/round_id/scene_id/expected_revision/request_id`；`action` 枚举 `present/next/save_view/reshuffle/refresh/sample`；action对应结构化payload | 返回新快照或明确错误；单范围客户端串行提交，禁止旧坐标写覆盖新scene。 |

快照字段：`scope`、`database_epoch`、`round_id`、`scene_id`、`revision`、`view_state`、`status`（`ready/empty/round_complete`）、`available_count/presented_count/remaining_count`、轻量 `entries[{entry_id,slot,kind,media_id,presented}]`、最近操作回执。entries≤1024。计数反映最近一次候选同步的可见集合，标出库已变化状态；不把首次总量当实时事实。

卡片投影字段：`entry_id, kind, media_id, title, thumbnail_url, aspect_ratio?, duration_ms?, unavailable_reason?`。缩略图 URL 由服务器原 owner 生成，不接受客户端路径或任意 URL。视频来源指纹在选中时通过既有会话获取，不为整墙同步 stat 原片。未知尺寸/时长为null，不用0冒充有效值。

`present` payload 为最多256个 entry ID；`save_view` 为范围校验后的倍率、平移、模式和selected entry；坐标必须为有限数值，选中项必须属于scene。`next/reshuffle/refresh`不接收自定义SQL、权重或候选ID。`refresh`用于用户接受库变更后重新核对当前场景的可用性，保留已有slot；版本关系的结构重算留到next，不暗中换墙。

写操作在事务内先以 `id + revision + round_id + scene_id` 条件更新根状态并递增revision，影响0行则全部回滚。随后写相关entries和回执，任一步失败整次回滚。数据库可因内部DML加锁，但不新增 `FOR UPDATE`、显式表锁或 advisory lock。仅事务本身不被当作排他保证。

请求身份为 `request_id = expected_revision十进制 + ":" + UUID`，服务端严格验证前缀等于expected_revision；完整request_id才是身份，改前缀是新身份。最近操作的 `request_id + payload_hash` 防止回包丢失后重复发新墙。同ID不同载荷拒绝；同ID同载荷且仍是最近操作，返回原scene/结果revision及当前可读取投影，不再次执行。更早操作带旧revision时拒绝，原完整request_id不能绑定新revision；不承诺追踪所有历史UUID后缀。客户端结果不明先读取快照/回执，未确定之前不提交下一项；不增加自动重试循环。幂等保证是副作用不重复，不承诺媒体标题永远不变。

`sample`只接收一个当前scene的视频entry_id及`source_version`，后者来自选中后的现有预览会话。先通过当前可见性及已有路径协调边界核对实际文件指纹，再生成合法随机毫秒点；短事务与根CAS一起写该entry最近3个点和source_version，快照返回该项取样范围。同身份恢复同一点；提交前取消不落库，提交后回包不明按回执恢复。取帧/解码在事务之外。源版本变化返回source_changed，不沿用旧位置，不自动替新文件取样。

所有绑定沿用结构化 `{status,data,error:{code,message}}`，错误包含`code`和中文`message`；普通错误不解析Go错误字符串来推测成功。拟议码：`invalid_request`、`exploration_conflict`、`exploration_stale_scene`、`exploration_database_changed`、`exploration_unavailable`。维护/待重启沿用原围栏结果。应在App边界明确映射并测试，不把内部异常直接拼进UI。

`database_epoch`为当前服务实例/库生命周期标识，重启或重新连接后改变；持久化scene可以恢复，但旧页面请求不能写入新生命周期。切库/恢复使全部迟到响应失效。两客户端竞争时只有一个CAS获胜，另一侧保留旧画面并提示刷新，不自动覆盖。

前端每次打开、换scope、换scene、隐藏或切库增加generation；加载响应必须同时匹配generation、scene和数据库实例。隐藏关闭预览并取消尚未开始的资源请求，不让晚回包重开窗口。视口保存每次手势结束后合并一次，最多每秒一次；显示坐标即时本地变化，不逐帧写数据库。崩溃时恢复到最后确认保存的视口，不能承诺未提交手势也恢复。

## 二维几何、资源和播放

<a id="D-ME-08"></a>
**D-ME-08 · Operational / Behavior Contract · Accepted；来源 U1、U4–U5。**

### 几何

世界格边长160，间隙2，固定32列。`x=(slot % 32)*162`、`y=floor(slot/32)*162`；屏幕坐标为 `world*scale + translation`，scale限0.2–2。图像到达不参与几何计算，窗口resize只重算视口，不重算slot。

缩放锚点p：先求 `world=(p-translation)/oldScale`，再令 `newTranslation=p-world*newScale`。只有到边缘约束时才允许夹紧导致锚点偏移；内容小于视口时居中。平移范围保留一小段边缘留白，不允许把整个墙拖出视口后找不回。

二维窗口按变换逆投影计算可见行列，向外预取一行一列。上限为当前1024项，不能为全库建DOM。只保留当前场景索引和当前视口图像引用；放大时卸载视口外图像节点，不仅CSS隐藏。手势过程使用requestAnimationFrame合并计算；拖动超过5px按拖动处理，pointerup不再触发点击预览。

键盘焦点与绘制节点分离，复用现有虚拟列表的焦点停靠思路而非复制整套行布局。缩放和换墙后选中项的aria文字更新；减少动态效果偏好下禁用缩放补间，几何结果相同。

### 播放 owner

给 `InlineVideoPlayer` 增加明确用途 `playback | browse-preview`，默认playback以保护既有调用方。browse-preview通过现有session/media资源打开，复用播放控件与区间定位；不创建正式观看tracker、不发watch-progress写回、不自动建立代理，不接管全局队列。切换用途销毁旧播放会话，不能复用同一tracker“改个标志”继续累计。

8秒边界由播放器已有区间机制扩展到只预览用途，暂停/seek/结束只影响局部预览。不能调用会把片段追加到持久队列的 `SearchPreviewHost.prepare` 来实现点击预览。

大预览点击视频「打开详情」时先停止局部播放器并释放资源，再经App观看导航进入详情；已有队列的暂停、接管沿用现有正式播放交互，探索页不私自清空队列。图片大图仍由PhotoLightbox按原规则记查看。各入口均须复核可见性，不能仅凭持久scene中的旧ID绕过当前范围。

### 探索资源的来源与范围核验

探索缩略图、完整图片、视频媒体和指定时间帧URL带专用探索上下文（database_epoch、scope、scene_id、entry_id；取样媒体另带source_version）。资源处理器`preview_asset_handler.go`在探索分支通过探索服务核对当前scene成员、媒体类型/ID和当前可见性，不能只调用GetVideo或loadImageForAsset；旧无参数路由行为不变。持久entry引用不是读取授权。

视频取样播放/帧读取须匹配该entry保存的样点来源版本。媒体读取在路径协调区间取得原文件描述符并核验fstat，与已批准source_version匹配后再服务Range；直接源使用这份描述符，不能核验旧路径后重新打开新路径。已有代理仍由原代理owner判有效，并保留原文件指纹核验。每个后续Range重新核验范围和来源，读期间检查描述符指纹，源被原位修改则中断；页隐藏关闭video并取消请求。派生图生成前后复核源指纹，失败不缓存为有效结果。既有无参数播放路径不因此改语义。

## 存储升级、故障和退出

<a id="D-ME-09"></a>
**D-ME-09 · Operational Contract · Accepted；细化 D-ME-05/06。**

- 新表无历史回填，首次打开范围才建轮次；注册顺序state在entry之前。迁移使用现有数据库设施，测试覆盖SQLite和PostgreSQL。逻辑媒体引用不改变原媒体删除语义。已展示组改变成员时，在同一entries表保留不可见的history行（旧成员快照与首次展示时间），当前单位更新为新成员；history只参与本轮展示传播、不进入候选，换轮一并清除。
- 数据库备份包含探索进度；双向迁移保留round、scene、排序和展示事实，重启后更新epoch。恢复旧备份意味着回到备份时的探索进度，这是备份语义，不跨备份另建隐形去重记录。
- 旧版本应用忽略新表；回退不删新表。旧应用对媒体的变更由新应用重新打开时按当前可见性核对。小图缓存不需要迁库，可从媒体重建。
- 维护先停止新探索命令与媒体工作，再等待已准入事务，复用项目维护owner；探索页不另设一套全局维护状态。退出尽力完成已准入展示确认，失败明确说明未保存，不能假称所有曝光已持久化。
- 数据库写入失败保留画面和待确认项；缩略图或原片单项失败保留位置和失败说明。只有用户的换墙/重试/进详情触发下一步，不新增网络、自动转码或跨提供方回落。
- 正常关闭增加探索flush握手：探索前端曾打开后，beforeClose先拦截一次并发带request_id的事件；重复关闭合并。前端暂停曝光/交互、串行确认积压曝光和最终视口，回执成功后再进入原任务退出守卫。App校验回执request_id，旧回执不能放行新关闭；5秒未完成或保存失败保留窗口并显示重试/仍然退出，后者须用户明确选择，绝不自动丢弃后退出。原任务确认框若取消，再次关闭需重新flush。内部恢复、待重启及RelaunchApp继续原放行，不尝试向已关闭数据库写入。
- 本轮无需部署、安装、提交或变更真实用户片库。
