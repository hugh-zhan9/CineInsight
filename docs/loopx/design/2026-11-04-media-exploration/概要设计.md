# 随机画廊与可缩放媒体墙 · 概要设计

状态：v1.1，2026-11-04，Accepted for implementation。用户在设计交付后要求「给出执行计划然后可以开始了」，授权按本设计实施；实现及验证记录见执行计划。

详细合同：[需求设计文档](需求设计文档.md)。实际WebView验收：[媒体墙截图](媒体墙验收.png)（合成素材）；视觉示意：[媒体墙线框图](媒体墙线框图.png) · [可编辑SVG](媒体墙线框图.svg)（示意素材，不读取个人片库）。

## 1. 用户要得到什么

本轮会话是需求来源，以下保留原意和关键原话，作为后续实施的验收依据：

| 来源 | 已确认的需求 |
| --- | --- |
| U1：「我不想嵌入过多AI的内容和调用」 | 体验不依赖新增 AI 能力或调用。设计选择第一版零新增模型、零外部 AI 请求。 |
| U2：「那如果我没有判断呢」并认可自动发现候选 | 不要求先标注、精选、制作书签或判断精彩片段。 |
| U3：「更加希望是视觉上的，然后足够随机的，不要翻来覆去就推荐那几部」 | 内容画面占主位；随机应覆盖整个候选库，避免反复推荐少数内容。 |
| U4：「媒体墙，由很小很小的图片/视频组成，可以缩放比例」 | 图片和视频画面可以密集排列，支持连续缩放。 |
| U5：「点击变大/或者点击一下变成对应的详情页」 | 单项可放大或进入对应详情；具体点击分工由本设计提出。 |
| U6：「嗯，设计一下吧」 | 设计阶段交付设计，未改业务代码。 |
| U7：「给出执行计划然后可以开始了」 | 已授权给出计划后按本设计实施；不包含提交、安装或部署。 |

验收表达：不用整理片库即可开始；缩小能浏览大量真实画面，放大能看清；对内容产生兴趣后可以直接查看；候选充足时持续换批不会重复发出本轮已经展示的内容。

## 2. 一个入口，两种看法

<a id="D-ME-01"></a>
**D-ME-01 · Behavior Contract · Accepted；来源 U1–U4。** 观看导航增加「探索」，内部切换「随机画廊 / 媒体墙」。首开为媒体墙，两种视图共用当前场景、候选顺序和展示记录。保留原视频页、照片页、管理布局及随机播放行为，不替换它们。

顶部只保留：媒体类型「全部 / 视频 / 图片」、视图切换、「换一批 / 换一墙」（空库或本轮结束时为“查看新内容”，可发现新入库项目）。底部浮动缩放条包含缩小、滑杆、放大与「适应窗口」。不把标签编辑、清理、AI 配置放进浏览过程。

- **随机画廊**：每批最多 24 项，卡片较大，便于逐个观察。下一批优先取当前场景内尚未展示的项目，再申请新场景。
- **媒体墙**：一个场景最多 1,024 项，固定 32 列，像地图一样平移和缩放。数量不足时按实际项数排，不复制内容补满。场景边缘明确终止，继续探索通过「换一墙」。
- **混排**：全部模式按候选单位等概率抽取，不暗加偏好权重或固定图片/视频配额。图片多的库自然图片更多，可用「仅视频」切换；三种类型范围各保存一轮进度，界面说明切换范围会使用该范围自己的记录。画廊与墙之间不重置进度。

选择固定有界场景，而非无限扩展画布，是为了让位置、内存、加载量和重启恢复都可预测。1,024 是每墙容量，不是片库候选上限。

## 3. 看、放大、进入、回来

<a id="D-ME-02"></a>
**D-ME-02 · Behavior Contract · Accepted；来源 U4–U5。** 采用固定坐标画布。缩放、窗口改变、缩略图加载、元数据更新均不得重新排序或重排已有格子。

| 动作 | 结果 |
| --- | --- |
| 首次进入 | 以约 48–64 CSS px 的小格开始；具体首开倍率按窗口计算并限于该区间。 |
| 触控板捏合 / Ctrl+滚轮 | 以手势中心或鼠标位置为锚点缩放。 |
| 普通滚轮 / 双指滚动 | 平移画布，不改变倍率；鼠标拖动也可平移。 |
| 缩放滑杆、加减键 | 以视口中心缩放；单格边长范围 32–320 CSS px。 |
| 点击缩略图 | 在墙上方打开大预览；图片看完整画面，视频显示完整比例画面并可播放短预览。 |
| 预览中的「打开详情」 | 视频进现有观看详情；图片复用已有大图信息面板，不制造一页重复详情。 |
| 关闭预览 / 详情返回 | 恢复坐标、倍率与键盘焦点，按下述 D-ME-10 原位替换已打开项目。 |
| 「换一墙」 | 明确换候选，保留倍率并把新墙定位到起点；不会在拖动中偷偷换墙。 |

方格间隙为 2 CSS px 的世界坐标等比例缩放，低倍率不显示片名、评分和标签。画面在格子内等比居中裁切，放大预览呈现完整比例，不改原文件。普通悬停只显示片名和类型；首版不在小格里自动播放。

这次提出单击先预览、预览内进详情；不使用单击与双击分别触发不同动作，避免微小目标误操作。键盘方向键移动选中项，Enter 预览，Esc 只关闭最上层；提供可聚焦网格和当前项文字，不给上千格创建独立 Tab 停靠点。触屏在极密状态先放大再选中，不承诺 32px 小格满足手指精确操作。

### 视觉层次

1. 远景：密集画面，几乎没有文字，用于扫视。
2. 中景：仍保持原位置，可以看清画面细节；只给当前选中项显示轻量名称和视频标记。
3. 近景：点击打开预览，墙保留为背景；上下一个只沿当前场景顺序浏览。

深浅主题沿用应用现有色彩和组件。这里的视觉重点是内容密度和缩放，不新增色彩分类、AI 主题或自动解说。

## 4. 随机必须可解释

<a id="D-ME-03"></a>
**D-ME-03 · Behavior Contract · Accepted；来源 U2–U3。** 使用无放回洗牌，整轮内已确认展示的候选不再被分配到新场景。每轮的候选来自完整可见库，不从列表前几页或最近入库的固定小池抽取。

视频按已有版本组作为一个候选；没有版本组的按视频 ID，图片按图片 ID。只使用已经建立的版本关系，不自动判断不同文件是否同一作品。剧集各集仍是独立候选；不同但相似的照片也可能同时出现，这是本方案不依赖内容识别的边界。

本轮中不使用评分、收藏、播放次数、标签推荐偏好或停留行为调高某部片的概率。旧「随机播放 / 今晚看什么」继续使用原算法。

展示与分配必须分开：

- 进入墙的场景列表只是预留，后台加载不等于展示。
- 页面在前台，缩略图成功显示，格子至少 50% 进入视口并持续 300ms，才确认展示。微缩状态满足条件也算展示，不推断用户是否看懂。
- 拖回同一片画布、关闭预览后返回、切换两种视图，是主动回看当前场景，允许看到原项目；“不重复”约束的是下一批新分配。
- 换墙时，未真正展示的预留项回到剩余池尾部；优先发还没分配过的候选，避免刚才在墙外预加载的项目长期占位。
- 进度持久保存，重启继续当前场景；数据库切换后使用该数据库自己的进度。
- 本轮剩余不足一墙时显示剩余数量，不拿已看过的项目补齐；耗尽后显示「这一轮已浏览完」，由用户点「重新洗牌」。

新扫描进库的内容在下次申请新场景时加入剩余池，随机插入未预留部分，不挤动正在看的墙。删除、移出可见范围或失联的项目不再发出；已占的位置按 D-ME-10 原位补充，其他格子不挪动。

新一轮尽量把上一墙已展示的项目排到其他候选之后；当库小到没有替代内容时明确显示已浏览完和重新开始，不承诺永不重复。具体状态和事务见[详细随机合同](需求设计文档.md#D-ME-06)。

## 5. 画面和播放的成本边界

<a id="D-ME-04"></a>
**D-ME-04 · Operational Contract · Accepted；来源 U1、U4。** 墙上的视频使用现有真实视频缩略图，图片使用现有图片缩略图，不使用电影海报替代视频帧。首版不为每个小格重新随机截帧，也不扫描全片寻找精彩时刻。

“换个画面”放在选中视频的大预览里：从已知时长内选位置，调用已有指定时间取帧。最多保留该项本场景最近 3 个取样点，主动换点时避免重复；时长未知则显示原因，不假装取到了随机位置。每个场景的取样位置固定保存，返回时不闪换。

墙只加载视口和一圈预加载区域，图像请求有界调度。当前没有缩略图时使用加载格，生成失败显示失败格；不把失败格算展示，不回退到外部 AI 或自动更换媒体。只在明确请求该项时生成普通缩略图，不为整库预热。

视频大预览为单实例、沿用本机上次音量及静音状态（首次静音，2026-11-09用户裁定）、单段最多 8 秒，到边界停住，用户可重播或换位置。不支持直接预览且没有现成可用代理时，显示「在详情中准备播放」，不因逛墙而自动转码。离页、隐藏、换片、维护或换库必须停止视频、取消尚未开始的取帧，丢弃晚到结果。

| 行为 | 是否计正式观看 |
| --- | --- |
| 墙上展示、缩放、拖动、短视频预览 | 不写播放次数、断点、已看或日记；仅更新探索展示记录。 |
| 点击图片进入既有大图查看器 | 沿用现有查看阈值及失败不记账规则，不另写一份查看。 |
| 明确进入视频详情后正式播放 | 沿用现有播放器观看规则。 |

## 6. 模块关系与复用

<a id="D-ME-05"></a>
**D-ME-05 · Architecture Contract · Accepted；来源 U1–U5。** 新增同进程的探索服务，拥有洗牌和场景状态；不另建服务进程、媒体库、任务队列或播放器状态源。

下图为拟议依赖方向（箭头表示调用），新增部分标“新增”：

```text
观看导航 / 详情返回栈（扩展）
    └─ 探索页（新增；画廊和墙共用场景）
         ├─ 二维画布（新增；只管几何、视口和命中）
         ├─ 大图查看器 / 视频播放器（复用；视频增加只预览用途）
         └─ App 探索绑定（新增；只做薄桥接）
              └─ 探索服务（新增；候选洗牌、场景、展示确认）
                   ├─ 视频 / 图片可见性与版本关系（复用）
                   └─ 当前数据库中的探索状态（新增两表）

二维画布 / 大预览 ─→ 缩略图、指定时间取帧和媒体读取（复用）
```

已有一维行虚拟列表不能直接承担二维锚点缩放；新增纯几何模块，保留旧列表不动。复用既有资源和可见性能力，不能整套复用旧加权随机算法，否则会违背 U3；不能把浏览状态写入播放历史，否则会改变观看统计。

模块依据、精确落点和维护成本见[架构适配](需求设计文档.md#架构适配)。新增状态参加现有 SQLite / PostgreSQL 备份迁移；探索失败只影响探索页，不阻断片库与播放。首版限桌面观看区，不增加手机或 Jellyfin 入口。

## 7. 评审时重点看什么

以下为本次实施采用的设计取舍（用户交付后授权开始实施）：

- 一个「探索」入口和两个视图；全部/视频/图片三个独立随机范围。
- 单击先放大，再进入详情；小格不自动播放。
- 32 列有界墙、最多 1,024 项、32–320px 缩放；方格预览可裁切，大预览显示完整画面。
- 跨启动保留展示进度和场景；本轮耗尽后由用户主动重新洗牌。
- 视频已知版本组只出现一个代表；不按语义合并作品或照片。

这些取舍让视觉体验、避免重复和桌面流畅可以同时实现。参数和交互按本稿实施；材料变化须先更新本设计，不在实现中静默降低验收。

文档走查、实现验收场景和未验证范围集中在[验证与交接](需求设计文档.md#验证与交接)。


## 2026-11-09 动态补位（取代固定内容返回与不可用格保留规则）

<a id="D-ME-10"></a>
**D-ME-10 · Behavior Contract · Accepted。** 用户明确要求删除后补位、点开后换内容、加载更快，并确认关闭预览或从详情返回时替换，耗尽自动换轮且排除墙上现有内容，无替代才提示。覆盖探索页的照片／视频混排墙及共用场景的画廊；不改变其他片库列表、正式观看记账或原媒体删除规则。

| 触发 | 转移与结果 |
| --- | --- |
| 预览内上一项／下一项 | 累积已打开项，预览期间不替换场景，保留浏览顺序。 |
| 关闭预览／详情返回 | 批量替换已打开项，位置、缩放和未打开项稳定；新内容到达前保留可用旧图。 |
| 删除／可见范围改变 | 合并事件，核对当前场景并为不可用项原位补充；隐藏页延后到返回。 |
| 无本轮新候选但有墙外可见项 | 自动开启下一轮，墙上所有当前项（含本批将被替换项）排除；只补请求位置，不整墙重排。 |
| 无墙外替代 | 保留可用旧内容；不可用位置给出明确说明，并提示没有替代内容。 |
| 查询或写入失败／结果不明 | 不自动重复写入；沿原错误与回执核对机制处理。 |

继续由 MediaExplorationService 和既有两表拥有状态，前端串行 controller 提交，不新增owner／数据库表／外部依赖。资源仍每次校验现有scene、entry与可见性；换下的entry移出scene，其旧资源请求不可再读。换轮保持scene和slot，更新round；本轮外历史按旧洗牌语义清理。详情返回、维护、切库与迟到响应不得把旧替换写进另一墙。
