# 手机端局域网浏览（short feed）

桌面端开启「手机端访问」后会在局域网上开一个小 HTTP 服务，手机浏览器打开就能刷本机媒体库。
2026-08-08 起这条流是**混编**的：向上划，下一条可能是视频，也可能是图片。

## 访问与安全边界

> 2026-09-29/30 产品完善度批次（R4 / D-PC45 / D-PC47）推翻了原来「没有登录、没有 PIN、没有二维码、随应用常开」的边界，
> 以下为现行规则。字段级契约见 `docs/loopx/design/2026-09-29-product-completeness/需求设计文档.md` §8.6 与 §1.2b。

- **开关**：设置页「手机端浏览」的「开启手机端访问」即时生效（`SetShortFeedEnabled`，不必点保存）。
  新装默认关闭；老库升级后保持开启，且没设 PIN 时设置页顶部提示「建议设置 PIN」。
- 端口在 `18088..18108` 之间取第一个可用的，**只监听 IPv4**。设置页显示手机该输的局域网地址，
  macOS 上另有二维码（`GetShortFeedQRCode`，CoreImage 生成；其他平台不显示）。
- 源地址必须是环回、私网或链路本地，公网来源直接 403；所有请求还校验 Host：必须是内网 IP
  字面量或 localhost，且端口与监听端口一致，否则 421。变更类请求另有同源校验与 JSON/1 MiB/未知字段的请求体纪律。
- **可选访问 PIN**（6–32 个字符，bcrypt 存库）。设了之后，除 `/short/` 页面本身、`/assets/` 静态资源、
  `/short-api/auth` 与 `/short-api/auth/status` 外的**所有**路由（含 `/short-media/`、`/short-thumb/`）都要会话
  Cookie `cineinsight_feed_session`，否则 401 `pin_required`，手机页显示 PIN 输入页。会话只在服务端内存里、30 天有效，
  重启应用即全部失效；设置、修改或清除 PIN 都让已登录的手机重新输入。没设 PIN 时照旧放行。
- **登录限次**：同一来源（IPv6 按 /64 聚合）5 次失败锁 60 秒（429 `pin_locked`）；全局每分钟 20 次失败预算，
  超出后冷却 60 秒起逐次翻倍、最长 15 分钟；24 小时内全局失败超过 200 次时拒绝所有新登录（429 带 `daily_locked: true`、
  `retry_after`、`locked_until`），最后一次失败 24 小时后自动解除，也可在桌面端「解除锁定」（`UnlockShortFeedLogin`）。
  已登录的会话不受这些限制影响。
- 没设 PIN 时，同一 WiFi 下能打开页面的人就能看、能收藏、能把媒体移到废纸篓；这是开关打开且不设 PIN 时被接受的边界。
- **可见边界**：视频候选、收藏页与媒体下发都先套扫描根 + 黑名单 + 非失效（图片沿用 `applyImageVisibility`），
  各写接口同样受约束，不可见的条目一律 404。此前黑名单里的视频也会在手机端出现（PLAY-01）。

## 媒体标识

图片 ID 与视频 ID 各自从 1 开始，共用命名空间会撞车，所以对外一律带类型：

| 用途 | 形式 |
| --- | --- |
| 条目标识 | `ShortFeedMediaRef{Kind, ID}`，文本形式 `video:12` / `image:7` |
| 媒体字节 | `GET /short-media/{kind}/{id}` |
| 缩略图 | `GET /short-thumb/{kind}/{id}` |
| 动作 | `POST /short-api/items/{kind}/{id}/{play,like,favorite,delete,restore,rating,watched,tag}` |
| 排除集 | `GET /short-api/feed/next?exclude=video:1,image:2` |

未知类型一律拒绝，不回退成视频。手机页与后端在同一个二进制里发布，所以这些格式
按不兼容变更一次改掉，没有做双读兼容。

## 入选规则

- **视频**：在扫描根内且不在黑名单 + 未失效 + 文件存在 + 时长在 `(0, 上限)` 内 + 「字节能直接发给浏览器」。
  上限来自设置项 `short_feed_max_duration_minutes`（默认 5 分钟），**只对视频生效**。
  「字节能直接发给浏览器」有三条路：扩展名在可内联播放白名单里；或者是 `.mov` / `.m4v` 且技术快照的首个视频流
  为 h264 / hevc、音频为 aac 或没有音频（2026-09-29/30 起，D-PC46，`mobileInlineMIME`，手机浏览器对这类 `.mov`
  比桌面预览宽；没有快照一律不认）；**或者这个视频有一份有效的播放代理**（2026-09-02 起，D-004）。
  `/short-api/feed/scopes` 的每个范围带 `unplayable_count`（被格式门排除的视频数），范围面板据此提示。代理是 `~/.CineInsight/proxies/` 下的 mp4
  派生文件，由用户在片库里显式生成或扫描后自动生成；它是白名单之外的第二条路，
  **不是把白名单扩宽**。抽签阶段只查「有没有 ready 的代理行」这一件事，不 stat 文件——
  与既有候选收集同口径（抽中之后才 stat 那一条）。
- **图片**：未失效 + 文件存在 + 有可用解码器。可显示性交给桌面端那套图片解码矩阵
  裁定（RAW/HEIC 经 sips 转 JPEG 后可显示），**没有去扩宽与桌面预览共用的
  `inlinePreviewMIMEs`**——那张表一改就会外溢到预览链路。
  图片字节：≤3 MiB 的 jpg/png/gif/webp 直出原文件，更大的发长边受限的 JPEG 视图缓存；
  **GIF 例外，不论大小直出原文件**（2026-09-09）——它多半是动图，降采样成 JPEG 只剩第一帧。

抽取时两种媒体进同一个候选池，按标签偏好加权（`1.0 + 偏好分`，偏好分上限 0.5）随机取一条。
标签偏好表图片与视频共用，因为 `tags` 表本身就共用。

排除集盖住全部候选时**回退允许重复**，只排掉最近一条避免连续重复。这里刻意不报耗尽：
客户端固定发最近 12 条作排除集，硬耗尽会让只有几张图的库刷十几下就停流。
真正的耗尽只在完全没有候选时报出。

## 媒体字节

`GET /short-media/video/{id}` 下发的字节按这个顺序决定：

1. 能直接发给手机（上一节的白名单或 `.mov` / `.m4v` 规则）→ 下发**源文件**，MIME 取判定出的那一项。
   但源文件超出手机端直连上限（长边 >1920 或总码率 >8 Mbps）时，有有效代理就改发代理，没有就照发源文件，
   并在开启自动兼容代理时请求后台生成。
2. 否则有一份有效的播放代理 → 下发**代理产物**，MIME 固定 `video/mp4`（D-004）。
   命中之前先 `os.Stat` 源文件比对 `size + mtime_ns` 指纹：对不上就把代理文件与表行
   一起删掉，本次请求按「没有代理」处理。命中之后顺带刷新 `last_used_at`（每视频
   节流 60 秒），LRU 淘汰按这一列从旧到新来。
3. 都不成立 → **不回落源文件**，返回 404（`ErrShortFeedNoEligibleVideos`）：把一段浏览器解不了的文件配上猜出来的
   MIME 发过去，只会得到黑框、白占流量。（此前这里写的「仍然下发源文件、MIME 按扩展名猜」与代码不符，
   2026-09-30 按代码更正。）不可见（黑名单、扫描根之外、失效）的视频同样 404。

路径形态一个字都没变：手机端只知道 `/short-media/video/{id}` 这一个地址，
换源发生在服务端。缩略图路由与代理无关。

## 互动与回写

浏览次数放在两张**并行表**里，而不是给一张表加媒体类型：

- 视频 → `short_feed_interactions`（`video_id` 唯一索引，外键到 videos）
- 图片 → `short_feed_image_interactions`（`image_id` 唯一索引，外键到 images）

这是刻意的选择：合并成 `(media_type, media_id)` 复合键需要迁移既有的喜欢/收藏数据、
重建唯一索引与外键级联，而并行表零迁移风险。服务层用 `shortFeedInteractionState`
把两套读写收敛成一处分派。

**收藏与点赞只存一份**（2026-09-29/30，R5 / D-PC40）：唯一数据是 `videos` / `images` 的 `is_favorite`
（另记 `favorited_at`）与 `is_liked`，手机端直接经桌面同一个 setter 读写，两端看到的永远是同一个状态；
互动表只继续记 `view_count` / `last_viewed_at`。手机端「收藏」页按 `favorited_at` 倒序。
~~回写投影（总开关 `short_feed_feedback_sync_enabled`）：喜欢完全拥有一个自动标签并双向对账；收藏每次手机端动作
只投影一次（`favorite_synced_to_library` 记账）~~——这套投影已被推翻：喜欢的自动标签早在 2026-09-01 改成了
`is_liked` 列，收藏投影与点赞双向对账在本批删除。升级时 `migrateUnifyFavorites` 只执行一次，把互动表里的收藏与
点赞取并集写回两张媒体表（主表上已有的收藏 / 点赞不会被取消）。「反馈回流」开关因此不再控制任何行为，
设置页入口已删，列保留。

评分、标记已看（只对视频）与打标签同样经桌面的服务直接写媒体表（`rating` / `watched` / `tag` 动作）。

**删除**：视频与图片都经桌面同一条删除路径把文件移到系统废纸篓（`DeleteVideo(id, true)` / `DeleteImage(id, true)`），
桌面回收站可恢复。所在磁盘不支持废纸篓返回 409 `trash_unsupported`（「该磁盘不支持废纸篓，请在桌面端处理」），
磁盘未连接 409 `volume_offline`，没有权限 409 `permission_denied`；手机端**不提供**永久删除。
删除后的撤销走 `POST /short-api/items/{kind}/{id}/restore`，只对本服务经手机端删除的项生效，否则 404 `restore_not_found`。
（此前写的「视频走 trash 文件夹」已过时。）

## 手机端界面

`frontend/short.html` 是第二个 Vite 入口，构建产物由 Go 服务从 embed FS 下发。
它不使用任何 wails 绑定，全部走 `fetch`，所以能在手机浏览器里跑。

组件拆分：`ShortFeedApp.vue` 持有状态机，`components/` 下是纯展示子组件
（`FeedStage` 媒体舞台、`FeedTopBar`、`FeedMeta`、`FeedActionRail`、`FeedProgress`、
`FavoritesView`、`DeleteDialog`、`PinGate` 等），唤醒锁在 `useWakeLock.js`。

两类媒体的行为差异：

| | 视频 | 图片 |
| --- | --- | --- |
| 自动前进 | 循环播放，不自动翻 | 不自动翻，停到你划走 |
| 进度条 | 有，可拖动/键盘定位 | 无 |
| 双击 | 播放/暂停 | 适屏 ↔ 原图（放大后交给浏览器原生平移） |
| 控件显隐 | 暂停时常驻，播放时定时收起 | 无播放态，单独定时收起 |
| 浏览计数 | 同一条累计播放越过 `min(60 秒, 时长一半)` 才上报一次（`POST …/play`，后端记 `mobile_feed` 事件、`random_play_count` 与 `last_played_at`）；拖动、循环回片头不算播放 | 手机页当前**不上报**（后端的 `POST /short-api/items/image/{id}/play` 会记浏览次数与最近浏览时间，但页面没有调用） |
| 加载失败 | 解码失败提示「无法在浏览器中播放，已跳过」，350ms 后自动跳下一条，提示留在下一条上 | 停在原地说明原因 |
| 画面适配 | 竖屏素材 cover 铺满；横屏素材（先看后端宽高，元数据到了以实际尺寸为准）contain 完整显示；手机横过来时竖屏素材也 contain | 始终 contain，双击放大 |

长按 650ms 同时喜欢+收藏、划动翻页、静音、收藏页、删除确认，两类媒体一致。

失败与重试（2026-09-30，D-PC46）：

- 取下一条失败（网络异常等）不再清空浏览历史：停在当前条目、往回划照样能看，另给一条「重试」，重试总是去取新的一条。
- 点赞、收藏失败时回滚按钮状态并提示原因；收藏页加载失败显示错误态与「重试」，已显示的收藏不清掉。
- 删除失败按 409 的三种原因分别提示（不支持废纸篓、磁盘未连接、没有权限），都让用户去桌面端处理。
- 收到 401 `pin_required` 时整页换成 PIN 输入页（`components/PinGate.vue`），登录成功回到原来的位置；429 按短锁定与每日锁定
  分别提示（每日锁定提示「请在电脑上解除锁定，或 24 小时后再试」）。PIN 登录与扫码打开的真机体验待真机验证。

全屏（2026-09-09）：顶栏按钮在有元素全屏 API 的浏览器（安卓 Chrome、iPad、桌面）里把整页
`documentElement` 进全屏，面板与滑动切换都留在里面；iPhone Safari 没有元素全屏，只能对当前
`<video>` 调 `webkitEnterFullscreen()` 进系统播放器（图片条目不显示按钮）。iPhone 想要无地址栏的
整页体验，用 Safari「添加到主屏幕」——`short.html` 带了 `apple-mobile-web-app-capable` 等 meta。

`frontend/scripts/short-feed.test.mjs` 里有一批针对**源码文本**的正则断言
（图标形态、空态渲染条件、图片分支、进度条隐藏条件等）。改结构时要把断言搬到新位置，
而不是放宽或删掉——它们钉的是交互契约。
