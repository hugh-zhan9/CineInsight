# 另一台 Mac 本地 / SMB 文件扫描为 0

- 记录日期：2026-09-10
- 状态：**待另一台机器验证，未关闭**
- 用户安排：先提交当前代码，之后在出现问题的机器上验证。

## 用户报告

问题发生在另一台 Mac。文件仍在本地磁盘，但应用看不到；用户怀疑以前已有记录，并曾看到类似“实时同步失败”的提示（原文未确认）。SMB 挂载磁盘也扫描不到数据。最新补充是：**手动扫描没有报错，只显示扫描 0**。

尚未取得目标机器的应用版本、扫描目录、排除配置、日志及文件信息。当前开发机的数据库和测试结果不能证明目标机器的原因。

## 本次已修复的相关代码缺陷

以下问题已用临时数据库和测试文件复现、修复并回归，但尚未证明就是目标机器的原因：

- 全量扫描重新找到失效记录时，清除 `is_stale`，并计入“恢复显示”。
- 文件因近期修改或其他筛选规则未进入候选列表时，不再直接认定丢失；确认磁盘路径不存在才进入缺失对账。
- 普通目录读取失败会返回错误，失败根不参与缺失对账；明确排除、隐藏、回收站目录仍跳过。
- 局部同步不探测无关挂载盘的失效记录；只有匹配迁移候选时才检查原文件。
- 手动扫描摘要展示恢复数量及失败路径、原因。用户明确删除的记录仍不会自动复活。

实现：`services/video_scan.go`；回归：`services/scan_visibility_test.go`；界面：`frontend/src/components/video-list/IncrementalScanBar.vue`。

## 目标机器验证步骤

1. 使用包含本次提交的构建，记录应用版本 / 提交号、macOS 版本。分别确认本地目录和 SMB 挂载目录能在 Finder 中打开，保留应用实际配置的扫描根路径。
2. 每个目录选择一个实际存在的视频，记录扩展名、修改时间、是否为符号链接，并核对应用的扫描格式与排除目录。先使用已停止写入超过 5 分钟的文件验证。
3. 分别手动扫描本地与 SMB 目录，记录完整摘要：扫描、新增、恢复显示、跳过、删除、失败；若有失败，保存失败路径和原因以及同一时间段应用日志。
4. 核对该文件能否在片库找到；曾被标为失效的现存文件应恢复显示。若仍为“扫描 0、失败 0”，连同第 1–3 步信息继续定位，不据此清库或删除旧记录。

“扫描 0”与“新增 0”不同：扫描候选统计发生在数据库去重前，已有记录本身不能解释候选数为 0。根路径为符号链接、排除规则、扩展名、近期 / 未来修改时间等只是待核对项，尚无现场证据确认任何一项。

SMB 的实时监听限制与手动扫描是不同路径；不能把实时监听不支持 SMB 当作手动扫描为 0 的解释。
