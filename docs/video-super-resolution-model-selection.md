🥷 视频清晰度增强技术选型探讨
============================

**状态**：选型讨论

**目标设备**：Apple M4 Mac mini，32GB 统一内存

**结论性质**：阶段性建议，不代表最终实施设计

## 1. 背景

CineInsight 计划评估视频清晰度增强能力。该能力需要从视频中恢复细节、降低压缩痕迹，并在必要时放大分辨率。与图片超分不同，视频处理还要控制相邻帧之间的纹理变化，否则增强后容易出现闪烁。

本轮只讨论模型和运行方式，不确定界面、任务表结构、文件生命周期和发布方式。

## 2. 选型目标

- 在 M4 Mac mini 上可以本地运行，不依赖 NVIDIA CUDA。
- 不显著增加 CineInsight 主程序的依赖复杂度。
- 支持普通真人视频和动漫视频。
- 默认保留原视频，增强结果写入新文件。
- 能够接入后台队列、进度上报和任务取消。
- 第一版优先保证可运行性和结果稳定，不追求论文指标上的最优效果。

## 3. 候选模型

| 模型 | 处理方式 | 优点 | 局限 | M4 适配判断 |
| --- | --- | --- | --- | --- |
| Real-ESRGAN | 单帧超分 | 成熟、模型选择多、支持切片、部署成本较低 | 相邻帧可能出现纹理闪烁 | 推荐 |
| RealESRGAN AnimeVideo-v3 | 动漫视频单帧超分 | 模型较小，线条和动漫画面效果较好 | 不适合普通真人内容 | 推荐作为动漫模式 |
| BasicVSR++ | 多帧时序超分 | 利用前后帧传播和对齐，时序稳定性较好 | 依赖 PyTorch、MMCV，运算和移植成本高 | 暂不推荐本地首发 |
| RealBasicVSR | 真实退化视频超分 | 适合低码率、噪声、模糊和多次压缩的视频 | 官方环境偏 CUDA，长视频资源消耗高 | 适合以后作为云端或专业模式 |
| 扩散式视频超分 | 生成式多帧超分 | 细节生成能力强 | 速度慢，可能生成原视频不存在的细节 | 暂不采用 |

## 4. M4 Mac mini 适配分析

32GB 统一内存为本地切片推理提供了较好的容量条件，但实际速度和可用 tile 大小仍取决于运行时是否能调用 M4 GPU。视频长度、帧率和输出分辨率会直接放大处理时间。

BasicVSR++ 和 RealBasicVSR 需要同时处理多帧，内存占用和计算量都更高。它们的官方实现还依赖 PyTorch、MMCV 或较老的 CUDA 环境，在 Apple Silicon 上需要额外移植和兼容性维护，不适合作为第一版的默认方案。

Real-ESRGAN 官方提供 macOS 的 NCNN/Vulkan 便携实现，不要求 CUDA 或 PyTorch，但官方说明没有明确承诺 Apple Silicon 原生 GPU 加速。对 CineInsight 来说，独立可执行程序仍比嵌入完整 Python ML Runtime 更容易隔离，不过必须先验证二进制架构、MoltenVK 支持、M4 GPU 是否被识别，以及实际推理速度。

## 5. 阶段性结论

第一轮可行性验证围绕 Real-ESRGAN 系列展开，尚不把模型与运行时组合确定为正式实现：

| 内容类型 | 推荐模型 | 默认倍率 |
| --- | --- | --- |
| 真人、电影、普通视频 | RealESRGAN_x2plus | 2x，先验证可用运行时 |
| 动漫、动画、线条画 | realesr-animevideov3 | 2x，先验证 NCNN 行为 |
| 540p 及以下动漫素材 | realesr-animevideov3 | 可选 4x |

1080p 素材默认只做 2x，输出到 4K。1080p 做 4x 会生成 8K 视频，处理时间、磁盘空间和编码成本都很高，实际收益有限。

`RealESRGAN_x2plus` 属于官方 PyTorch 模型，但不在官方 NCNN 便携包列出的内置模型中。若最终采用它，需要验证 PyTorch/MPS 路径，或完成模型转换并校验输出一致性。NCNN 便携包内置的 x4 模型虽然提供缩放参数，也不能在验证前等同于原生 x2 模型。

可行性验证的初始参数：

```text
执行后端：候选为 NCNN sidecar 或 PyTorch/MPS sidecar
默认倍率：2x
默认 tile：512
内存压力较大时：tile 调整为 256
增强任务并发：1
输出编码：H.265 或 H.264
原音轨、字幕和容器元数据：尽量复制到输出文件
原视频：保留
```

## 6. 建议处理链路

```text
视频信息检测
  -> FFmpeg 解码或导出帧
  -> Real-ESRGAN 分块推理
  -> FFmpeg 重新编码
  -> 复制音轨、字幕和必要元数据
  -> 校验输出文件
  -> 写入新视频记录或刷新媒体库
```

输出文件建议使用独立命名，例如：

```text
movie.mp4
movie.enhanced-2x.mp4
```

增强过程不覆盖原文件。任务失败时只清理未完成的临时文件，不影响原视频和现有数据库记录。

## 7. 已知风险

- Real-ESRGAN 按帧处理，复杂纹理可能在相邻帧之间轻微闪烁。
- 超分模型无法恢复真实丢失的信息，生成的面部、文字和纹理可能不准确。
- 长视频会产生大量中间数据，需要限制临时目录占用。
- NCNN 切片可能产生块边界差异，需要用实际素材验证 tile 大小。
- 输出到 H.264 或 H.265 会再次压缩，需要制定质量参数和码率策略。
- 不同内容适合不同模型，动漫模型不应自动用于真人视频。

## 8. 后续验证

正式实施前先完成运行时门槛验证：

- 确认 macOS 可执行文件是 arm64、通用二进制，还是依赖 Rosetta 2。
- 确认 NCNN/Vulkan 在 M4 上能够识别并使用 GPU，而不是退回 CPU。
- 确认 MoltenVK 依赖和应用签名、分发方式能够兼容 Wails 安装包。
- 对比 NCNN x4 模型输出 2x 与原生 RealESRGAN_x2plus 的质量和块边界差异。
- 记录 10 秒、1 分钟和 10 分钟样片的速度、峰值内存和临时磁盘占用。

通过运行时门槛后，再准备一组固定样片，至少覆盖：

- 480p 真人低码率视频
- 720p 真人视频
- 1080p 高压缩视频
- 480p 动漫视频
- 快速运动和镜头切换场景
- 包含人脸、小字和字幕的场景

每个样片比较原视频、2x 输出和 4x 输出，记录处理速度、峰值内存、输出体积、闪烁、文字失真和人脸失真。选型结论以实际样片结果为准。
